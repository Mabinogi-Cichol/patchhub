# v0.2.0

v0.2.0 重构来源缓存与游戏匹配，改写 ZIP/EXE 安装写入路径以减少临时副本和磁盘占用，并修复来源匹配、缓存统计与安装相关问题。Windows 客户端与 Steam Deck Decky 插件共用同一核心与协议 v5，请将两端都更新到此版本。

## 新增功能

### 来源与匹配（Windows / Steam Deck）

- **按来源更新与共享索引**：每个来源维护一份可复用的游戏/补丁索引，更新只刷新指定来源；更新失败或取消时保留上次成功的索引和补丁记录。
- **游戏增量匹配**：新增游戏只匹配自身，索引命中后才获取该游戏相关详情；详情与匹配结果跨游戏、跨重启复用，不再随扫描反复抓取整站。
- **来源管理**：每个普通来源提供手动更新、自动更新间隔（关闭 / 6 小时 / 12 小时 / 24 小时 / 3 天 / 7 天 / 14 天，默认关闭，仅在应用或插件运行期间检查）、索引条目与修订、覆盖完整性、最近成功与最近尝试、下次到期时间，以及任务进度和取消。新增“匹配全部游戏”。
- **单游戏重新匹配**：已命中、未找到和未完成的游戏都可以重新匹配；重新匹配复用已有索引、不刷新来源；来源更新后自动重算受影响的游戏。
- **匹配状态更明确**：区分普通来源命中、HGamer 补查命中、已启用来源未找到、来源覆盖不完整、待匹配和失败；普通来源确认命中后不再显示 HGamer 候选。
- **HGamer 补查**：仅在普通来源没有可信命中且已启用来源覆盖完整时补查；HGamer 单列为“补查来源”，不参与定时更新。

### 安装与磁盘占用（Windows / Steam Deck）

- **ZIP 直接安装**：普通来源、签名目录与本地 ZIP 不再整套预解压、全量备份原文件或写入授权文件，改为边解压边写入游戏目录；不再产生 stage、backup、payload 等临时副本，减少重复读写和磁盘占用。
- **EXE 直接提取安装**：受支持的安装包在分析完成后直接流式提取所选成员写入游戏目录，不再生成中间 ZIP、完整暂存和逐文件事务状态。同一个 3.53 GiB、12,141 文件的包，Steam Deck 上安装事务从旧路径的约 1153 秒降至约 49 秒。
- **进度与大包支持**：分析、提取阶段按未知总量显示不确定进度，不再固定为 0%；可读取超过 4 GiB 的 ZIP64 包和超大文件报告；升级后可继续读取旧版事务记录。
- **长任务不再被固定时限中止**：移除安装计划 15 分钟有效期、前台心跳租约、来源查询 29 秒/24 次总预算、分析转换的固定时限和下载前固定空间门槛，按实际进度与真实资源检查执行（仍保留单请求超时、限速、取消和权限边界）。
- **移除无依据的大小、数量和格式限制**：大页面、大索引和大响应不再被固定上限截断；下载按实际文件格式识别，而不是要求链接带有 `.zip`/`.exe` 后缀；大缓存和备份目录可以完整盘点。

### Steam Deck（Decky 插件）

- **可折叠订阅源卡片**：每个来源显示为独立卡片并默认收起，标题保留名称、启用状态、当前任务或最近失败摘要；多张卡片可独立展开，切换页面返回后保留展开状态，操作归入所属卡片。长网址与快捷访问菜单下无横向溢出。
- **缓存与备份设置**：全局设置的“下载缓存”扩展为“缓存与备份”，显示下载缓存与安装备份的实际占用；可清理下载缓存或清理全部安装备份，清理后刷新占用，部分失败逐项提示。
- **终端在线安装/更新**：桌面模式执行一行命令即可安装或更新插件，自动校验发行包与哈希，成功或恢复后清理本次下载、备份和暂存，失败时自动恢复旧版。本版本起随发行附件提供 `install-decky.py`。

## 修复

- **VenusBlood FRONTIER International 漏匹配与重新匹配报错**：Kagura CN 索引已包含该游戏文章，但工具只给出 HGamer 网页候选；在 Steam Deck 上重新匹配还会显示 Python Exception（日志为 `instance_required`）。现改为按已确认 AppID 1189440 的精确上游文章关联普通来源索引，重新匹配按安装实例调用，不再依赖相似标题猜测；真实设备隔离对比确认显示 Kagura CN 命中并解析出下载镜像。
- **下载缓存占用始终显示占位提示**：改为读取核心的实际统计，显示字节与条目数；手动清理后刷新，读取失败或部分统计分别提示。
- **大包 EXE 与 ZIP64 失败**：删除 16 MiB 的安装报告与标准输出上限；中心目录偏移落在 2–4 GiB 的合法 ZIP64 包不再被误判。Steam Deck 实机 3.53 GiB 包已安装成功。
- **升级后插件启动失败**：旧版 journal 与授权文件中的过期/租约字段改为只读兼容，历史事务可继续读取和恢复，不再报 `journal_invalid`。
- **EXE 分析/提取阶段进度恒为 0%**：改为按未知总量显示不确定进度。
- **本版新链路的稳定性修复**：来源正文读取支持取消，缓存盘点句柄不再随目录宽度增长，Unix 捕获失败后恢复路径完整。
- **发行附件名与校验清单不一致**：安装包先按公开文件名（空格转点号）暂存再生成 `SHA256SUMS.txt`，本版本清单与下载文件名一致。

## 其他改动

- 协议升级到 v5：Windows 与 Steam Deck 必须同时更新；新增来源更新、匹配、重新匹配、缓存与备份状态等接口，旧的来源刷新/发现接口移除。
- 来源存储结构自动迁移到 schema 2；迁移失败时保留旧文件并提示，不删除历史数据。
- 程序、核心、Decky 插件与依赖清单版本统一为 0.2.0。
- 依赖审计：npm 生产依赖 0 漏洞；完整依赖仍有 7 条 high，全部来自 Decky 构建链中的 braces 栈耗尽公告（上游暂无修复版本）；本轮未重跑 RustSec。
- 发行附件共 9 个（新增 `install-decky.py`），`SHA256SUMS.txt` 覆盖其余 8 个内容附件。

`SHA256SUMS.txt` 覆盖发行附件；`checksums-*.json` 为两端 ZIP 校验信息，`dependencies-*.cdx.json` 为依赖清单。GitHub 自动提供的 Source code 是源码。

## 使用边界与已知限制

- **首次使用或从旧版升级后，请先在“管理订阅源”手动更新一次来源**（或设置自动更新间隔）。v0.2.0 起扫描只读取本机游戏并从已有索引匹配，不再自动逐游戏全站查询；索引为空时游戏会显示“来源尚无可用索引，请先更新来源”。
- **新 ZIP/EXE 安装直接覆盖文件，不创建自动备份，也不自动回滚。写入后取消、失败或中断会保留已写入内容，必要时重新安装；请自行备份重要文件和存档。** 历史事务仍按其原有记录处理。
- 安装前关闭游戏、暂停 Steam 更新。来源命中不保证当前游戏版本、本体/DLC 或语言适配；手动候选需自行核对。
- 第三方网站变更、登录/网盘要求或不支持的安装器行为可能影响获取与安装；工具不附带、镜像游戏补丁，也不绕过网站要求。
- Windows 安装包没有 Authenticode 签名，系统可能显示未知发布者。
- 安装备份清理入口目前只在 Steam Deck 的 Decky 插件中提供，Windows 客户端没有对应界面。
- 终端安装入口尚未在 Steam Deck 实机验收，且仅适配 Decky Loader 3.2.9；已禁用的插件需要先启用再升级。
- 已有双端自动化和部分 Steam Deck 部署/页面/安装记录；VenusBlood 修复通过真实设备的隔离状态及在线元数据对比。Windows 完整实机矩阵、来源任务/休眠调度、实体手柄、新版安装链的完整取消/中断回归，以及超过 4 GiB 的单成员包仍未全部验收。本发行不将这些项目列为已通过。
