# 隐私与本地数据

PatchHub 不包含遥测、账号系统或游戏库上传。扫描和匹配在本机完成，来源缓存与安装记录保存在本机。

客户端启动后会异步访问本项目 GitHub Release API，并按每日节奏检查应用版本；手动检查也使用同一接口。确认更新后才下载官方发行 ZIP 与 SHA-256 清单。GitHub 会收到正常网络请求的 IP 和 User-Agent，不发送游戏库、Steam 账号或本地安装路径，无需 GitHub 登录或 Token。“跳过此版本”仅在本机保存该版本的提醒偏好。

默认启用 patch.moe、Kagura 国内和海外发行商源、YOZAKURA 以及 HGamer 补丁索引。扫描先读取本地缓存；打开游戏详情后，插件按需读取发行商公开页面，并在匹配不足时向 HGamer 发送该游戏的名称或有出处的名称变体。请求会向对应网站提供正常的 IP 地址和 User-Agent，不发送 Steam 账号、安装路径、build、操作记录或完整游戏库，不导入外部浏览器的登录信息。可在订阅源设置中全局关闭任一来源，或仅取消某个游戏的订阅；关闭后不再查询或用该来源补全身份。必要的补丁元数据与成功查询缓存在本机，失败时保留上次结果。本功能仅发现来源，不镜像站点正文或补丁文件。

打开官方来源会由浏览器访问第三方网站；获取补丁时会连接对应来源规则允许的 HTTPS 主机。第三方网站可能要求年龄确认、使用 Cookie 或记录访问，请自行查看其政策。工具不保存网站密码，也不绕过网站验证。

Shiravune 更新遇到站点 JavaScript 验证时，宿主会在后台浏览器中加载其页面和语言表单。Windows 将该来源的会话 Cookie 和浏览器数据保存在本地状态目录的 `source-browser`，Decky 复用 Steam 的浏览器会话；不会读取外部浏览器的登录信息，也不把 Cookie 导出给 Lua 或项目服务器。本功能不提供网站账号登录。浏览器响应仅交给本机核心解析，普通更新不要求用户手工采集。

安装记录可能包含游戏路径、AppID 和下载信息。新安装直接解压覆盖，旧版本留下的记录和备份可能仍在本机。分享诊断前，请移除用户名、绝对路径、下载 URL 中的访问凭据和游戏库清单。

Steam Deck 的 Decky 宿主可能以 root 运行；后端将核心子进程降至配置的 Deck 用户，并设置该用户的 HOME 与 XDG 路径。权限不足会报错，不要求整个 Windows 客户端以管理员身份常驻。
