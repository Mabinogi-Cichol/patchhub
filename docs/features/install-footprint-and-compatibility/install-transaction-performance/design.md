# EXE 无备份直接安装设计

2026-10-28：解析器执行方式采用[普通子进程直接解析方案](../../patch-management-flow-simplification/design.md#32-exe-直接解析技术方案)，移除本文对应的 LPAC / bwrap、隔离探测和输入副本要求；流式解析与直接写入继续沿用。实际验证见[整合施工记录](../../patch-management-flow-simplification/progress.md)。下文保留本轮之前的设计依据。

日期：2026-10-17（Asia/Shanghai）。状态：**D1–D4 已按本设计实施并通过本地自动化验证；D5 双平台实机验收待执行**。关联：[施工记录](progress.md) · [父功能设计](../design.md) · [取证记录](evidence-20261017.md)。

## 1. 产品决定与范围

用户明确取消备份。当前流程取代此前 P1–P6 局部优化及带备份的五步方案：

**解析 EXE → 从 EXE 直接提取并覆盖游戏目录 → 安装完成。**

不备份原文件，不提供本次安装的自动回滚。不生成中间 ZIP、完整 stage 或逐文件临时副本；不做多轮全量哈希、重复解析/授权或逐文件状态落库。安装期间外部修改不纳入设计。

继续使用静态提取器，不执行 EXE 自带安装程序。范围为已支持的安装器格式与文件安装行为，Windows 与 Decky 共用此流程。普通 ZIP 安装不在本次变更范围；已有旧事务及其备份按旧记录处理，不能因新安装不再备份而删除旧恢复材料。

## 2. 三步执行流程

### 1）解析 EXE

下载或复用缓存后，打开 EXE，取得所选成员的目标相对路径、解码位置、大小及实际安装条件。一次确定文件列表；必要条件只在这里判断。解析只做生成安装列表所需的工作，不预先解压全部载荷来计算成员摘要，再重复解压安装。

当前 `audit::audit` 混合了载荷解码与审计，实施时分开必要文件表/元数据解析与实际载荷解码。格式确实要求解码某段才能读取后续元数据时，记录实际原因，不额外构造完整预检遍历。

入口确认游戏与安装目录一次。输出路径只允许落在所选游戏目录内；重复目标、非普通文件目标和不能执行的安装动作在开始覆盖前明确处理。沿用真实格式错误，不加入文件数/大小许可线。

容量只考虑尚需创建的真实材料：下载/沙箱输入尚未落盘的部分、直接覆盖顺序产生的游戏净增长及必要元数据，不再预留原文件备份、ZIP、stage 或临时目标副本。已存在的材料不能重复计入额外空闲需求。实际空间耗尽仍作为写入错误返回，不假装可以回滚。

### 2）直接提取到游戏目录

按清单逐成员解码，直接写最终游戏路径：已有普通文件截断覆盖，新文件创建，必要目录按需创建；保留已有文件权限。文件内容通过流式通道传递，消费即写入，不生成替代容器或整包内存缓存。

解码、写入或必要同步实际报错即停止。不预设复制/磁盘会静默损坏，不写后逐文件复读哈希、不在提交前再次读取全部游戏文件。格式长度/CRC 若随解码已经完成，使用该次结果。下载缓存可随下载流计算身份摘要，不传播为安装阶段多层复验。

正常写完后关闭文件，成功结果前完成必要文件/目录同步；同步错误作为安装未完成处理。用户进度来自提取字节数和完成文件数，不保存逐文件 writing/installed 状态，不建立断点续装机制。

### 3）安装完成

全部所选成员成功写入、提取器成功退出且输出同步完成后，保存一次成功结果和必要收据。收据只表达实际完成的安装，不承诺可卸载还原；不为兼容旧结构伪造原文件摘要、备份或 ZIP 字段。

释放 worker/runtime/沙箱输入，下载 EXE 是否删除沿用缓存设置。没有备份清理阶段。缓存或工作目录清理失败单独报告，不把成功安装改为失败。

## 3. 直接提取的技术衔接

现有 [sf.rs](../../../../crates/installer-worker/src/sf.rs) 的 `write_zip` 调用 [audit.rs](../../../../crates/installer-format/src/audit.rs) 的 `decode_payload`，底层可向 writer 输出。新路线消费解码字节，不经过 ZIP writer、`validate_artifact`、ZIP prepare、重复授权或 `retain_plan_archive_at`。

沿用解析器隔离：一次 worker 会话解析并输出安装列表，主进程完成目标与空间处理后继续提取；worker 输出成员字节流，主进程按清单写入游戏文件。worker 不需要整个游戏目录的写权限。只处理安装列表、提取数据、结束/错误与取消，不建通用队列或持久化消息协议。

原先 `WorkerRuntime::execute` 收集完整 JSON stdout，需核对 Linux/Windows 沙箱的双向管道并改为流式消费，不能用现有完整输出缓冲承载游戏文件。EXE 输入在会话内只准备一次；平台隔离仍需要输入副本时只保留一份，结束后释放。该接口已按下述 3.1 实施；Windows 自动化通过，Linux 分支与双平台实机仍待验证。

### 3.1 已实施接口（2026-10-18）

- 保持固定、一次性 worker 动作，不新增常驻双向控制协议。一次 staging 会话只复制一份 EXE，分析和提取是该会话上的两个固定动作：`analyze_behavior` 输出成员表报告；主进程完成条件/目标/空间检查后，以 `extract_behavior` 提交所选成员的偏移、长度、CRC 与压缩标志。
- 提取动作不重新生成 ZIP、不重新解析成员表，也不写中间文件；它按成员顺序向 stdout 输出一行 JSON 成员头、恰好声明长度的原始字节、一行含 SHA-256/CRC 的 JSON 尾帧，最后输出 done 帧。主进程在同一调用线程消费 stdout 并直接写入游戏目标。
- `WorkerSession` 持有会话目录、输入只读句柄和平台 profile；分析提取共用该输入。Windows/Linux launcher 增加有界 stdout 流通道，消费端停止时终止 sandbox；不保留完整 stdout 缓冲。
- 分析只做元数据/行为解析，不再解码全部载荷计算成员摘要；提取时逐成员解码并用同一次 CRC/SHA 结果作为安装收据。提取动作在开始前仍校验一次完整 EXE 摘要，用于绑定同一会话输入。
- 保留一次性动作的取舍：避免为“解析后再提取”引入通用队列、持久消息协议或跨平台长连接状态；代价是同一会话输入在提取动作开始时多一次完整摘要读取，但不再有全量载荷预解码、中间 ZIP 写读或备份复制。

## 4. 失败、取消和进程中断

- 开始写入前失败：游戏未被改写，正常报告错误。
- 写入后失败或取消：停止并等待提取器及写入端退出，关闭文件；保留已覆盖、新增及可能半写的文件，不恢复原文件、不删除本次游戏输出。
- 进程退出或断电后：下次读取已有任务记录时将未完成任务报告为安装未完成，不自动恢复、不自动续装、不据此阻止用户重新发起安装。
- 全部写完但成功记录未保存：同样视为未完成，不推断成功。
- 用户重新安装时从头提取覆盖，不依赖上一次完整成功的收据，也不因部分安装造成旧状态/条件检查而无法重试。依赖原始字节的格式条件需在实施时明确支持边界，不能宣称所有部分安装都能直接重试成功。

沿用现有任务开始/终态记录即可，不建立专门的回滚 journal、备份清单、恢复哈希或逐文件检查点。源包不可用、任务失败等错误如实显示；不再返回本路线的 rolling_back、rolled_back、needs_recovery 或备份相关提示。

界面在失败/取消后明确“安装未完成，已写入的文件未恢复”。可重新安装补丁；需要恢复游戏本体时提示用户使用 Steam 验证游戏文件，不自动执行。不能声称 Steam 验证一定删除补丁新增文件，也不把该提示当作插件具有还原能力。

## 5. 实施拆分与验收

1. **D1 解析与流式接口**：分离必要元数据解析与载荷解码，打通双平台单会话输出；确认无整包内存缓存、中间 ZIP 或重复完整解码。
2. **D2 无备份直接写入**：目标清单、直接覆盖/创建、权限、空间与进度；删除新 EXE 路线的备份/恢复字段和调用，不引入备份开关或两套新安装模式。
3. **D3 任务结果与重试**：成功收据、失败/取消/中断未完成语义、从头重新安装和缓存清理。同步 Windows/Decky 文案与状态消费者，旧事务仍按旧记录恢复，不迁移或清除旧材料。
4. **D4 删除旧链路**：新 EXE 不再进入 convert_behavior→ZIP→prepare→重复授权→备份事务；删除专属参数、错误、提示及测试。普通 ZIP、旧事务实际需要的代码保留。
5. **D5 实机验收**：新增/覆盖/混合文件、权限、部分写入后取消/失败/进程中断、未完成后的重试、旧事务兼容；核实新安装无 backup/ZIP/stage、无回滚和逐文件提交。验收中断会留下部分安装，测试使用明确可重建的测试游戏副本或夹具，不以现有真实游戏损坏作为默认验证步骤。

同一设备、同一 EXE、可比较初始状态下测量完整耗时和空间；历史 1044/1153 秒仅为问题依据，不承诺目标时长。游戏生效单独确认。当前仅设计修订，生产代码、自动化及实机均待实施/验证。

## 6. 设计审阅

备份及其衍生的复制、同步、清理、恢复识别和数据库状态全部退出新 EXE 正常流程，不以隐藏临时副本替代备份。保留项只服务格式解析、输出路径、真实 I/O、任务进度和结束状态。单会话流式接口用于取消中间文件，不扩展为通用安装框架。
