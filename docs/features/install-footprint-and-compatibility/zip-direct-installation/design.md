# ZIP 无备份直接安装精简计划

日期：2026-10-18（Asia/Shanghai）。状态：**Z1–Z4 已实现并通过本地自动化；Z5 自动化完成，Steam Deck 部署与一次 ZIP 直接安装通过；Windows/Deck UI 交互、取消/中断及同包性能对比待验证。** 关联：[施工记录](progress.md) · [父功能设计](../design.md) · [EXE 直接安装](../install-transaction-performance/design.md)。

## 1. 目标与范围

作为安装磁盘占用与兼容性精简的独立子功能，与 EXE 计划分别维护。采用用户已确定的直接覆盖语义：

**获取 ZIP → 读取文件表并确定目标路径 → 直接解压覆盖游戏文件 → 完成。**

新 ZIP 安装不备份、不自动回滚、不生成完整 stage 或单文件临时副本，不预解压全部成员计算哈希，不逐文件扫描游戏库或同步数据库。失败/取消保留已写入内容，允许从头重新安装。

覆盖普通来源 ZIP、签名目录 ZIP，以及签名目录入口支持的用户本地 ZIP。保留原来源与目录的身份契约、既有路径映射、真实格式错误和实际 I/O 失败处理。不扩展支持的压缩格式，不增加“快速/安全模式”或备份开关。已存在的旧事务按旧语义恢复，不删除旧备份。

## 3. 新流程

### 3.1 获取 ZIP

网络包下载到现有缓存，缓存锁沿用至本次消费结束。下载计算的摘要用于缓存身份；普通来源没有发布者预期摘要时，不把自算摘要当作内容真实性证明。

签名目录入口保留目录签名、版本/撤销及 release 选择的入口检查，并沿下载流一次比对目录声明的包摘要。缓存复用和用户本地包在获取边界核对一次声明摘要；随后持有同一文件供读取，不再阶段性全包复读。这是已有签名目录的包身份契约，不是默认下载会损坏。新签名请求仍读取当次目录状态，不使用跨请求的永久可信缓存。

本地 ZIP 保持用户所有权，清理任务不能删除它。保留下载设置，不新增归档移交或长期归档引用。

### 3.2 文件表与安装映射

读取中心目录及 ZIP64 元数据，生成选中成员的索引、原始名称、目标相对路径与大小。普通来源复用当前 XP3/YPF 包装目录处理，不将任意包简单剥掉第一层目录；签名目录直接使用它提供的 source→destination 映射。

映射前后处理路径越界、链接/特殊文件、重复目标、大小写冲突与文件/目录冲突，确认目标属于用户所选游戏目录。成员列表只解析一次，映射所需格式签名只读必要文件头，不进行全量预解压或遍历原文件内容。

不为比较新旧内容读取游戏原文件哈希。游戏实例、实际必要条件在入口确定，不逐成员重复事实检查。签名 recipe 如声明必须匹配原始内容的实际安装前提，应明确区分首次安装与覆盖/重装语义，不能机械沿用旧基线检查使部分安装后的重试被阻断，也不能伪造已满足条件；具体调用方在 Z1 核对。

### 3.3 直接解压覆盖

复用现有 `begin_direct_at`、`open_direct_target`、`commit_direct_at`、`fail_direct_at`。将成员索引/目标映射留在 ZIP 编排层；不创建第二个通用安装框架，不将 ZIP 经由 EXE worker。

持有安装锁，按确定顺序打开 ZIP 成员，流式写到最终目标文件，已有文件覆盖、新文件创建；保留已有文件权限。达到成员 EOF 时取得解压库的长度/CRC 结果，真实解码错误立即停止，不额外复读。

当前 `commit_direct_at` 接受安装态摘要，供现有收据/检测消费者使用。因此本批在唯一一次解压写入流中顺带计算该摘要，既不提前解压，也不写后读回；不是新加一次正确性比对。签名 recipe 明确提供成员摘要时可在同一流中比较，不增加读取次数。若未来决定取消收据摘要，应连同 EXE 及全部消费者统一调整，本计划不创建 ZIP 独有的空摘要兼容分支。

每个文件正常写完后关闭并按现有直接安装约定同步，受影响目录在成功前处理；不逐文件提交数据库。进度通过既有字节数/文件数事件更新，保留用户取消。

### 3.4 完成、清理与中断

全部成员写完、解压校验和输出同步成功后保存一次成功记录。缓存按用户设置清理，无 backup/stage 清理阶段，无卸载还原承诺。

开始写入后的失败、取消或进程中断保留已有及半写文件，不回滚、不删除新增游戏文件。下次显示安装未完成，允许新请求从头安装；同一请求重复提交沿用去重，不把旧请求重放当作新的重试。不能因旧完整收据缺失或原态已经变化而将无备份安装永久卡住。

Windows/Decky 显示“安装未完成，已写入文件未恢复”，不显示正在回滚或待恢复。可提示重新安装；Steam 验证不是插件还原机制，不承诺清除新增补丁文件。旧未完成事务仍调用原恢复路径，不能将它们误标为直接安装。

## 4. 空间与性能目标

游戏盘只考虑直接覆盖顺序的净增长。第 i 个文件原大小为 o_i、新大小为 p_i，完成后的累计变化为 delta_i = sum(p_j-o_j)。在截断后直接写入、没有临时副本的路线中，额外数据空间可按 max(0, max(delta_i)) 计算；实际按所用文件打开行为验证，不照搬旧 O+T 备份模型。

下载 ZIP、元数据与文件系统余量按真实卷单独计算，已下载部分不重复预留。CoW 等实际卷行为和空间不足通过原有容量约定及 I/O 错误处理，不引入固定包大小/文件数量门槛。

可验证的操作目标：无完整预解压、每个选中成员安装时完整解码一次（映射用头部读取另计）、无原文件全量读取、无备份/临时目标副本、无逐文件数据库提交、无随文件数增长的 Steam 扫描。性能收益用真实 ZIP 前后对比，不承诺未经测量的秒数。

## 5. 实施拆分

- **Z1 映射与入口契约**：将 metadata/mapping 从旧 hash recipe 中分离，核对 XP3/YPF、签名映射、原态条件与重试调用方；保留实际业务条件，清理只为旧事务建立的检查。
- **Z2 普通 ZIP 直接安装**：接入已有 direct 接口、单次解压写入、进度、取消与空间模型；停止生成旧 plan/authorization/backup。
- **Z3 签名目录和本地 ZIP**：保留一次目录/包身份核对，使用同一直接写入路径，删除外部包托管复制与重复授权；确认用户文件所有权。
- **Z4 状态及删除收尾**：双端结果/重试/收据检查，清理专属旧参数、错误文案和测试；普通/签名 ZIP 与 EXE 共用直接安装结束语义，旧记录仍可读取和恢复。
- **Z5 验收**：针对性自动化、Windows/Deck 实机及可比较的性能测量；代码与配套文档分别提交（提交需用户明确要求，本轮未提交）。

## 6. 验收标准

1. 平铺、XP3/YPF 包装目录、签名自定义映射、UTF-8/现有支持编码、ZIP64、Stored/Deflate 均保持正确目标和完整输出；路径越界、链接及碰撞不能写出游戏目录。
2. 新增/覆盖/混合及大小变化、权限与目录创建正确；重试可以覆盖部分输出，不要求之前已有完整成功收据。
3. 流式 CRC/解码错误、真实空间不足、Windows 占用错误、取消及进程中断均报告未完成并保留部分结果；使用可重建副本测试，不默认破坏用户游戏。
4. 新安装不产生 backup/stage/每文件临时副本/授权文件/外部 ZIP 副本，源码及受控计数证明没有全量预读与逐文件提交；旧事务回归不删除恢复材料。
5. 签名目录及包身份不匹配在获取边界失败；本地用户 ZIP 安装/失败/缓存清理后仍在原处。下载缓存设置保持原意。
6. 同设备、相同包、相同初始状态记录总时间、解压写入时间、读取/写入量与空间峰值；无函数计时的数据不拆成假精确占比。实机游戏效果和实体交互未做则明确待验收。

## 7. 过度设计审阅结论

沿用既有 direct 写入/结果接口，删除原事务重复工作；ZIP 格式解析与映射是必要输入处理，签名入口一次身份核对有明确外部契约，其他保留项对应真实 I/O 和用户取消。不新增线程池、队列、检查点、备份开关或按时抽查。当前是静态方案审阅，原态条件消费者与双端实际重试在 Z1/Z4 核对；不把待实现方案写成已通过验收。

## 8. 实施结果与保留项（2026-10-18）

- 删除 `installer/authorization.rs` 及授权写入/复验链；ZIP 与签名 ZIP 新事务不再生成 `authorization.json`、backup 或 stage。
- `zip_recipe` 拆为 `open` / `plan` / `plan_mapped`，只读中央目录与 XP3/YPF 包装头；新增 `zip_direct`，在唯一一次解压流中写最终目标、计算 SHA-256，并由解压库在成员 EOF 校验 CRC。
- 旧 `prepare_for_request_at`、`apply_at`、外部包 adopt 及旧 stage/backup 前向写路径保留为 `#[cfg(test)]` 历史事务夹具；生产恢复仍由 `recover_checked_at` 处理旧备份事务，未删除旧恢复材料。
- 直接覆盖的空间预算只计目标卷峰值净增长与 margin（`for_direct_overwrite`）；旧文件与已下载 ZIP 不重复计入。
- 本地用户 ZIP 在同一打开句柄上完成一次声明摘要校验后交给解压库；签名成员计划按 recipe 顺序写入日志，保持 projection 的重装比较一致。
- `recover_selected_at` 在把 direct 事务标记失败前探测游戏锁，运行中的其他进程安装不会被并发恢复改写；`open_direct_target` 改为校验通过后才清空目标，硬链接被拒绝时不再截断共享文件。
- 核心层 `Reinstall` 采用与 EXE 一致的直接覆盖语义，不再要求旧成功收据或原文件摘要；重装可用性由 projection 的 `reinstall_*` blocker 约束。
- Z5 自动化已通过；Windows/Steam Deck 实机与同包性能测量尚未执行。
