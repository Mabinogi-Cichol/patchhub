# Windows FakeIP 下载兼容方案

状态：公共 IP 限制已移除；Windows release 构建、便携部署、原生窗口检查及 FakeIP 下真实 ZIP/EXE 下载验证通过。实际记录见 [施工记录](progress.md)，历史证据见 [调研](research.md)。

## 目标与原因

让下载器使用系统解析结果连接，不根据 IP 网段推断用户的网络使用场景。

旧实现先解析域名，再要求所有地址通过公共 IP 校验。用户网络返回的 FakeIP 在 HTTP 连接前被拒绝，报 `download_private_address`。本机同时返回 IPv4 和 IPv6 保留地址，因此不能仅对某个 IPv4 网段做例外。

共享传输用于当前动态 ZIP、EXE 和签名目录下载，修复同样适用于使用该传输的 Windows 与 Steam Deck。

## 产品决策

2026-10-13 用户明确要求直接放行，不检查 FakeIP，不预设网络使用场景。据此取消公共 IP 限制，对所有来源采用相同规则；不增加 FakeIP 识别、特殊网段白名单、来源信任分级或网络设置前置要求。

此前建议的定向 DNS 排除和显式本地代理不再作为本次实施方案。历史调研内容保留在 research.md，以记录决策变化。

## 实现

- 保留系统 DNS 解析，使用解析得到的 IPv4/IPv6 地址，不按公网、局域网或保留网段筛选。
- DNS 调用失败或结果为空时返回 `download_dns_failed`。
- 删除 `public_ip` 函数、公共地址拒绝分支及对应的旧策略单测。
- 保留每跳解析后的 `resolve_to_addrs` 连接绑定、HTTPS/443、证书和域名校验、下载与重定向域名白名单、禁止 URL 凭据、大小/空间/取消/哈希/格式检查以及安装授权和事务逻辑。
- 本次保持已有 `no_proxy()` 行为，解决系统 DNS 返回的地址被应用层拒绝的问题；TUN、路由或其他系统网络机制负责实际连通性。

## 实施与验收

1. 移除共享传输的地址分类和拒绝逻辑，删除旧策略单测。
2. 检查剩余地址分类引用，运行现有下载获取、重定向、缓存、哈希和格式校验测试。
3. 在 FakeIP 保持开启时，用重新构建的 Windows 产物验证实际补丁下载；同时观察 IPv4/IPv6 返回结果。
4. 不要求用户改 DNS、关闭 TUN 或配置指定代理来通过本次下载校验。

编译及自动化测试需要可用 Rust 工具链；未执行的验证记入施工记录，不以静态检查代替真实下载成功。
