# Decky 详情页信息优先级调整方案

状态：**仅方案，待实现**。2026-11-02 用户反馈详情页信息优先级不对，并明确“先出方案”。本轮只修改文档，不改产品代码、不构建、不连接设备或部署。

所属设计：[design.md](design.md)；实际进度：[progress.md](progress.md)。继续使用尚未合并的 `feature/decky-visual-refresh`，不另建修复分支。

后续状态：用户随后单独要求的信息折叠、选择器外置及“选择补丁 → 下载项 → 安装操作 → 详情 → 重新查询”顺序已实现并部署，详见施工记录；本方案其余调整仍待实施，以下原始规划内容保留。

## 1. 当前问题与依据

依据当前 `GameManager` / `CandidateDetails` 源码，以及 2026-11-01 本功能已部署的真实详情页截图；没有为本次方案重新操作设备。

- 首屏排列为游戏名称、Hero、AppID、Build、路径入口；“操作哪个补丁、能不能安装、下一步是什么”尚未出现。
- “查找补丁”独立占一个区块，重新查询排在已有补丁前；普通浏览结果也要先经过维护动作。
- 多补丁时先有“选择补丁”下拉区块，随后又有同名区块展示补丁名与来源，形成重复标题和重复身份信息。
- 下载文件、镜像、完整 URL、兼容性与安装方式逐项排列，安装按钮位于它们之后；只读文件预览甚至先于安装按钮。
- 来源候选同样先展示多条详情和证据，之后才给出“未找到下载链接”与手动输入入口。

## 2. 调整原则

继续使用 Decky Loader 原生组件、默认主题、三栏目导航和普通纵向滚动。只调整现有内容的顺序、重复项和折叠方式，不新增概览页、常驻/悬浮底栏或自定义主题。

详情页首先回答：选中了哪个补丁、当前能执行什么操作、有哪些必须先看到的条件。艺术作品为辅助展示，技术信息按需展开。

## 3. 推荐默认顺序

| 优先级 | 内容 | 呈现方式 |
| --- | --- | --- |
| 1 | 当前游戏与补丁 | 当前原生栏目中显示完整游戏名；补丁选择只出现一次，多条为原生下拉，单条直接显示名称；来源作为同一区块的次级说明 |
| 2 | 操作可用性与必要条件 | 简短显示可安装、可覆盖安装或当前不可用，以及真实必要条件/阻断原因；已知检测状态作为辅助信息，不把“检测未知”推断成已安装或不可安装 |
| 3 | 下载项与主要操作 | 多镜像时选择下载项；关闭游戏/暂停更新提示；安装或覆盖安装按钮。只有单项时无需单独的镜像选择区块，下载标签/文件名按需作为简短说明 |
| 4 | 次要操作 | 打开来源网页、重新查询，以及现有手动直链/本地 ZIP 输入入口；不让只读预览抢在主按钮前 |
| 5 | 艺术作品 | 保留原生 Hero 自动展示，放在主操作和必要辅助入口之后，随正文滚动；无图时沿用现有隐藏行为 |
| 6 | 更多详情 | 默认收起，分“补丁技术详情”和“游戏信息”；展开后保留全部原有字段和复制动作 |

正常结果中，查询入口放在补丁区块的次要操作位置；查询中保留同位置的进度与取消入口。无结果时重新查询、游戏订阅升级为主要引导，不埋到技术详情里。

### 示意（普通可安装补丁）

```text
原生左侧导航                 原生右侧补丁管理
                            游戏完整名称
补丁管理                    补丁：[当前补丁               ▾]
操作记录                    匹配来源 · 当前可用性
游戏订阅                    必要适用条件 / 阻断原因（存在时）

                            下载项：[镜像                 ▾]（多个时）
                            安装时请关闭游戏并暂停 Steam 更新
                            [安装补丁 / 覆盖安装补丁]

                            [查看来源网页]  [重新查询]
                            ▸ 导入本地 ZIP（仅原能力允许时）

                            原生 Hero 艺术作品

                            ▸ 补丁技术详情
                            ▸ 更多游戏信息
```

示意中的按钮可以沿用原生单列，不要求为了同排效果压缩按钮宽度或缩小字号。

## 4. 字段与行为归属

### 主操作之前必须可见

- 当前补丁身份、实际匹配来源和现有原生选择控件。
- 与当前选择直接相关的适用条件，例如本体 / DLC、必要版本、语言事实，以及实际阻断原因。条件过长允许自然增高和滚动，不能裁切或藏进折叠区来凑首屏。
- 多下载项/镜像选择；现有自动、覆盖或手动输入路线的操作可用性。
- 当前游戏需处理的历史操作提示和记录入口：仍按当前权威动作判断，不借布局调整新增安装门槛，也不把恢复动作的范围改为当前游戏。

### 次要但保持容易找到

- 来源网页入口保留在主操作后、艺术作品前；对于没有自动链接的候选，它是补充下载链接的重要动作，提升到该候选的操作区。
- 重新查询保留在该页面，不再独占前置区块；进行中显示真实状态，仍能取消，失败保留原结果及既有反馈规则。
- 本地 ZIP 仍为可选入口，条件与现有 `local_archive.available` 一致；展开输入时相关安装按钮紧随字段，不为布局合并改动安装调用或原始参数。

### 默认收起

- 补丁技术详情：完整下载地址、文件格式/安装方式的详细说明、版本证据和冲突的原始依据、只读文件变更预览入口及其结果。必要冲突结论仍在主操作前。
- 更多游戏信息：AppID、Build、安装路径、游戏库路径和复制按钮。完整游戏名保留在上方，不要求展开才能识别当前游戏。
- 默认技术详情折叠不阻断安装，不触发预览读取；用户展开并选择“查看文件变更”后才沿用现有只读 RPC。

## 5. 不同状态的优先级

| 状态 | 首要展示 |
| --- | --- |
| 可安装 / 可覆盖 | 补丁与来源、必要条件、当前下载选择、相应主按钮；覆盖标签仍由当前权威动作决定 |
| 当前不可用 | 补丁身份、不可用原因与可行下一步，相关按钮沿用原禁用条件 |
| 找到来源但没有下载链接 | 候选身份与必要条件，明确“未找到下载链接”，紧邻来源网页及手动直链入口；版本证据下移，不能用“可安装”概括来源线索 |
| 已补充手动直链 | 字段、输入有效性、下载并安装按钮保持相邻，仍使用现有任务通道 |
| 没有补丁结果 | “暂无补丁结果”、重新查询与游戏订阅先于图片和游戏技术信息 |
| 查询进行中 | 真实查询状态与取消入口清楚可见，旧结果继续显示；不增加查询步骤或等待门槛 |
| 安装失败 / 需要处理 | 现有反馈和必要记录入口优先显示，不能被图片或折叠区遮住 |

## 6. 实施范围与验证（均待后续施工指令）

1. 调整 `GameManager` 展示顺序，合并补丁身份/选择区块；候选详情按相同优先级组织。
2. 将技术字段、文件预览与游戏元信息归入原生可聚焦折叠入口；艺术作品下移，图片来源和渲染逻辑不改。
3. 补充实际顺序、重复内容、折叠内容可达性测试；回归单/多补丁、多镜像、来源候选、自动/覆盖/直链/本地输入及查询状态。
4. 实施后执行类型检查、前端测试与构建；获得对应设备授权后检查真实首屏、末端滚动、折叠焦点与软键盘。按当前真实 854×534 CSS viewport 优先验证，同时覆盖计划视口与长文本。

验收目标是普通短标题、无长条件的默认状态尽量首屏可看到补丁、状态和主操作。多选择或长条件场景优先保留全部必要信息，不能通过固定高度、截断文案或隐藏条件来保证主按钮必定首屏出现。

本次按 `overengineering-review` 审阅：信息重排、消除重复与两组按需详情对应已确认的实际问题；不需要新路由、图片系统、固定底栏、配置项、超时、重试或状态框架。方案尚未实现，未宣称通过 UI 或手柄验收。
