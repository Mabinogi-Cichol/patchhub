## 1. 目标与范围

Decky 界面沿用 Decky Loader / Steam 原生组件及其默认视觉。Windows 仅作为“详情中展示游戏艺术作品”的功能参考，不作为 Decky 的色板、卡片、字号或布局模板。

本轮规划的重点是：在游戏详情的补丁管理页加入艺术作品，同时保留当前补丁选择、安装、查询、记录与订阅的操作方式。

- 保留现有 QAM 选游戏 → 全屏管理结构，以及补丁管理 / 操作记录 / 游戏订阅三个栏目。
- 导航、区块、字段、按钮、下拉、开关、进度、模态与焦点使用 `@decky/ui`，默认颜色、字体、间距和选中态跟随原生组件。
- 艺术作品展示于当前游戏补丁管理详情和安装进度面板（见第 13 节），不铺到 QAM、全局设置、操作记录和游戏订阅页。
- 图片相关样式只负责尺寸、裁剪与正常排版；标题与状态仍使用原生内容区，不在图片上另画一套工具栏或交互控件。

上一版中的 Windows 中性深色色板、自定义卡片系统、独立底部安装操作区、QAM 行样式重做及其他页面整体视觉改造，均退出当前实施范围。现有局部样式若不影响本次图片接入，不附带开展全站迁移。

## 2. 已核实的原生能力与证据边界

规划阶段检查了仓库安装的 `@decky/ui 4.12.1` 源码和声明；施工时进一步通过当前 Devkit 配对连接 Steam Deck，核对实际组件和图片加载。静态声明与运行结果分别记录如下。

| 能力 | 本地证据 | 判断 |
| --- | --- | --- |
| 原生页面结构 | `SidebarNavigation` 支持 `ReactNode` 内容；`PanelSectionRow` 接受 `ReactNode` 子内容 | 可以在现有页面内容中容纳图片，无需更换路由或导航 |
| 图片辅助组件 | 包公开导出 `SuspensefulImage`，接受标准图片属性及加载占位宽高，加载时使用库内 `Spinner` | 有库内图片展示方式；它是 Decky 库提供的辅助封装，不是专用 Steam Hero 组件 |
| 自定义艺术作品地址 | `window.appStore` 声明 `GetCustomHeroImageURLs`、`GetCustomLandcapeImageURLs`、`GetCustomVerticalCapsuleURLs` | 可作为优先核实的自定义图片来源；方法拼写以依赖声明为准，返回顺序和实际含义待设备验证 |
| 默认游戏图片地址 | 声明 `GetLandscapeImageURLForApp`、`GetVerticalCapsuleURLForApp` 及对应 cached 方法 | 存在横图/竖封面接入线索，但不能据此声称已有默认 Hero 地址接口 |
| 规划基线接线 | `steam.ts` 只读取 `GetAppOverviewByAppID`、显示名称和 `GetIconURLForApp` | 施工前尚未接入艺术作品，本次新增独立原生图片组件 |
| 当前设备原生渲染 | 在已加载 Steam 模块中发现 `LibraryAssetImage` 类，具有 `GetSourcesForAsset` / `OnImageLoaded` 等方法；Hero 类型为 1 | 能直接复用原生 Hero 选择、缓存和自定义图片路径；两款真实游戏已加载成功 |
| 声明漂移 | 设备上 `GetLandscapeImageURLForApp` 实际为 undefined | 不能按类型声明直接调用该方法；实现不使用这条路径 |

依赖源码位置（从仓库根目录算起）：

- `node_modules/@decky/ui/src/custom-components/SuspensefulImage.tsx` 及其 `index.ts` 导出。
- `node_modules/@decky/ui/src/components/SidebarNavigation.ts`、`Panel.ts`。
- `node_modules/@decky/ui/src/globals/stores.ts`，并与 `dist/globals/stores.d.ts` 核对公开声明。
- 插件接线：[steam.ts](../../../apps/decky/src/steam.ts)、[index.tsx](../../../apps/decky/src/index.tsx)。

在 `@decky/ui` 公开组件中没有专用 Hero，但其公开的 `findModuleExport` 能定位设备已加载的 Steam 原生 `LibraryAssetImage`。实现按原型方法识别，不固定本轮混淆模块编号或导出名。原生类自带自定义图片与缓存选择，因此不使用 `SuspensefulImage`，也不手工构造图片地址。自定义图片实际优先级仍待带自定义图片的样本验收。

## 3. 详情页设计

```text
Steam 顶部状态区
┌──────────────┬─────────────────────────────────────────┐
│ PatchHub     │ 游戏名称（原生标题/信息区）              │
│ 当前游戏     │ ┌─────────────────────────────────────┐ │
│              │ │ 当前游戏艺术作品                    │ │
│ ▌补丁管理    │ │ 复用库内图片组件，仅能力可用时展示    │ │
│  操作记录    │ └─────────────────────────────────────┘ │
│  游戏订阅    │ 原生区块：游戏信息、查询与补丁选择      │
│              │ 原生区块：补丁详情与安装操作            │
│              │ 内容按现有方式滚动                      │
└──────────────┴─────────────────────────────────────────┘
Steam 原生 A 选择 / B 返回
```

- 图片位于补丁管理页顶部的“游戏信息”中、游戏名称之后，与正文一起滚动，不固定在屏幕上方。图片容器高 `clamp(120px,20vh,180px)`，图片填满内容宽度并按 cover 裁剪；仅增加排版 CSS，不设置主题颜色、边框或圆角。
- 使用 Steam 原生 Hero 类型，图片选择由该组件负责；不调用不存在的默认横图方法，也不将横图当作默认 Hero。
- 首轮只选择一种经验证可用的横向展示，不同时添加背景 Hero、竖封面和 Logo，不构建图片类型选择器或轮播。
- 本轮设备确认 Hero 可用，因此只接入横向 Hero，不增加竖封面分支。
- 游戏名称和状态放在图片外，保证明亮或复杂艺术作品不影响文字辨识；图片本身没有独立点击行为，不新增手柄焦点站点。附近已显示游戏名时，图片作为装饰不重复朗读。
- 未加载时隐藏图片区域；原生组件加载真实艺术作品后显示。最终落到 Steam 通用默认 Hero、所有来源失败、没有游戏信息或组件不可用时不展示图片区，补丁正文与动作不等待图片加载。
- 默认跟随 Steam 当前用户的艺术作品配置，但只有验证自定义图片接口实际返回行为后，才能宣称支持用户自定义作品。游戏切换必须同时切换图片，不能显示上一个游戏的艺术作品。

## 4. 最小接入方案

1. 新增 [game-artwork.tsx](../../../apps/decky/src/game-artwork.tsx)，按 Steam 原型方法通过 Decky 公开查找工具定位原生组件；查找不到则不渲染。
2. 从 `window.appStore.GetAppOverviewByAppID` 取得当前游戏原生对象，向原生图片类传入 Hero 类型。`@decky/ui` 没有公开重导出该枚举，局部常量 1 与依赖枚举及设备运行值对应。
3. 设置 `allowCustomization=false`，避免原生图片组件插入文件选择或修改作品入口；关闭重复标题与过渡，图片不新增焦点。使用原生 `onLoad` / `onError` 及实例 `is_default_image` 判断是否显示；通用 Hero 不冒充该游戏作品。
4. 使用 Steam 原生 `ErrorBoundary` 的空 fallback 限定第三方渲染失败的影响范围；以 AppID 为 key 隔离图片加载/失败状态。管理页另以实例 ID 为 key，换游戏或实例时重新挂载，避免旧图和失败状态残留。
5. 保留原生 `PanelSection` / `PanelSectionRow`，局部样式仅控制图片尺寸和裁剪。Rust、Python、协议及业务动作不变。

只在图片入口处理实际存在的“方法不可用 / 无图片 / 加载失败”，不扩展成多层图片探测、重试、URL 猜测、CDN 地址拼接或后台下载服务。Rust、Python 宿主、协议、安装状态、取消和更新行为不变。

## 10. 2026-11-02 隐藏不支持的 EXE 文件预览

用户报告点击“查看文件变更”后出现 `exe_check_required`。沿 CLI `preview` 路由与 Rust `projection::preview` 核对：`exe-selection-*` 进入 `PublisherExeSelection`，当前只返回该 blocker，不提供变更清单；这不表示安装 EXE 不受支持。

- 根据与核心相同的动态选择身份，在 `exe-selection-*` 路径隐藏预览按钮及预览结果；安装、覆盖安装和现有阻断原因保持原样。
- 签名目录与动态 ZIP 路径保留只读预览，不根据文件名后缀推断能力，不新增探测、下载或协议字段。
- 验证 EXE 无预览入口但仍可安装，切换 ZIP / 签名目录后预览入口正常，切回 EXE 后隐藏；更新施工与部署记录。
