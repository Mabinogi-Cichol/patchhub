# Windows 补丁管理页布局修复方案

状态：已实现；定向与完整 Flutter 回归、静态分析、Windows 原生窗口验证及 release 候选构建通过；用户视觉验收待完成。2026-10-29 根据用户截图与 `main` 的 `1269094` 制定并实施本方案。设计入口见 [design.md](design.md)，实际验证与待验收项见 [progress.md](progress.md)。修复分支：`fix/patch-management-flow-simplification`。

## 1. 问题与证据

| 问题 | 当前实现与影响 | 判断边界 |
| --- | --- | --- |
| 重新匹配按钮孤立 | [library_page.dart](../../../apps/windows-flutter/lib/pages/library_page.dart) 的 `managementContent` 在页签下另建一行，按钮与导航、补丁信息都未形成明确对齐关系 | 截图与源码相符 |
| 右侧补丁状态过窄 | [patch_management_page.dart](../../../apps/windows-flutter/lib/pages/patch_management_page.dart) 使用 `SizedBox(width: 240, child: summary)`；外层左右各 20、状态块左右各 16、图标 26 与间隔 12，使状态描述实际可用宽度约为 130 | 原因是固定宽度和层层留白，不是单纯最大宽度偏小 |
| 更多游戏信息不完整 | 安装路径与库位置合在同一个 `SelectableText`，位于窄侧栏的 `ExpansionTile` 中；截图显示频繁折行与底部内容未完整可见 | 当前局部代码未发现显式固定高度或行数限制；实际裁切机制待运行时复现，不能直接归因于 `maxHeight` |

## 2. 推荐布局

### 2.1 重新匹配并入页签工具栏

- 宽窗口：左侧保留“补丁管理 / 操作记录 / 游戏订阅”，右侧放带刷新图标的次要按钮“重新匹配”，在同一行垂直居中。左右边缘与下方内容卡片对齐。
- 该按钮仍只在补丁管理页签显示；有结果、仅网页候选和暂无结果时都可触达。游戏订阅页已有的重新匹配入口保留原有作用。
- 匹配过程中，按钮原位显示转圈图标和“正在匹配”，沿用 `queryRunning(row)` 禁用重复点击；移除旧独立行及其“正在查找补丁”占位。开始与结束不造成整块内容上下跳动。
- 宽度不足或文字放大时，工具栏改为两行：页签在上、操作靠右在下，维持完整文字与正常点击区域。沿用现有页签横向滚动能力。
- 按钮保留按文字缩放计算的宽度；切到其他页签时保留其布局占位，避免底部安装操作栏随页签切换移动，隐藏按钮不参与点击和键盘聚焦。
- 修改局限于 `library_page.dart` 的页签工具栏及 `managementContent`；未完成操作提示继续保留在内容上方，安装栏继续放在底部。

### 2.2 补丁状态栏采用更宽的自适应宽度

- 双栏时，右栏以 **320–360 个 Flutter 逻辑像素**为初始视觉目标，随内容区域可用宽度分配；这是布局目标，不限制文本长度。
- 右侧面板外层内边距建议由 20 调整为 16，状态块内部保留约 16；不通过缩小字号补空间。状态标题与说明允许自然增高，图标与文字顶部对齐。
- 双栏判断改为读取卡片内部真正可用的宽度，计入封面、两处间距、右栏及左侧选择区；左侧选择区以约 360 个逻辑像素为初始可读宽度，并考虑文字缩放。空间不够就让状态面板进入下一行、占满卡片宽度。
- 封面沿用现有显示规则；不为了塞入右栏压窄补丁选择、镜像选择及适用条件。
- 上述尺寸为待渲染校准的设计起点；最终以长文案、窄窗口和 125% / 150% 文字缩放下的实际效果验收。

### 2.3 更多游戏信息改为通栏折叠区

- 右侧保留补丁状态、AppID 和游戏 Build，供首屏快速浏览。
- 将“更多游戏信息”从右侧面板移出，放在“封面 + 补丁选择信息 + 状态栏”整行下方、现有“文件与技术详情”上方，使用卡片内容全宽。
- 安装路径与库位置拆成两个独立字段，采用“标签在上、完整路径在下”的格式，字段间留 12–16 像素。标签和路径不再串成一段文本。
- 使用普通文本自然换行并配合 `SelectionArea` 保留选择与复制；不设置固定内容高度、最大行数或省略号，不在路径区域再套一层滚动。长路径与无空格目录名均须完整可达；复制内容保持原始字符串。
- 展开时由内容撑开折叠区和卡片，沿用外层管理页 `ListView` 滚动。底部安装操作栏保持可见，最后一行路径能滚动到操作栏上方。
- 沿用按游戏实例区分的展开状态 key，维护展开、页面滚动及文本选择之间的状态隔离。切换游戏、切换页签后不出现类型冲突或其他游戏的路径。

## 3. 实施顺序

1. 调整页签工具栏与重新匹配按钮，覆盖查询运行中及无结果入口。
2. 调整卡片内部双栏宽度预算与侧栏留白，确保选择区仍可读。
3. 迁移游戏路径折叠区，拆分完整路径字段，核对展开后的自然高度、外层滚动及复制。
4. 按下列验收项补充有针对性的布局检查、原生截图与施工记录；更新本方案中经渲染校准的尺寸。

## 4. 验收标准

- 复用 [modern_layout_test.dart](../../../apps/windows-flutter/test/modern_layout_test.dart) 的 1440×900、1180×760、850×560，以及 1.0 / 1.25 / 1.5 文字缩放和深浅主题；补充截图约 1382×1169 的近似尺寸检查。测试中的窗口尺寸以 Flutter 逻辑像素为准，原生截图另记录系统 DPI。
- 补充当前状态说明、长中文标题、长下载项、含空格路径、中文路径及长无空格目录名的真实字段展示。展开后滚到最后一行库位置，检查完整可见及可选择复制；没有布局异常不足以证明文本完整。
- 检查有补丁、仅来源候选、无匹配结果，以及查询进行中 / 结束后的按钮位置和可用状态；沿用 [patch_management_flow_test.dart](../../../apps/windows-flutter/test/patch_management_flow_test.dart) 的真实交互夹具。
- 调整窗口及文字缩放时，双栏在空间不足时转为纵向排列；路径展开与收起不遮挡底部安装按钮，补丁和镜像选择状态不变。
- 原生窗口检查截图中的三处问题及键盘聚焦、Tab 切换和长路径复制。原生验证前不标记视觉验收通过。

## 5. 过度设计审阅

对上述方案及当前成功路径进行静态审阅：未发现需要额外机制的项目。三项修改均对应截图中的实际问题，复用现有工具栏、布局约束、折叠和页面滚动即可；不新增可拖动侧栏、宽度设置、详情弹窗、嵌套滚动或查询状态机。320–360 与 360 是初始排版目标，不能作为截断合法文本或拒绝展示的条件。此结论仅评价方案必要性，不代表实现、自动化或实机已通过。
