# 补丁管理整合与流程精简

状态：已实现；自动化、Windows 原生窗口与本地候选构建通过；真实游戏 / Steam Deck 验收待执行，详见施工记录。

任务类型：feature。最终范围包含新增手动下载链接能力及双端交互重整；开发分支为 `feature/patch-management-flow-simplification`，后缀与功能目录一致。

施工记录见 [progress.md](progress.md)。本方案依据 2026-10-28 对话和当前 `main` 的 `fbe3ce5`，生图仅供布局讨论，不作为业务状态或能力的依据。

## 1. 目标与已确定的产品决策

- Windows 和 Decky 均删除独立概览页签，选择游戏后直接进入补丁管理。
- 保留补丁下拉选择和下载项 / 镜像选择，不改成平铺候选卡片。
- 将概览仍有用途的信息并入管理页：完整游戏信息、重新查询与语言偏好、未完成操作提示和操作记录入口。查询错误只写日志，不迁入页面作为诊断提示。
- 精简用户指出的四类流程：要求本地 ZIP、EXE 隔离可用性阻断、待核对来源、查询未完成。按确认范围删除实际判断、入口和仅为其服务的文案及测试，不只隐藏状态卡片。
- 本地 ZIP 保留可选导入，删除必须选文件的默认安装路线。
- 删除 EXE 提前隔离探测和实际解析隔离，改为直接启动项目自带解析器进程。
- 保留来源网页；没有解析到下载项时明确提示，并支持手动输入 ZIP / EXE 直链。
- 查询运行时显示加载动画；失败停止动画、保留旧结果，无旧结果显示“暂无补丁结果”，保留重新查询入口，具体错误只写日志。
- 2026-10-28 用户已要求开始施工；在当前 feature 分支实施并记录验证。计划提交为 `130a434`；本轮不发布或操作 Steam Deck。

## 3. 用户确认的施工边界

2026-10-28 两轮问答已确认下列决定，原草案的互斥路线全部撤销。

| 编号 | 已确认决定 | 施工约束 |
| --- | --- | --- |
| Q1 | 只删除必须选本地 ZIP 的流程，保留可选导入 | 保留 `archive`、`LocalArchive` 和现有支持该能力的条目；不把可选导入扩展成所有来源的新能力，不再用它替代默认自动下载路线。 |
| Q2 | 连实际解析隔离一起删除，直接运行解析器 | Windows AppContainer / ACL profile 与 Linux bwrap 等生产隔离链路退出；不保留自动隔离回退或开关；保留解析、流式提取和实际错误处理。 |
| Q3 | 保留来源网页，明确没有下载链接，并允许用户手动输入 | 仅支持可直接下载 ZIP / EXE 的链接；不包含网盘分享页、提取码或浏览器自动化。 |

| Q5 | Windows 与 Decky 均删除概览及相关流程 | 两端导航和默认入口同步调整，共享核心、协议和宿主同步接线。 |

### 3.1 页面与操作

- 两端保留补丁管理、操作记录、游戏订阅三栏；Decky 继续使用原生下拉和手柄导航，不复制 Windows 控件。
- 正常条目仍为补丁下拉 → 下载项 / 镜像下拉 → 安装；已安装时沿已有事实显示覆盖安装。
- 仅网页条目显示“未找到下载链接”，保留“来源网页”和“手动输入下载链接”入口；手动输入区域包含链接字段，使用同一安装任务，不额外增加人工核对确认页。
- 有有效下载项的候选直接进入既有安装路线；不因语言或 DLC 信息未知增加待核对门槛。本轮不扩展为清理所有安装器内部条件。
- 本地 ZIP 放可选折叠区，用户主动选择后才进入本地输入路线。签名条目无远程 artifact 时仍可主动导入；页面说明没有下载链接，但不展开必选文件提示，不把主按钮改成“需要选择本地 ZIP”。未提供任何输入时不发送空安装请求。
- 查询失败不弹窗、不展示错误横幅、诊断折叠或错误状态标签；旧结果保留，无结果统一使用已确认的中性文案。范围是查询反馈，不吞掉下载安装、写入或恢复任务的错误。

### 3.2 EXE 直接解析技术方案

- 复用项目自带 `patchhub-worker` 与现有分析 / 提取协议，宿主直接创建普通子进程；输入路径由宿主传入，取消、退出码、stderr 和 stdout 流继续由现有任务管理。
- 删除 CLI `exe_sandbox_availability`、探测缓存 / 临时探测目录、能力投影的隔离阻断，以及安装入口的重复 probe。
- 改造 `WorkerRuntime` / `WorkerSession`：移除 AppContainer profile、ACL 授予、bwrap 挂载 / namespace、仅服务隔离的非 root 限制和资源硬限制；移除仅为隔离创建的 worker / 输入副本。生产路径不再依赖隔离原型和 probe 二进制。
- `sf_worker.rs` 当前 Linux 固定读取 `/input/archive.exe`，Windows 使用相对路径；必须同步改为宿主传递的实际输入路径，不能只替换启动函数。
- 保留子进程的目的为沿用流式协议和可取消任务，不增加新的服务、线程池、重试或跨进程框架。直接运行的是本项目解析器，补丁 EXE 仍作为解析输入。
- 保留真实文件提取目标边界、帧 / 输出契约与取消终态；解析器缺失、无法启动、解析失败等在实际操作时按真实任务错误返回，不再包装成隔离不可用。
- 删除仅服务旧隔离链路的模块、依赖、构建 / 打包检查和测试；在取消需要进程管理机制时只保留相应的生命周期作用，不重新施加访问隔离。

### 3.3 手动下载链接技术方案

- 当前 `manual_selection` 只能选择缓存中已有 mirror，不能承接未解析出的 URL；因此需要新增显式手动下载输入，不能将用户链接假装成已解析 mirror。
- 以当前游戏和所选来源候选为上下文，通过安装请求携带候选身份和用户明确输入的链接；核心重新读取真实实例及候选事实。新增目标输入与既有 release / selection 目标互斥，不接受前端指定写入目录、配方或 worker 路径。
- 在同一次安装任务中完成下载、按实际内容识别 ZIP / EXE，再复用相应解析 / 提取 / 写入流程；不依赖 URL 扩展名，不新增“先创建链接任务再安装”的前置步骤。
- 手动链接作为显式用户输入，与自动来源的 `download_hosts` 规则区分；不因来源解析规则未收录该下载域而阻断用户补充的直链，也不修改来源的全局域名配置。只接受网络下载 URL，保留已有真实下载错误和格式错误的解释。
- HTTP 重定向使用同一手动输入语义处理，不能在首跳放行后又套回自动来源域名判断；下载后为网页或其他不支持的文件时按安装结果报错，不新增网盘解析流程。
- 幂等身份绑定实际链接、游戏和候选；用户改链接后不复用旧输入的任务身份。复用现有 request / task 机制，不新增链接库、持久化配置或通用下载管理器。
- 双端输入在当前选择内保存；换游戏或补丁清除，运行中使用任务启动时的输入快照。可复制链接和来源入口保留。

### 3.4 查询逻辑精简

- 页面是否查询中只由实际任务 `running` 判断；持续动画随任务开始 / 结束切换，有真实进度再展示计数，不使用任意耗时阈值判断失败。
- 删除游戏页和游戏列表中查询失败 / 未完成 / 覆盖不完整的专门反馈，检查双端共用状态函数、通知与 task.error 的页面传播，避免其他公共横幅再次显示相同错误。
- 来源索引完整度、失败等底层事实若仍参与来源查询和回填，保留其必要数据，不将错误改写成 `no_match` 或成功。清理只为旧 UI 状态服务的分支，避免误删仍用于真实匹配的判断。
- 查询更新按实际结果更新，失败不清空已有补丁和来源信息；无旧结果用“暂无补丁结果”，仍可重新查询和进入游戏订阅。

1. 删除双端概览导航和页面实现；Windows 三页依次为补丁管理、操作记录、游戏订阅；Decky 默认面板由 overview 改为 patches，删除对应 SidebarNavigation 项及专属滚动状态。

### P2：删除四类多余流程

按以下顺序推进依赖，保持每步可验证：

1. **EXE 运行时**：先完成普通子进程分析 / 流式提取，再移除 probe、能力阻断、旧隔离模块及依赖；核对 Windows 和 Linux 两条实际启动路径。
2. **默认与可选输入**：修改 `PatchActions::evaluate`，不再将 local_archive 自动选为主输入；双端保留可选导入和现有协议字段，主动选文件后才启用本地安装；删除“主要路线必须本地 ZIP”及对应 UI 判断。
3. **手动链接核心**：扩展安装请求目标及协议；在 acquire / resolve / service / 请求身份绑定中接入显式 URL 输入，按实际内容分派 ZIP / EXE。实现无扩展名与正常跳转的直链，不增加来源配置步骤。
4. **来源界面**：移除泛化待核对状态及人工核对步骤；双端新增“未找到下载链接”和补充链接区域，接入同一任务进度 / 结果流程；普通下载项保持原下拉选择。
5. **查询界面**：使用实际 running 展示动画；删除终态失败 / 未完成专门页面、标签和游戏查询通知，错误只记日志；失败保留旧结果，无旧结果为“暂无补丁结果”。

交付：删除发生于实际执行路径，UI 不再被已删除的核心事实反向禁用。
