# 打开时初始化订阅源与每周默认更新

施工状态见 [progress.md](progress.md)。

## 目标与产品规则

- 每次打开 Windows 客户端或 Decky 插件界面时，检查启用的发布者订阅源；状态为 `not_refreshed` 时，在后台发起 `force: true` 更新，包括关闭了周期更新的自定义源。
- 每次打开只检查一次；失败或取消后不在轮询中反复强制更新，下次打开仍是未更新状态时再次尝试。已有运行中的同源任务复用，不重复排队。
- 内置发布者源在没有用户周期设置时默认每周（168 小时）更新。显式保存的周期（包括 0 / 关闭）优先，自定义源仍默认关闭周期更新。
- 禁用源不自动更新。HGamer 为按游戏查询的 fallback indexer，没有整站更新入口，保留现有按游戏补查行为，不设置周期。

## 技术方案与边界

- Rust `SourceRegistry::list_sources` 根据来源类型和是否内置，提供默认周期；不迁移或改写用户设置，不增加协议字段。
- Windows 复用启动时立即执行的调度检查，以打开检查参数纳入 `not_refreshed` 源，并对它们传入强制更新标志；每分钟调度仍仅处理到期源。
- Decky 在界面开始订阅任务轮询时，读取当前来源并启动未更新源任务；使用现有任务 RPC 和后台同源任务去重。后续任务轮询和后端定时更新流程保持原职责。
- 使用已有后台更新、进度、失败状态和更新后的游戏投影，不增加重试器、超时、持久化标记或新的设置项。打开检查是发起更新的规则，不阻塞界面等待网络完成。

## 实施与验收

1. 建立文档，调整 Rust 默认周期，覆盖新状态、已有设置和自定义来源。
2. 接入双端打开入口，覆盖未更新、已更新、禁用、fallback、周期关闭和运行中任务。
3. 运行对应 Rust、Flutter、Decky 回归和静态检查，完成过度设计审阅并记录结果。
4. Windows / Steam Deck 首次打开、失败后重新打开及真实站点更新为实机待验收项；本任务不包含部署或发布。
