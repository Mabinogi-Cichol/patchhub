# 可导入脚本来源适配器施工计划

状态：**施工中，P0 原型与 P1 核心导入/设置事务已完成，P2–P7 待实施**。目标与技术决策见 [design.md](design.md)，实际执行记录写入 [progress.md](progress.md)，不得把本文件的任务清单当作完成记录。

## 依赖与执行方式

`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7`。每阶段完成后更新施工记录、记录必要证据，并按仓库精简原则审阅实际实现。发现接口或数据形状不足时先更新设计，不通过站点专用暗门绕过公共入口。**全部内置来源迁移为脚本并移除旧 Rust 网站实现，是最终交付条件**；单个样例与自定义导入能力仅是中间阶段。

初始计划阶段只完成文档。用户于 2026-10-30 要求开始施工后，P0 已按下述出口实施，证据见 [P0 合同](p0-contract.md) 与施工记录；部署、安装、Git 提交及实机操作仍不因本计划获得授权。

随后用户明确要求先提交 Git、再实施 P1。已将 P0 代码/文档分别提交为 `138c0c6` / `57dd65c`，P1 实施与验证结果见施工记录；此授权不扩展为推送、合并或设备操作。

## P0：验证运行时与冻结合同

**目的**：用最小原型证明跨平台执行和现有核心接口能接上，再进入持久化与界面开发。

- 在临时测试目标验证 Lua 5.4/`mlua` 的 Windows MSVC 与 Linux 构建，选择兼容仓库工具链的版本、`lua54`/静态内置/序列化等必要 feature；记录许可证、产物体积与打包影响。
- 验证借用现有 `RequestContext` 的 scoped 回调、DOM 节点生命周期及 Lua/Rust 数字、UTF-8、数组/空值转换；不靠 `unsafe` 延长引用生命周期。
- 验证文本加载、显式标准库集合、无文件/进程/模块加载入口；用纯计算循环及 `pcall` 包裹回调验证用户取消，单独测量长字符串/C 函数期间的取消限制。明确 hook 对取消信号的所有权，不借助 `unsafe` 伪造静态生命周期；入口返回与发布前再次检查取消。
- 选定一个真实非表格样例。优先从现有 Kagura 海外解析构造脚本样例，覆盖目录分页、详情 Steam ID 和镜像；录制所需页面/响应夹具，不将“已经有表格脚本”当作复杂网站已支持。
- 同时建立全部四个内置来源及通用表格的迁移行为清单，覆盖设计 §7 所列路径；原型选择单站点不缩减最终迁移范围。
- 冻结脚本 API v1、导入/读取 DTO、错误语义、源码摘要与索引解析标识关系；核对 JSONL v5 扩展及持久化字段的真实兼容性。

**出口**：两平台最小运行与取消证据、接口合同及样例字段表齐全。若关键能力不足，写明原因并修订方案；不能只把技术选型写成“已支持”。

## P1：导入、读取与完整设置事务

**主要位置**：`sources/model.rs`、`validate.rs`、`registry.rs`、`store.rs`、`snapshot.rs`。

- 新增 `lua` 来源描述、API 版本/源码摘要及默认空的源码存储；普通列表仅输出描述。
- 实现导入与读取；源码只做语法编译，不执行顶层；入口缺失在可取消执行时给出明确错误。
- 首次导入拒绝重复 ID，显式替换只更新同 ID 脚本来源；保留名称覆盖、启用、订阅和间隔。
- 规则、源码、摘要和设置版本同事务提交；注入写失败验证旧设置字节与原有来源不被部分覆盖。
- 只读快照捕获同一份规则与源码，普通读取不能创建状态或执行脚本；新增元数据缺失时保持旧来源行为。

**验证**：旧设置读取、新来源/重启读取、显式替换、重复 ID、错误 API 版本、无效 UTF-8/语法、摘要不一致、保存失败与只读不写入。覆盖新增能力本身不改变尚未迁移的来源指纹，名称编辑不改变解析身份；实际切换脚本的失效验证归 P3/P6。

**出口**：核心可在隔离状态中导入/取回/替换脚本，尚不宣称联网解析可用。

## P2：脚本运行时与宿主能力

**主要位置**：拟新增 `sources/adapters/script.rs`，关联 `adapters/dom.rs`、`http.rs`。

- 实现一次调用一个环境、导出函数调用、作用域内 HTTP/HTML/URL/JSON 回调及返回值转换。
- 脚本 HTTP 复用 `RequestContext` 的 URL/域名与重定向检查、Cookie、字符解码和取消；支持真实样例所需的 GET/POST/表单，脚本无直接网络或文件入口。
- 在模块顶层与各入口执行期间接入取消 hook；取消后终止当前执行并返回现有任务取消语义。不要用任意运行时长阈值取代取消。
- 输出转换/校验失败带来源 ID、入口与 Lua 行号/错误详情；宿主错误不得吞为 `nil` 或空成功。

**验证**：列表/表单/中文编码、DOM 选择与 URL 合并、非法域名/跳转、纯计算循环取消、网络等待取消、语法/运行时/类型错误、实例之间无可变状态共享。用真实需求判断是否需要补充宿主函数。

**出口**：脚本可以提取事实并可靠结束/取消；核心权限边界与风险表有执行证据。

## P3：发行商索引、详情与缓存/安装一致性

**主要位置**：`adapters/mod.rs`、`update.rs`、`matching.rs`、`index.rs`、`registry.rs`、`snapshot.rs`、`installer/{resolve,exe_resolve,manual_selection}.rs`。

- 新增统一适配器解析，接入索引采集；详情解析改为公共入口，Rust Kagura 可在迁移期临时委托，最终由 P6 脚本替换并删除该 Rust 委托。
- 将脚本 `IndexOutcome`/`PageFact` 转换进现有发布、共享详情缓存和候选生成路径。直链和详情型索引均需覆盖，不能把所有非表格条目强制交给 Kagura。
- 明确完整/部分/失败结果；不完整或异常不覆盖上次完整索引，既有续跑进度继续受核心管理。
- 源码摘要参与规则和索引解析身份；落实设计 §6.2 的所有读取及安装消费者。脚本替换后即使条目字面未变，也要使旧详情/匹配与旧选择失效。
- 预览/安装复用有效缓存，不在安装写文件阶段任意执行来源脚本；未匹配或过期时要求重新更新/匹配。

**重点回归**：

1. 索引更新不遍历游戏库；游戏匹配不重新遍历全站列表。
2. 同页面详情跨游戏复用；解析异常保留上次正式文件并明确失败。
3. 原脚本 A 已有索引、详情、游戏匹配和选择；替换为 B 后，在更新前、更新后但未匹配、重启及只读投影中均不能把 A 的结果当作 B 的授权。
4. B 返回与 A 相同条目时仍重算必要详情；名称编辑不触发这类失效。
5. ZIP、EXE、人工候选与手动 URL 路径均继续执行域名、身份、订阅及格式检查。
6. 迁移期间未切换的来源继续可用；已切换来源只走脚本生产路径。四个来源的最终完整迁移验收归 P6/P7。

**出口**：一份实际导入的非表格发行商脚本完成“更新 → 匹配 → 核心预览/重新解析”链路，缓存与选择绑定回归关闭。

## P4：脚本补查与多来源聚合

**主要位置**：`adapters/mod.rs`、`matching.rs`、`registry.rs`、既有补查记录与诊断投影。

- 实现 `discover` 的事实返回及核心候选生成，脚本不直接指定自动安装能力或候选指纹。
- 遍历所有符合条件的补查源，复用聚合 `FallbackMatchRecord`；查询键覆盖排序后的来源集合及脚本摘要。
- 保持发行商命中优先；补查源不接受全站更新，也不进入自动索引调度。
- 单源失败保留其他源成功结果与对应诊断；全部完整无命中才产生无结果。旧单源负缓存不用于新的来源集合。

**验证**：仅 HGamer、仅脚本、HGamer+脚本及多个脚本；一成功一失败、全部完整无结果、取消、订阅切换、源码替换、重启查询复用。沿真实调用链检查 `cached_discovery`、候选与动作投影，不能只验证查询函数。

**出口**：索引型和按游戏查询型网站均能通过自定义脚本接入，具备在 P6 将 HGamer 完整迁到脚本的能力。

## P5：协议、双端导入与编辑

**主要位置**：`crates/protocol`、`crates/cli`、`packages/contracts`、Decky `main.py/backend/source_service.py/src/index.tsx`、Windows `host/models/pages/source_pages.dart`。

- 增加导入/读取接口、结果与能力声明，更新生成契约、跨语言夹具和 Flutter schema；两端方法表与核心一致。
- 两端提供规则和源码输入、语法错误展示、示例、编辑/显式替换；成功后刷新现有来源列表，保留既有名称编辑/启用/订阅/间隔。
- 已迁移的内置脚本也能读取和显式保存为同 ID 用户覆盖；发行版更新不能悄悄覆盖用户已保存的脚本。沿用现有来源覆盖机制，不新建另一套脚本版本管理。
- 显示脚本类型、API 版本和摘要；简短说明执行来源代码与域名范围。明确“保存成功”“实际执行通过”“尚未更新/匹配”的区别。
- 输入/读取源码按实际协议承载，不复用旧 `add_source` 的固定文本上限；不增加源码大小、页数或报告长度的任意截断。
- 更新 [来源使用指南](../../source-adapters.md) 与示例目录（实施时建立），说明作者所需入口、字段、导入方式、更新和调试方法。

**验证**：双端导入/读取/替换/失败保留输入、重开保持、既有页面回归、不同能力版本的明确错误；大于旧文本入口上限的合法脚本可正常传输。执行仍在核心，不能在前端或 Python 暗中运行另一解释器。

**出口**：用户能够在两端自助管理脚本来源，不需要手改状态目录。

## P6：全部内置来源迁移与 Rust 网站实现退役

**主要位置**：`crates/core/resources/sources.json`、拟新增随包 Lua 脚本资源、`sources/adapters`、`matching.rs`、来源回归夹具与发行资源配置。

- 将 Shiravune、Kagura 国内、Kagura 海外、HGamer 逐一实现为随包 Lua 脚本，统一走 P2–P4 的生产分派；可按逐源验证结果依次切换，最终必须全部完成。
- 将 `table_html` 的列配置解析迁到随包 Lua 脚本，保持现有 JSON 示例可用；Rust 保留通用 DOM/HTTP/URL/身份处理能力。
- 内置脚本与自定义脚本使用同一 API、执行器、权限和取消机制；内置来源无需用户手动导入。需要兼容的既有适配器名称只映射到脚本资源。
- 保持四个来源 ID、用户名称、启用、订阅、间隔及历史记录。迁移使解析身份变化时让受影响缓存/旧选择按既定规则失效，不通过保留旧指纹来继续授权旧结果。
- 为四个来源分别记录旧行为基线与脚本结果对照，覆盖设计 §7 的语言表单、分页/多入口、详情、镜像、DLC 和补查路径；对比使用同一批页面/响应输入，并补充真实网络证据。
- 逐源切换后删除对应 Rust 网站专用模块、注册与详情分支，清理只为旧路径服务的配置/测试；保留并迁移仍有业务价值的夹具和断言。
- 验证读取/更新/匹配/预览/安装均无法进入旧 Rust 网站解析路径；脚本失败应明确失败，不得回退旧引擎，也不通过网站专用宿主回调偷偷保留旧算法。

**出口**：四个内置来源与通用表格均已脚本化、逐源验证有证据，生产代码不再保留旧网站解析实现。任一来源未迁移则本阶段不能完成。

## P7：全面验收、打包与收尾

- 对全部内置脚本与自定义导入样例完成离线自动化和真实网络验证；内置脚本覆盖设计 §7 的逐源矩阵，自定义导入覆盖独立规则与源码。均走生产分派，不使用直接调用 Lua 的专用测试捷径代替，也不以单个站点通过代表全面迁移。
- 在隔离游戏目录执行合成 ZIP/EXE 的下载/预览/安装回归，核对脚本没有文件写入能力；真实游戏安装只在获得相应操作授权后执行，并独立记录游戏内是否生效。
- Windows 与 Linux/Deck 构建、原测试门禁、协议生成一致性、许可证/SBOM/发行包 runtime 依赖核对。确认终端用户无需另外安装解释器。
- 核对两端发行资源包含全部内置脚本，干净环境启动无需手动导入；升级已有设置时仍使用相同来源 ID 和用户设置。扫描产品代码和发行包，确认没有 Rust 网站解析兜底或只在发行模式启用的旧分派。
- 获得设备操作授权后分别做 Windows 原生界面与 Deck 游戏模式/实体手柄导入、进度、取消、重启验收。自动化或 Linux 构建通过不能代替设备验收；未执行项保持“待验证”。
- 对最终 diff 与执行链做过度设计审阅，核对没有额外重试、TTL、任意容量/时长上限或不再使用的专用配置。
- 更新设计、施工记录和功能索引，列明完成项与遗留风险；仅在用户要求提交/合并时按仓库规则拆分代码和文档提交。

**完成标准**：P0–P6 的出口全部有证据；四个内置来源与通用表格全部使用脚本，旧 Rust 网站实现退役，双端构建、核心一致性和约定范围的实机验收完成。若用户调整验收范围，明确记录调整，不能把未执行的网络/安装/手柄检查写成通过，不能自行将“全部迁移”降为后续事项。

## 施工中应持续核对的风险

| 风险 | 处理时点与核实方法 |
| --- | --- |
| Lua API 能力不足以覆盖真实网站 | P0/P2 用非表格样例验证后补最少宿主函数 |
| 当前 Kagura 专用详情调用遗漏 | P3 搜索分派并追踪更新、匹配、只读及安装消费者 |
| 只完成示例或遗留 Rust 网站兜底却宣称迁移完成 | P6 四源逐项切换和退役证据，P7 生产调用链/发行包核对 |
| 脚本替换后旧缓存/旧选择仍可使用 | P3 的 A→B 同条目场景，覆盖全部读取与安装路径 |
| 多补查源被 `.find` 或旧聚合键静默丢弃 | P4 多源混合结果与重启用例 |
| scoped 回调或 DOM 节点越过生命周期 | P0/P2 原型与类型约束，不用不必要的跨线程共享 |
| 纯 Lua 可取消但长 C 调用/内存耗尽未隔离 | P0 测量并写入用户信任边界，不宣称任意恶意脚本安全 |
| 宿主环境缺少运行时依赖或许可证遗漏 | P0 静态构建，P7 安装包与干净环境验证 |
