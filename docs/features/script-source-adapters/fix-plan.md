# Shiravune 后台自动访问与脚本信息展示修复方案

[设计文档](design.md) · [施工记录](progress.md)

状态：**修复施工中**。继续使用 `feature/script-source-adapters`，基线为 `2fd4881`。Windows 全新会话后台原型与 Deck 隔离状态中的普通更新任务已取得真实列表；正式普通入口、定时入口及发行部署按施工记录分别验收，不以原型代替完成。

## 1. 产品要求与边界

- 普通用户点击“更新来源”或触发定时更新后，后台自动完成来源访问、站点正常 JavaScript、会话与重定向、语言表单、Lua 解析、正式索引发布及游戏匹配。不增加打开网页、点击年龄 YES、手动采集或导入响应等常规操作。
- 用户在 Windows/Deck 原型中亲自确认年龄和采集，是协助验证开发可行性；该流程不是正式产品要求。此前手动页面和“在网页验证并更新”入口从产品实现中移除，原型证据保留在施工记录。
- 本次 Rust→Lua 迁移为 **Breaking Change**。不收养旧缓存、不补写旧解析指纹、不恢复旧安装选择；需重新取得索引并匹配。
- 内部源码摘要及解析身份保留，普通来源卡片移除完整 SHA-256；编辑器保留详情。
- 若网站真正强制真人验证码或要求用户本人声明，不能伪造声明或破解验证。该场景明确报告自动更新未完成，不能靠增加人工步骤降低完成标准。

## 2. 已确认的问题与证据

旧索引仍有 `SACRIFICE VILLAINS：牺牲恶棍` 的中英繁标题和补丁 URL，但没有当前解析指纹。Core 因而排除旧结果；新更新又收到 HTTP 200 请求验证页，产生 `patchmoe_language_forms_missing`。

旧 Rust 与 Lua 都保留重定向、Cookie 和语言 POST，也都在这张验证页失败；这说明存在已有访问能力缺口，不构成功能正确的证据。用户浏览器能完成验证进入列表，随后两个平台的手工原型取得了真实页面，说明浏览器会话内采集可行。

进一步自动化验证：Windows 使用新建 profile 的无网页界面 WebView2，加载原已配置的 `https://www.patch.moe/?flag=1`，未点击控件便自动取得根页面及英/繁/简三次 POST。Deck 普通 `SourceService.start_update_source` 在隔离状态中，经真实 Core 和隐藏 BrowserView 自动生成 165 条完整索引。此处不将“手工采集后回放”作为后台自动更新的通过证据。

标题线索目前保留原可信度，候选存在时汇总为未完成，避免假报 `no_match`；不把所有标题命中升级成可信身份。验收需同时核对目标游戏候选、来源状态、安装选择及重启读取。

## 3. 最小实现

### 3.1 宿主提供后台浏览器运行环境

- Windows 使用已验证的 WebView2 插件，控制器不挂载为网页组件；在应用状态目录保存独立 profile，正常执行网站脚本并复用有效会话。
- Deck 使用 Steam 自带 `BrowserView.Create`，设置可布局的视口后保持不可见。通过本插件创建的唯一空白地址绑定 CEF target ID，按实例读回响应。实测页面标题可能为空，完成事件中的 URL 也可能为空，故不依赖这些字段定位。
- 不调用年龄确认按钮，不伪造页面或验证码答案，不读取其他浏览器账户或页面；不引入通用浏览器平台。
- 按真实加载事件采集，站点仍正常验证时继续报告进度，用户可取消；没有任意总时长阈值或循环重试框架。完成、失败和取消均销毁本轮控制器或隐藏实例，会话数据按正常浏览器 profile 规则保留。

### 3.2 与普通更新、定时更新及 Lua 自动衔接

1. 沿用普通 HTTP 更新。识别已复现的请求验证/年龄页时，不将其解析为补丁列表，不发布空索引，记录检查时间与明确状态。
2. 宿主在同一个来源任务中自动进入后台浏览器阶段，加载当前来源入口。站点 JavaScript 自行完成正常请求验证；脚本仅提取页面和语言表单响应。
3. 宿主将响应交回 Core。`BrowserFetcher` 严格对应 Lua 实际发出的 URL、方法和表单体，Core 继续校验来源域名、事实、解析身份与发布条件。浏览器只提供传输结果，不代替 Lua 解析，也不恢复旧 Rust 网站实现。
4. 取得完整列表后发布索引并按现有路径重新匹配游戏。浏览器阶段和第二次 Core 调用仍属于同一宿主任务，保留进度及取消；不需要用户启动第二个任务。
5. Windows 普通更新和 `schedulerTick`、Deck 普通 RPC 和后台调度均调用这一相同来源任务路径。前端不新增手工响应入口。
6. 真正的个人声明、真人验证或异常网页阻断时返回明确失败。失败不能伪报刷新完成；已有兼容正式索引保留，Breaking Change 排除的旧索引仍不可用。

## 4. 验证与完成标准

- 自动化覆盖验证页/年龄页不能覆盖索引、浏览器响应与 Lua 请求绑定、三语言合并、目标游戏候选与 ZIP 选择、后台等待取消及实例清理、真人声明阻断不能变成成功。
- Windows 通过正式普通更新按钮和真实后台 WebView2；Deck 通过正常更新 RPC、正式后端和隐藏 BrowserView，均不使用手工采集文件作为输入。
- 两端在隔离的受控到期状态中触发真实定时入口，使用真实站点、当前 Core、同一自动浏览器阶段；分别记录到期条件、任务结果、完整索引和目标候选。不把时间夹具或单元测试描述为真实定时触发。
- 来源刷新、目标游戏匹配及重启读取通过后，才标记对应平台访问修复完成。标题证据仍按实际可信度展示，不为状态好看而放宽身份判定。
- 两端普通来源面板不展示长哈希，脚本修改仍使旧结果失效，显示名称修改不影响解析身份。
- 本轮不下载或安装真实游戏补丁；安装选择仅进行只读解析。设备部署沿用当前授权及项目技能，提交和推送另按用户要求执行。
