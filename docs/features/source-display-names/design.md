# 订阅源显示名称与规则示例

施工状态见 [progress.md](progress.md)。

## 目标与范围

- Windows 和 Decky 的全局来源均可编辑内置源、用户添加源及补查源的名称。
- 内置发行商源使用发行商名称；`patchmoe` 默认名称由 `patch.moe` 改为 [Shiravune](https://store.steampowered.com/publisher/shiravune/)。Kagura 保留国内/海外区分，HGamer 保留索引身份。
- 用户编辑名称只改变展示，不改变 ID、站点、适配器、订阅、更新间隔、索引或安装标识。

## 技术方案

在现有 `settings.json` 增加默认空的 `names: source_id -> name`。生成来源读模型时覆盖显示名称，内部规则保持原值，旧设置无需迁移；不复制内置规则，后续内置规则更新仍生效。

新增一次性协议方法 `set_source_name(source_id, name)`，返回设置版本、源 ID 和实际保存名称。核心去除首尾空白并拒绝空名称，未知源返回 `unknown_source`。不增加名称长度上限。名称在所有来源读模型中一致显示。

两端在展开的源卡片中加入有标签的名称输入及“保存名称”按钮，复用现有设置保存、忙碌态与错误反馈。失败保留输入，保存成功显示新标题；不触发网络抓取。

## 添加规则示例（2026-10-29 补充）

Windows 在“高级：添加来源规则”标题旁提供“示例”按钮，以可滚动对话框展示通用 `table_html` JSON；Decky 在添加按钮旁提供可展开的规则示例。两端提供复制按钮，不覆盖编辑中的规则，不自动添加来源。示例使用占位域名，说明需要修改 ID、名称、域名、表格 ID 和从 0 开始的列号，区分必填标题/下载列与可选列。复用既有系统剪贴板与错误反馈，不新增协议或规则解析能力。

## 实施与验收

1. 设置持久化、合并与默认名称；验证重开及旧设置兼容。
2. 协议、CLI、生成契约及 Decky 桥接。
3. 两端编辑交互及相关自动化。
4. 沿真实调用路径审阅过度设计并记录验证结果。

验收覆盖内置源/添加源/补查源、空白输入、失败反馈、重开保持、游戏订阅显示和用户编辑名称前后内部规则不变。发行版将内置规则默认名称更新为 Shiravune，按现有规则指纹契约计算新默认规则摘要。Windows 原生窗口与 Deck 实体手柄验收单独记录，自动化通过不代表实机验收。
