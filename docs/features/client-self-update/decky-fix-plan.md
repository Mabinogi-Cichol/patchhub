# Decky 自更新修复

- 分支：`fix/decky-self-update`，从当前 `main` 创建。
- 关联：[设计](design.md) / [施工记录](progress.md)。

## 已确认问题（2026-11-01）

设备现有 0.4.0 更新至 v0.5.0 失败，状态文件报 `pending_plugin_write`。只读 Steam CEF 现场显示多个 PatchHub `claim_app_update_notice` 在途请求。安装器 `BRIDGE` 的允许方法遗漏该方法，将维护插件目录外提醒记录的请求误判为插件业务写入，在 acquire 阶段拒绝更新。Loader 3.3.0 官方 `wsrouter.ts` 确认 `runningCalls` 仅保留未收到结果的请求；不直接删除其中的请求或解除真实写入保护。

现有进度只有每 3 秒刷新的下载字节文本，没有原生进度条，校验/替换/验证/恢复也没有阶段反馈。

## 最小修复

1. 将领取更新提醒加入安装器允许的方法；实际补丁写入和其他 Loader 安装仍互斥。用保留该在途请求的桥接夹具验证安装可完成，并验证真实写入仍被拒绝。
2. 独立执行者输出真实下载、校验、备份、安装、验证、恢复和清理阶段，沿用 preparing/applying 两个活动状态，不增加新的事务状态机。
3. 使用现有 Decky ModalRoot/ProgressBar 展示进度；已知大小显示百分比与字节数，未知大小和非下载阶段显示不定进度。点击更新立即打开，关闭仅收起；下载取消单独操作，替换时等待完成。全局设置保留进度入口与最终结果，重载后继续读取外部状态。
4. 状态轮询顺序执行并清理计时器，预期重载期间的读取失败呈现为等待连接，不能虚报安装失败。更新结果仍以外部执行者状态为准。

## 更新后当前页面未刷新（2026-11-01 追加）

用户实测测试候选 0.4.0 → 正式 v0.5.0 更新成功，但需要退出后重开页面。设备执行结果为 `completed / v0.5.0`，Loader 日志确认新版后端和前端导入已执行；插件导入/运行验证不等于已打开的 Steam 全屏页面重新挂载。

用户允许在不能可靠自动刷新的情况下修改完成提示。实机通过已有 Navigation 和 Loader 路由注册检查，未取得重新挂载旧页面的可靠证据；同路径追加版本查询参数仍不产生可确认的新组件挂载。因此本次采用提示方案，不添加内部 Steam 缓存操作、固定等待/循环导航或整个 JS 上下文重启。

- 安装按钮改为“更新插件”，不再承诺自动刷新当前界面。
- 进度说明提示完成后退出页面并重新打开；实际 Loader 后端安装流程保持不变。
- 设置页与进度弹窗完成提示一致：“更新已完成。请退出当前插件页面，再从 Decky 重新打开 PatchHub，以加载新版界面。”
- 已安装版本仍按真实更新结果报告，不能将界面未刷新写成安装失败，也不伪报界面已自动刷新。

## 验证

- 本地：桥接回归、安装器 Python 回归、更新宿主回归、前端组件/交互回归、TypeScript 检查及构建。
- 实机：测试候选部署、用户真实 0.4.0 → v0.5.0 更新及完成提示原生界面已验证；正式 v0.5.1 发行附件及实体手柄仍待验收。详细状态与证据以[施工记录](progress.md)为准。
- 过度设计复核：只放行有证据的提醒方法，不清空 Loader 请求、不增加重试、固定超时或新的恢复层。
