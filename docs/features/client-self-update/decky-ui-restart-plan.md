# Decky 自更新单行交互与客户端重启计划

- 日期：2026-11-03。
- 状态：候选已部署，定向自动化、原生界面、真实 RPC 与 Steam 客户端重启验证通过；完整 UI 跨版本自更新及实体手柄待验收。
- 基线：`main@f5488d8`；计划分支：`fix/decky-update-ui-restart`。
- 关联：[设计](design.md) / [施工记录](progress.md)。本计划覆盖旧 Decky 进度弹窗与“退出页面重新打开”的产品决策，Windows 不变。

## 1. 目标与界面

全局设置的“缓存、备份与更新”二级页面只保留一行更新信息：左侧当前运行版本，右侧唯一状态按钮。QAM 不新增更新入口。

| 状态 | 左侧 | 右侧原位内容 |
| --- | --- | --- |
| 初始、无新版 | 当前版本 vX.Y.Z | 检查更新 |
| 检查中 | 当前版本 vX.Y.Z | 检查中…（禁用） |
| 有新版 | 当前版本 vX.Y.Z | 更新至 vA.B.C |
| 更新请求已提交 | 当前版本 vX.Y.Z | 0% · 准备更新 |
| 下载、校验、安装、验证 | 当前版本 vX.Y.Z | N% · 当前阶段 |
| 安装验证与清理完成 | 当前版本 vX.Y.Z | 100% · 正在重启客户端 |
| 重启后 | 新进程确认的当前版本 vA.B.C | 检查更新 |

点击“更新至”即启动现有更新链，按钮立即被同位置的进度展示替换，禁止重复提交。不再自动打开进度弹窗，不显示第二份进度、发行说明、发布时间、可用版本行、“稍后”“跳过”“查看进度”或常驻完成提示；清理仅服务于这些 UI 的调用与组件。自动检查和已有新版本通知复用现有机制；按用户追加要求，插件前端启动立即检查，完成后通过原生 toast/tips 提醒新版，点击进入本页；无新版静默，同一 Tag 仍去重。不重做检测服务或偏好存储。

无新版用一次简短通知反馈。检查/启动失败用错误通知说明原因，单行回到可操作状态；安装失败沿用真实执行结果，必要时右侧唯一按钮为“恢复更新”。详细错误通过点击该异常状态查看，二级页面不增加错误段落。恢复成功不当作新版本安装成功而自动重启。重启调用失败明确显示“更新已安装，客户端重启失败”，右侧提供“重启客户端”；此操作只重试重启，不重新下载安装。

移除下载取消入口；本轮交互为点击更新后完成更新并自动重启。仍可离开设置页，后台执行不依赖页面存活。更新按钮的可访问名称明确包含“完成后自动重启 Steam 客户端”，更新期间保持手柄焦点稳定，进度区域提供可访问状态，不能因按钮被替换造成焦点跳入无关操作。

## 2. 百分比语义与数据来源

百分比表达整体更新进度，不能把下载完成显示为整体 100%。采用明确的阶段里程碑，下载阶段按真实字节推进，非下载阶段仅在完成实际工作后跃迁，不按时间模拟：下载占 0–80%，包校验完成 85%，备份完成 90%，Loader 安装完成 95%，新版运行验证完成进入清理 99%，事务收尾完成 100%。阶段名称与数字同位置展示，里程碑权重仅为 UI 约定，不宣称剩余时间。

下载总量优先使用已冻结的 Release 附件大小，并核对实际下载字节。没有可信总量时显示当前已确认的里程碑百分比与“下载中”，不按时间虚增。校验清单与包分别下载时，应按实际可计量任务汇总，不能重置或倒退百分比。

由现有独立执行者在插件目录外状态文件中记录进度，沿用执行状态及阶段字段，按需增加一个整体百分比字段；前端只呈现执行者结果。沿用现有约 1 秒串行读取，界面离开时清理计时器，重新进入后读取同一事务，不额外增加推送通道、进度服务或独立恢复状态机。安装卸载插件期间暂时断连保留最后进度，不虚报失败或 100%。

## 3. 完成后强制重启 Steam 客户端

成功链：下载 → 校验 → 现有任务门禁/备份 → Loader 安装 → 新版运行验证 → 事务收尾与结果持久化 → 发起 Steam 客户端重启 → 新客户端加载新版插件。

重启由现有独立安装器发起，不能由旧 React 页面观察 `completed` 后触发，否则旧页面卸载或用户离开设置会漏掉重启，也可能因重挂载重复触发。仅 GUI 自更新的正常安装成功路径触发，命令行安装、检查模式、失败回滚、恢复清理和仅查询历史结果均不触发。

安装结果和重启结果分开表达：重启请求受理不等于新版已在新客户端运行；预期 CEF/连接断开也不等于重启失败。先持久化安装成功与重启请求信息，再发起调用；新插件启动只读取结果，不对历史成功记录再次自动重启。不增加循环重启、固定倒计时或后台重试。

### 重启接口核验与实际落点

- 官方 [Decky 3.3.0 updater.py](https://github.com/SteamDeckHomebrew/decky-loader/blob/v3.3.0/backend/decky_loader/updater.py) 的 `do_restart` 调用 `service_restart("plugin_loader", block=False)`；它直接证明 Loader 服务重启，尚不能证明完整 Steam 客户端重启。
- 官方 [utilities.py](https://github.com/SteamDeckHomebrew/decky-loader/blob/v3.3.0/backend/decky_loader/utilities.py) 单独提供 `restart_webhelper`；不能只按函数名把 WebHelper 重启写成完整客户端重启。
- 实施首先追踪当前支持的 Loader/Steam API 和服务启动链，确定可由独立执行者调用的客户端重启操作。优先使用已有受支持接口，实际验证 Steam 客户端进程重建与新版页面加载；若只能刷新 WebHelper，则继续解决完整客户端重启路径，不将局部刷新视为需求完成。
- 不调用系统 reboot/shutdown，不把重启整个设备作为替代，不仅靠路由跳转或重新导入插件满足验收。
- 实施已核对当前依赖 `@decky/ui/src/globals/steam-client/User.ts`，声明 `StartRestart(force: boolean): void` 并注明重启 Steam 客户端。独立安装器通过既有 CEF 连接调用 `SteamClient.User.StartRestart(true)`；不使用 Loader 服务或 WebHelper 重启替代。按钮传入其实际页面的 `performance.timeOrigin`，宿主转交独立安装器并写入结果；前端只在同一页面上下文展示等待重启，避免新客户端读取历史成功结果后继续显示重启中。实机已确认 SharedJSContext 与页面标记不同，因此不从后台上下文取标记。接口及断连已覆盖夹具；生产重启函数已实机确认 Steam PID 改变、boot ID 不变、新版实例重新加载。完整 UI 更新成功后自动调用的整链仍待验收。

## 5. 验证与验收

- 前端：初始、检查中、无新版、有新版、请求提交、持续进度、断连、失败、恢复、重启失败；正常状态仅一行，更新过程中无自动进度弹窗；按钮重复点击不会重复发起更新。
- 安装器/宿主：真实字节和阶段驱动进度；仅完整成功链请求一次重启；失败回滚、取消、检查模式、终端安装、历史结果读取与恢复清理不请求重启；重启失败保留已安装成功的事实。
- 日常仅执行受影响的 Decky 前端测试、typecheck、构建及安装器/更新宿主 Python 回归，不运行发布完整矩阵。具体命令与结果在实施时写入施工记录。
- 实机：游戏模式 1280×800 页面及实体手柄操作；从按钮发起完整旧→新更新，进度原位刷新；离开页面后仍自动完成并重启；保存客户端重启前后进程、设备 boot ID（保持不变）、包与运行版本、页面新组件加载证据。重启后无需用户退出重开插件页面。
- 验证用户设置、来源和安装记录保留，现有任务门禁有效；客户端重启会重新加载其他插件，需记录其恢复情况，不承诺其他插件完全无中断。

## 6. 过度设计审阅

已按项目 `overengineering-review` 技能进行计划级静态复核：复用既有安装器、状态文件、轮询、完整包校验、任务门禁和失败恢复；新增内容限定为单行呈现、真实进度映射及成功链末端的客户端重启。没有新增常驻服务、通用更新框架、任意耗时硬限制、自动重试或循环恢复。具体重启接口已有依赖类型声明与设备进程重建证据；完整 UI 跨版本更新、百分比及自动重启整链仍待验收，不将单独重启验证等同于整链通过。
