# Windows 安装进度界面

施工记录：[progress.md](progress.md)。

## 目标与范围

按照用户提供的 PatchHub 安装进度图例重排 Windows 安装弹窗。复用现有任务事件、Steam 本地封面、下载速率与终态回执；不改变 Rust 协议或安装行为，不涉及 Decky 界面。

## 视觉与交互

- 使用现有主题语义色：深色表面 `#191919`、正文 `#eeeeee`、次级文字 `#b8b8b8`、分隔线 `#363636`、蓝色进度 `#78a9ff`；浅色跟随主题。沿用 Segoe UI / 微软雅黑，不添加字体依赖。
- 约 640 逻辑像素宽的居中弹窗，16 像素圆角与细边框。标题为 24 像素，游戏名 20 像素，正文 16 像素，内容左对齐。
- 顶部“安装进度”和右上关闭图标；主体左侧 84 × 112 的游戏封面，右侧依次为游戏名、补丁名、当前阶段、圆角蓝色进度条与百分比、已处理/总容量、下载速度和下一阶段提示。
- 下载阶段隐藏没有业务意义的文件计数；校验、提取、写入等阶段显示实际文件计数和当前文件。总量未知时使用不定进度，不伪造百分比。
- 底部以分隔线独立出操作区，右对齐描边“取消安装”。右上图标与 Esc 复用同一取消入口，任务结束前不关闭；取消请求已发出时按钮禁用，保持等候实际回执。
- 成功、失败、取消与仍需恢复结果沿用现有原因、诊断、清理和操作记录入口。关闭结果不会再次取消。
- 封面复用详情页已经加载的 Future 和现有 GameArtwork 缺图提示，不增加图片读取链或网络请求。小窗口 / 大字体时正文可滚动，长名称与路径换行，操作区保持可用。

## 实施与验收

1. 接入现有封面，替换弹窗布局和进度呈现。
2. 检查下载有/无总量、阶段切换、取消与终态；深浅主题、长文字及大字体布局。
3. 执行 Flutter 静态分析和相关回归，渲染界面检查视觉。真实游戏安装与原生窗口验收分别记录，不用夹具替代实机事实。

## 精简审阅

方案只调整视图与增加一个可选封面参数，使用现有 CoreTask 取消和结果处理。没有新增任务状态机、超时、重试、硬限制或动画框架；宽度为布局约束，不截断业务内容。
