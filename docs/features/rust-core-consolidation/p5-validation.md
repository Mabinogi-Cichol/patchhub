## 实现与边界

- `crates/protocol` 是唯一 wire 定义和校验入口，版本固定 4。逐方法严格 params，必需 host 六字段，显式 operation/cleanup_policy，外层 request_id 唯一绑定；拒绝未知字段、旧版本、重复 JSON 键和不安全整数。core 不依赖 protocol。
- 非打包 `crates/contract-gen` 以 schemars/ts-rs 生成 JSON Schema、TypeScript、Python 纯数据和固定夹具。UTF-8/LF、顺序稳定、没有时间戳或绝对路径；check 逐字节校验。共享 fixture 验证 Rust、Windows、Python、UI 的消费一致性；最终42请求、82响应、19事件、3序列、4边界、2原始请求、1detail样本和8早期错误生产者样本。
- CLI 使用结构化 DomainError 和有界 serializer。64 KiB/8 MiB 均包含末尾一个 LF；超限响应归一化后仍处理下一请求。最大合法 512 条完整 cleanup 诊断可序列化且保留 commit。内部 finalizing 不进入正式事件，终态响应表示完成。
- instance_id 专用 16 KiB UTF-8 限额，其他业务 ID 256 bytes、request_id 128 bytes；保留完整旧 Steam 路径身份，不改变持久目录/schema。真实扫描及 signed 安装/双次 replay 覆盖超过 256 bytes 的实例。
- 新 outcome.error/cause.detail/recovery.detail 限 2048 UTF-8 bytes；截断只产生展示副本，不加省略号，不影响 disposition，历史 Transaction.error/journal/ledger 原文保留。9 MiB 历史字串的两次 committed 重放通过，完整输出小于 64 KiB；exact2048/+1/null 和大历史 Transaction.error 夹具验证。
- Windows 直接使用 Rust protocol，Decky 使用生成 schema/常量；握手先于宿主状态写入，每次校验响应/事件、ID 和全局 sequence。首个有效 terminal 封闭解析；晚到 malformed/oversized 数据、冲突 terminal 或非零 exit 仅为独立诊断。
- 安装中传输错误不 kill writer，发送 cancel/EOF 等待核心安全退出；Windows 有界排空超时继续持有安装互斥。Decky terminal 后前台最多 1 秒/8 MiB、每块 64 KiB，超限返回首结果并后台观察退出，不追加 control/kill。
- UI 权威 DTO 全部引用生成文件；动作、安装结果、进度、URL 和来源状态 helper 共享。新操作按 disposition 呈现，未知合法错误码保留。Error/RuntimeError/ValueError 前缀仅作显示标签规范化，不用于协议权限判断。
- 三个 CI job 检查生成漂移，生产构建明确指定 CLI/worker 两枚 binary。插件只有明确 backend allowlist 和生产 ELF，生成器/开发 oracle 不入包；外层打包校验生成 Python/schema 与仓库源逐字节一致。
