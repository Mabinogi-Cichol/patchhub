# YOZAKURA 内置订阅源

[施工记录](progress.md)

## Lua 适配器

默认启用发行商源 `yozakura`。Lua 读取官网目录对应的 WordPress 文章接口，处理分页并提取作品标题、Steam AppID 和补丁下载链接，再通过现有发行商流程解析命中的文章。只索引公布了补丁链接的作品。文章 150 当前误指向 AppID 4370020，由 Lua 针对这一组合使用 Steam 核实的 4376090。

## 框架兼容与内置注册

- 官网文章以 `/?p=<文章编号>` 区分。Rust URL 归一化兼容这类文章地址，保留用于定位文章的 `p` 参数，继续移除跟踪参数和片段。索引、详情缓存和来源链接使用同一文章身份。
- [内置源配置](../../../crates/core/resources/sources.json) 的 `bundled_scripts` 声明适配器的 Lua 文件列表，`sources` 声明来源规则。构建时嵌入脚本并生成运行时规则。新增内置 Lua 源只需添加脚本并修改这份配置。既有脚本按原顺序拼接，保留原始字节和指纹。
- 官网英文文章标题与两个样例在 Steam 上的英文商品名均有差异。索引条目包含明确 AppID 时，核心据此挑选详情页。Lua 继续从详情提取并核对 AppID，只有和当前游戏对应的详情能产生 AppID 命中。

## 下载项

同一个补丁目标提供几条下载链接，就在现有「下载项」栏逐条列出几项。显示发行商提供的链接标签，由玩家自行选择。语言识别、语言分组和按语言默认选包均不属于本功能。官网样例的三个 ZIP 是同一个补丁目标下的三个独立下载项，每项对应自己的文件及安装选择。

现有候选归并会按文件名拆开三个 ZIP。Lua 在文章事实中设置 `single_download_group`，将这些链接声明为同一补丁目标的可选下载。核心为该目标保留一个候选及每条链接，Windows 和 Decky 复用现有「下载项」和文件选择流程。自动获取 ZIP / EXE 的下载主机为 `www.zakuragames.com`。Google Drive 和 Dropbox 分享链接可在官网文章中打开。
