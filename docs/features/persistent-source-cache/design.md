# 来源缓存持久化与重新查找修复设计

- 状态：P1–P4 已实现并自动化验证/打包；P5 已正式部署并完成真实 RPC / 页面验证，真实游戏安装与手柄待验证。
- 施工记录：[progress.md](progress.md)。
- 相关功能：[来源发现](../shared-source-discovery/design.md)、[Kagura / HGamer](../kagura-hgamer-fallback/design.md)、[共享核心](../rust-core-consolidation/design.md)、[安装器](../cross-platform-installer-migration/design.md)。

## 目标与产品决策

用户不需要来源缓存定时过期。已找到的补丁来源持续保留；经过数小时或数天，不自动变成过期，不因时间禁止安装，也不因到期在打开页面、扫描或安装时强制联网重查来源。用户点击“重新查找补丁”时才主动更新已缓存来源。首次没有查询记录时，沿用既有首次查询入口。

此决定覆盖来源发现成功结果、来源索引与其分页检查点，以及普通来源列表缓存的时间有效期。已查询无结果同样不按时间重查，主动查询或查询上下文变化可重新查找。网络失败/部分完成仍允许用户主动重试，不能永久视为完整无结果。

`checked_at` / `observed_at` 保留为实际记录时间，不伪造刷新时间。不增加“缓存有效期”设置或后台定时更新任务。

本次取消的是来源元数据按年龄失效。解析器/结构版本不兼容、来源停用/退订、身份矛盾、下载失效、游戏条件变化仍按实际问题处理；签名目录撤销/有效期、安装任务租约、计划授权、请求幂等与恢复状态属于其他机制，维持既有语义。不能只把全部 `stale` 统一改为可用。

## 已确认的问题

2026-10-14 Steam Deck 实机取证：

1. 来源候选超过 6 小时被标为 `stale`；ZIP 共享准入与 EXE resolver 将其转为 `selection_stale`，导致安装不可用。
2. 设备实际“重新查找补丁”调用 `session.refresh()` → `readSnapshot()` → `scan(false)`，只读缓存，未调用单游戏 `discover_game`。
3. 来源索引受时间门槛影响不再复用；发行商每轮只有 6 秒/3 个请求子预算。实机有预算耗尽、索引不完整、重试延期诊断，已有详情未优先重验。
4. 真实强制查询取得新的国内本体 v1.03 候选，但同候选原有的已确认 AppID/身份依据消失，退化成 `title / game_appid=null`；HGamer 当前未订阅，不能要求用户重新启用才能保留已核实身份。
5. `local_archive_signed_only` 缺中文解释。它限制动态来源导入本地 ZIP，与自动安装的时间拦截分别判定。
6. 当前选中“夏日狂想曲+”DLC 2.02.1，要求 DLC 1390150。历史该候选下载完成后报 `[worker] exe_project_options_unsupported`，属于独立安装器问题。

原始证据存于忽略目录 `.artifacts/summer-memories-diagnosis-20261014/`。本设计记录事实，不将旧截图或历史失败当作本轮安装验收。

## 技术方案

### 1. 分离记录兼容性与时间调度

修改 [registry.rs](../../../crates/core/src/sources/registry.rs)：将 `discovery_fresh` 中的格式/解析器/查询/编码版本检查与年龄检查拆开。`cached_candidates`、`previous_success_candidates`、`shared_index` 和普通来源读取不再因年龄失效；兼容且已持久化的成功结果按缓存结果读取。

`needs_refresh` 与 `refresh_source` 去除按 TTL 自动重查条件，改用明确触发：没有可复用记录、用户 force、需要重新查询的上下文变化或结构版本不兼容。区分完整无结果与失败/部分尝试，保持原有重试节流但主动重查必须能继续。索引旧分页检查点继续可用，不能仅因旧日期从网站首页重建。

移除 [resolve.rs](../../../crates/core/src/installer/resolve.rs) 和 [exe_resolve.rs](../../../crates/core/src/installer/exe_resolve.rs) 的纯时间 `selection_stale` 准入。不改变 selection 内容绑定、来源允许列表、订阅、游戏身份、语言、DLC、下载与文件计划校验。版本不兼容应返回准确的重新查询原因，不能接受不可解释的旧结构。

核对 [identity.rs](../../../crates/core/src/sources/identity.rs)、[session.rs](../../../crates/core/src/sources/session.rs) 中基于时间状态的 fallback 决策及共享投影。协议中的 `stale` 还有设置修订/代次并发含义，保留这类旧响应拒绝；现有旧缓存按当前兼容性重新解释，无需清空来源数据或提升协议主版本。若必须新增错误码，更新 Rust 协议及生成文件，不手改派生 schema。

### 2. 让主动重新查找真正查询当前游戏

修改 [Decky 页面](../../../apps/decky/src/index.tsx) 和 [前端 session](../../../apps/decky/src/session.ts)：按钮调用单游戏发现 `force=true`，传可信实例、当前名称提示和语言偏好；普通“重新扫描”继续扫描库与缓存。查询中反馈当前游戏状态，并防止连点重复请求；新语言/force 请求不得被不同上下文的旧 pending 请求吞掉。

发现返回的 `patches` 和候选合并到当前代次；继续校验 generation、settings_revision、instance_id 和 appid。跨游戏旧响应、停用来源旧响应不得回写。刷新失败时保留既有结果，并提示“查询未完成，继续显示上次结果”；实际身份冲突或设置失效不能伪装成正常缓存。

核对 Windows 的 `findGame(force)` 与共享投影，保持两端缓存语义一致；不改成扫描时全库强制联网。

### 3. 优先核验已知详情并保留已确认身份

主动查询优先读取已知且符合当前来源域名规则的详情页，再按预算补查索引；不能把详情 URL 当作永久可信的安装授权。force 表示获取新内容，不表示必须丢弃已知入口与分页检查点。

在共享 Rust discovery 提交前恢复同一候选身份保留：同一来源、规范化发布页、版本、语言、variant 和 DLC 条件一致（核对当前 `candidate_id` 的实际构成）且无新冲突时，沿用已确认 AppID、parent_appid、match_basis 与 identity_evidence。不覆盖本轮下载链接、版本或新内容；同候选身份保留不依赖本轮 HGamer 是否启用。新版本/不同候选不能直接继承旧身份。

部分失败不能覆盖最后成功记录；官方结果为空而本轮未可靠覆盖已知详情时，不作为权威删除。明确详情撤下或真实身份矛盾应准确提示并停止该候选安装。

### 4. 文案与本体 / DLC 选择

在 [共享 UI](../../../packages/ui/src/index.ts) 补充 `local_archive_signed_only` 中文：“此来源不支持导入本地 ZIP，请使用来源自动安装。”更新时间过期文案及失败保留缓存的反馈，界面不再要求用户因记录年龄重新查找。

初次进入多候选页面优先本体候选；用户已经主动选择 DLC 时保留其选择。明确展示本体/DLC、语言、版本和要求，不把安装按钮可用等同于满足 DLC 条件；实际安装继续核对条件，不修改用户 DLC 或 Proton 设置。

## 实施拆分与交付顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P1 | 缓存持久化与安装准入解耦 | 旧日期缓存可读取，ZIP/EXE 不因时间拦截；来源停用、真实冲突仍拒绝 |
| P2 | 主动查询与已知详情/身份保留 | 真实单游戏请求、失败保留、同候选身份稳定；代次隔离回归通过 |

每阶段记录实际验证结果。代码与文档按仓库规则分开提交；初始设计阶段仅制定计划，后续实施、部署和提交事实见施工记录。部署依 [decky-deploy-verify](../../../.agents/skills/decky-deploy-verify/SKILL.md) 执行活动任务检查、备份、SHA-256、Loader 正式安装/重载与真实运行验证。

## 验收矩阵

1. 固定相同兼容缓存，把时钟推进 7 小时、7 天、30 天：候选与身份保持一致，安装能力不新增 `selection_stale`；读取/普通扫描不因年龄增加网络请求。
2. 旧索引/普通来源缓存仍可复用；完整无结果不定时重查；首次无记录和主动查询正常联网；结构版本不兼容不会误判可安装。
3. 点击重新查找实际发出当前游戏 `force=true` 请求；连点、语言切换、刷新期间切换游戏、订阅变化、旧响应返回不会吞掉新请求或覆盖当前状态。
4. 断网、预算耗尽、部分刷新、空但未覆盖详情：保留旧候选及身份，显示可理解的查询失败/部分反馈；恢复网络后主动查询可继续。
5. 本轮 HGamer 未启用或失败，同一候选仍保留已确认身份；不同版本、语言、DLC 条件、来源页或明确 AppID 矛盾不能继承旧身份。
6. 来源停用/退订、伪造 selection、失效下载、语言/DLC 不满足、内容变化、需要恢复等仍按实际条件拒绝。时间修改不影响真实条件检查。
7. 夏日实机：首次默认本体，国内 v1.03 保持可匹配，DLC 2.02.1 单独展示；重新查询不再导致身份降级，页面无时间过期和裸错误码。
8. ZIP 与 EXE 各一条已有来源验证共享投影，Windows 检查一致性。实体手柄、真实补丁安装与游戏内生效分别记录，不用合成任务代替。

## 独立后续：Summer DLC 安装器兼容

`exe_project_options_unsupported` 不因取消缓存 TTL 自动消失。按独立修复处理：先用已有下载样本及哈希在隔离目录只读分析，确定实际 project options 和 worker 支持差距，再提出准确提取/路径/条件方案及失败无写入回归。只有解析、计划、取消/回滚和游戏条件验证完成才验收该 DLC 的可安装性。不能删除拒绝分支后直接放行。

本计划 P1–P5 可以独立验收；“该 DLC 完整安装成功”必须等安装器修复与实际安装授权、验收，不将缓存问题修复写成 DLC 已可安装。

## 补充决策：自动匹配失败时仍可手动安装候选（2026-10-14）

用户明确要求：不是所有补丁都提供版本号或 DLC 标记，自动匹配失败不能阻止玩家手动选择安装候选。此要求优先于前文中将未知条件直接视为拒绝的表述。

- 自动推荐与手动选择分别建模。版本为空、variant 未知、AppID 未回填或仅标题匹配时，仍保留可选候选和“手动选择此补丁安装”入口，显示哪些条件未知；不伪造版本、AppID、DLC 或已验证状态。
- 玩家明确将当前候选绑定到当前游戏实例，可确认未知的语言/版本/DLC适用信息后进入既有准备与安装流程；此人工选择需要进入请求绑定、计划与记录，后端独立校验，不仅前端解除按钮禁用。用户确认不等同于自动身份验证。
- 同一候选含多个不同下载项时提供下载项选择，不能仅以无法唯一自动选择为由封死手动路径；每个选择明确绑定候选内容和目标实例。网盘等不能直接获取的来源仍显示实际手动下载要求。
- 未知条件允许手动决策；有明确相反证据时展示冲突，不可把冲突悄悄当未知。安装器内明确且必要的运行条件、目标路径安全、解包支持、文件计划/空间、事务恢复等实际执行检查仍保留。
- variant=unknown 不等同于 demo；不以缺少版本号或 DLC 分类拒绝用户明确选择。已明确为 demo 的候选单独标明，不自动推荐到正式版。
- 新增共享契约：以人工选择方式绑定 trusted instance_id 与候选/下载项的内容标识；不修改来源元数据来伪造匹配。Windows 与 Decky 使用同一后端准入和任务链。协议字段、schema、请求验证、worker策略身份及幂等绑定需一起检查。
- 补充验收：缺版本、缺 DLC 标记、仅标题匹配、无 AppID 的 ZIP/EXE 均能手动选择并生成安装计划；未知条件反馈可理解；多下载项可选；候选内容/目标变化拒绝复用旧确认；安装成功/失败/取消均有记录；伪造选择、目录逃逸和不受支持的安装器仍不能绕过执行检查。

实施将此路径纳入 P2/P3，并扩大 P4 的共享协议/后端回归与 P5 的实机候选选择检查。不得仅取消 TTL 而留下无身份候选无法人工安装的问题。


## 实现选择与当前边界

人工选择复用现有 ZIP/EXE selection 请求格式；共享核心计算独立的人工选择哈希，包含 manual_selection 标记、可信 instance_id、目标 AppID、候选当前规范指纹和具体 mirror URL/format。客户端选择该投影并明确确认，后端解析与 apply 前重解析同一标识，不伪造来源身份，也无需新增安装 RPC。任务、计划与事务以此 selection_id 保留人工选择的目标/内容绑定。PatchMatch 以可选 download_url/download_label 提供所选下载信息，compatibility=manual_selection_required 区分人工适用性确认。

当前受信任直链 ZIP 来源和内置 Kagura EXE 来源支持这条路径。仅网盘/网页入口或不受支持的安装器仍按真实下载/执行能力提示。真实 AppID 矛盾、明确且必要的安装条件不满足、目录安全问题和任务恢复状态不会因为人工选择自动解除。

实施与验证事实见 [施工记录](progress.md)。设备曾因锁屏断连，用户解锁后已正式部署并验证；实机追加的 title 正结果保留修复也已完成，详见施工记录。


实机补充：已有非空来源候选无论自动身份是否确认，都属于持续保留的正结果；名称提示变化不能将其当作无结果缓存重查或删除。只有空结果的查询上下文变化才触发非 force 重查。手动候选因此能跨普通扫描保留。
