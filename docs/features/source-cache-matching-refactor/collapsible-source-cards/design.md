- 分支：沿用父功能分支 `feature/source-cache-matching-refactor`。本项依赖该分支已实现的来源页与协议 v5，作为其子 feature 在父分支内完成，不从尚无父功能的 main 重建实现。合并遵循父 feature 验收结论，本计划不触发合并。

## 1. 问题与目标

用户在已部署的 Decky“全局设置 → 管理订阅源”页面反馈：各来源之间排版边界不明显，并要求每个来源卡片支持折叠。

静态核对 [index.tsx](../../../../apps/decky/src/index.tsx)：`SourcesPage` 将所有发行商源放在一个 `PanelSection`，每个源以 `Fragment` 连续输出；`SourceCard` 本身也是信息行的 `Fragment`，更新间隔和操作按钮位于其外。HGamer 同样使用连续信息行。用户难以区分一个来源的结束与下一个来源的开始。

目标：收起时能快速辨认来源和当前状态；展开时详情与所有来源操作归属清晰；完整支持 Decky 的手柄导航。减少初次进入的纵向信息量，同时保留全部原有功能。

## 2. 范围与边界

包含全局订阅源页的发行商源、补查来源、来源卡片样式、折叠交互、前端会话状态及相应验证。

保留页面的“匹配全部游戏”、来源任务区域、添加源表单、现有来源顺序以及发行商/补查来源分组。单游戏“订阅源管理”页与 Windows 不在此次改动范围。

不新增 RPC、协议字段、后端存储或数据库；不调整来源启停、更新间隔、索引/详情获取、匹配、任务取消及自动调度语义。不新增一键展开/收起、来源搜索、分页、拖动排序、磁盘持久化或通用折叠组件框架。

## 3. 产品与交互契约

### 3.1 卡片边界与标题

每个来源拥有完整的卡片容器，使用细边框、轻微背景差异、适当圆角及卡片间距。背景与边框应在 Steam Deck 深色主题中可辨认；焦点样式比普通边框更突出，不仅依赖颜色区分。

整条卡片标题为一个可聚焦按钮，显示：

- 来源名称，作为主标题；取消详情中重复的“名称”信息行。
- “已启用”或“已停用”的文字状态。
- 展开/收起箭头，方向与当前状态一致。
- 有正在运行的该源更新任务时显示简短进度；没有活动任务时，如最近来源尝试失败，则显示失败短提示。完整说明放在展开内容或现有反馈区域。

来源名称可换行，不使用固定高度裁切。标题主行空间不足时，状态/进度置于下一行；站点 URL 不进入收起标题。标题不放启用开关、取消按钮等嵌套交互控件，避免误触和焦点歧义。

### 3.2 默认与状态保留

- 新插件前端会话初始时所有来源默认收起，包括 HGamer；允许同时展开任意多个来源。
- 展开状态按稳定的 `source.id` 保存，与名称、数组顺序及来源修订无关。
- 在同一前端会话内，离开该页面、进入缓存页或游戏页后返回，保持各来源的展开状态；来源列表刷新和轮询不得重置。
- 插件前端重新加载或 Steam JS 上下文重启后全部恢复收起。仅后端重载而前端会话仍存续时不主动重置。
- 新添加来源默认收起；已不在列表中的 ID 不渲染卡片，不为此新增清理流程。
- 来源启停、任务开始/完成/失败均不自动改变展开状态，不抢夺用户当前焦点。

只保存折叠选择，不承诺恢复离页前的像素滚动位置或全部控件焦点历史。

### 3.3 展开内容

普通来源展开后依次保留站点、索引条目与修订、覆盖完整性、最近成功、最近尝试、自动更新状态、启用开关、更新间隔及手动更新/取消更新操作。信息行和操作均位于同一卡片边框内；启用状态在标题已有说明，删除正文重复的只读“启用状态”行，保留实际启用开关。

HGamer 展开后保留站点、启用开关、最近尝试及“按游戏补查，不参与定时更新”说明。不新增普通源的索引更新或间隔控件，也不把历史补查错误表述成全站更新失败。

长网址与多入口地址在正文内换行，不撑宽卡片。详情内部间距保持紧凑，避免卡片样式额外放大长页面。

### 3.4 任务与错误

- 任务仍由现有来源服务和前端 session 管理，折叠只控制内容显示，不停止、取消或重新创建任务。
- 标题从当前来源数据和任务快照派生摘要；不新增定时器、任务历史、重试或错误恢复状态。
- 收起时仍可看到对应源正在更新或最近尝试失败。要取消更新时，展开该卡片使用原有取消入口；现有全局任务区仍保留。
- 完成后摘要由最新来源快照更新，既有成功缓存及失败提示语义保持不变。失败不自动展开卡片。
- 无对应来源的匹配任务继续由原任务区域展示，不随意附到某个源卡片上。

### 3.5 手柄、键盘与无障碍

- 使用现有 Decky 可聚焦按钮及焦点系统，手柄 A 激活标题切换状态；键盘 Enter/Space 与鼠标点击等价。
- 向下可从标题进入展开后的控件；收起的正文控件不进入导航顺序。卡片内部动作不会触发标题切换。
- 激活标题收起后焦点留在该标题；展开后也留在标题，由用户继续向下进入内容。
- B 沿用现有页面返回行为，不引入优先折叠或新的按键拦截。
- 标题暴露 `aria-expanded`，并用 `aria-controls` 关联稳定、唯一的内容区域 ID；箭头作为装饰不重复朗读。控件与正文实际可访问名称可识别所属来源。
- 初期不引入展开高度动画；避免动画测量和焦点滚动之间的额外耦合。

## 4. 技术方案

### 4.1 渲染结构

在 [index.tsx](../../../../apps/decky/src/index.tsx) 的 `SourcesPage`/`SourceCard` 局部实现卡片容器、标题与正文。`SourceCard` 接受来源、展开状态、切换回调、对应任务以及现有来源操作回调；将当前在卡片外输出的更新间隔、手动更新及取消入口移入正文。通过已有 `source.role` 区分普通源和补查源，不另建平行数据模型。

标题始终挂载，正文根据展开状态渲染，使收起控件从焦点导航中移除。正文只包含展示和操作控件，不承担任务生命周期；`GlobalSources` 的 `session.startSourcePolling()` 维持页面级订阅。

样式限定在该全局来源列表的卡片类名内，复用现有 `Row`、`InfoRow`、Decky 控件和 CSS 注入方式，避免影响 QAM、其他 `PanelSection` 或游戏来源页。

### 4.2 会话状态

在 [session.ts](../../../../apps/decky/src/session.ts) 的现有 `SessionState` 增加按 source ID 保存的展开标记，以及一个同步切换方法。未记录的 ID 即收起，更新时生成新快照并复用现有订阅通知。

`GlobalSources` 读取这一字段并传给页面；不能只用会随路由卸载的局部 `useState` 实现跨页面保留。切换展开状态不调用 `work`、扫描、来源刷新、设置接口或磁盘写入。列表刷新与 `commitSources` 合并数据时保留该 UI 字段。

### 4.3 摘要与既有错误语义

复用 `sourceTaskStatusText`、`sourceTaskTerminal` 与来源状态文案；按当前 `update_source` 任务的来源键对应卡片。标题摘要只组合现有数据，不因展开/收起引入网络查询。已核对现有实现仅在更新成功时重读来源列表，失败时前端快照可能仍保留上次成功状态；因此失败的 update_source 结束后也调用一次已有 list_sources，使最近尝试摘要更新。读取失败与原任务失败同时显示，不新增轮询、历史记录或重试。如果现有短文案过长，使用本页的简短摘要，正文继续显示完整信息，不能任意截断错误详情。

## 7. 风险与处理

- Decky 手柄焦点与 DOM 焦点不完全等价：复用现有 Decky 控件，实施时核对当前依赖提供的焦点接口，以实体手柄验收为准；不预建自定义焦点管理器。
- 折叠造成正文卸载：任务与轮询保持在现有 session/页面层，正文不持有取消清理逻辑；逐条检查实际调用路径。
- 长名称与任务摘要挤占标题：允许自然换行，分主次行展示，不设置任意字符上限。
- 默认收起可能隐藏操作：标题保留明确箭头和状态，所有源使用一致交互；不额外引入首次引导弹窗或偏好设置。

## 8. 过度设计审阅结论

2026-10-19 按仓库 `overengineering-review` 对本计划及现有入口静态自审：未发现需额外增加的机制。独立容器对应用户实际分界反馈；折叠来自明确需求；内存展开记录对应已约定的离页返回保留；标题任务摘要避免任务/失败被折叠隐藏；正文焦点移除属于真实输入边界。

执行路径限定为“标题激活 → 前端展开快照更新 → 本页重新渲染”，与“现有 RPC/任务 → 原 session 快照 → 卡片摘要/正文显示”分离。不增加持久化、后端状态、通用抽象、动画测量、重试或限制。此结论是计划自审，未实现、未运行测试、未验收设备，不代表独立代码审查通过。

## 9. 2026-10-19 实施审阅

C1–C3 实现沿“标题 Button → toggleSourceExpanded → 现有订阅快照 → SourceCard”路径自审。展开选择仅存前端 session，正文条件渲染且无任务生命周期 effect；页面级轮询保持原路径。失败结束的来源列表重读对应实际陈旧摘要问题，且错误继续显式反馈。未增加后端协议、持久化、硬限制、重试或通用折叠框架；移除本页不再使用的 Fragment 导入。

这是实现静态自审与针对性行为测试，不是独立 Agent 审查。实际测试、部署及未验收项以 progress 为准。
