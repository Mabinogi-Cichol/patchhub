## 1. 目标与范围

整体重构来源更新、元数据缓存、游戏匹配及 Windows/Decky 调度和交互。核心目标是按来源更新一次、供所有游戏复用；游戏增量匹配不再触发普通源网站遍历，只按索引命中项获取相关详情。不是全项目重写：保留 Rust 核心、现有来源解析器中有效的解析逻辑、下载器、ZIP/EXE 安装与事务恢复、收据及人工选择能力。

本功能在功能分支内分阶段实施；各阶段的实际修改、测试与证据以 [progress.md](progress.md) 为准。未执行的检查（真实网站、双端实机、游戏内生效）必须明确标为待验证，不以构建通过代替验收。

## 2. 当前问题与证据

- [Decky main.py](../../../apps/decky/main.py)：scan 首次读取报告，刷新列表型来源后、逐游戏查询后分别再次整库投影；_project_row 也通过全库 scan 提取单行。P0 实测一次刷新周期 3 次整库 `bridge.scan()`，单游戏查询另 2 次。
- [来源 session.rs](../../../crates/core/src/sources/session.rs)：逐 AppID 串行 discover_game，普通源发现和 HGamer fallback 混合在单游戏流程中。
- [Kagura 适配器](../../../crates/core/src/sources/adapters/kagura.rs)：已有共享索引，但 force 会按游戏重新加入入口；详情工作队列仍与游戏查询绑定。P0 实测强制扫描时每款游戏重翻全部列表页。
- [HTTP 上下文](../../../crates/core/src/sources/http.rs)：响应缓存按游戏隔离；不同游戏访问同一页面无法共享本轮响应（P0 S4：同批两款游戏同详情页请求 2 次）。
- [Decky session.ts](../../../apps/decky/src/session.ts)：整库与单游戏查询共用扫描快照轮询；后端 start_game_discovery 会关闭原扫描会话。
- [持久缓存旧设计](../persistent-source-cache/design.md)曾决定不增加定时更新。本需求明确替代该产品决策，但保留“不因缓存年龄禁止展示或安装”的原则。旧施工记录保留历史事实。

以上为代码静态核对与 fixture 驱动基线，不是真实网络或耗时测量。P0 证据（2026-10-19）修正了一处原表述：普通首次扫描的普通源索引只构建一次、后续游戏复用持久化索引；“逐游戏重新触发普通源全站遍历”只在 force 刷新路径可复现。普通首扫的线性请求来自每命中游戏的详情获取和每未命中游戏的 HGamer 补查；详情不跨游戏共享。整库重复投影与哈希仍是宿主侧真实成本（Decky 一次周期 3 次整库 scan）。完整数字、口径与代码行号见 [p0-baseline.md](p0-baseline.md)。

## 3. 产品契约

### 3.1 管理订阅源

位置：全局设置 → 管理订阅源。每个普通源提供手动更新、自动更新间隔（可关闭）、最近成功更新时间、最近尝试结果和当前进度。一次手动更新只更新指定源。

初始计划默认关闭自动更新，避免替用户选择流量与后台活动频率；用户设置后持久保存。间隔采用小时/天等清晰单位，不引入无依据的上下限。具体控件预设在 P0 固化。

自动更新仅在宿主运行时执行：Decky 后端运行期间、Windows 应用运行期间。退出或休眠不额外安装系统服务；恢复/启动后检查到期项，每源补一次，不补跑每个错过周期。根据最近尝试结束时间安排下一次自动尝试，成功时间单独展示；失败不形成即时重试循环。手动更新随时可发起，同源已运行时返回现有任务，不叠加重复工作。

到期表示应更新，不表示缓存失效。更新失败或取消继续使用最后成功快照，并准确显示状态。禁用源停止其自动更新，匹配时不使用该源。

### 3.2 HGamer fallback

HGamer 在全局管理中标为“补查来源”，可启停；不提供普通源的全站定时更新。游戏详情中的显示规则与全局管理列表区分，避免隐藏后无法管理。

1. 普通源确认匹配到补丁：显示普通源，不查询、不显示 HGamer。
2. 普通源未命中，HGamer 命中：显示 HGamer。
3. 普通源与 HGamer 都完成查询且未命中：显示无补丁。
4. 普通源尚未初始化、数据覆盖不完整，或补查失败/取消：不能标成确认无补丁。已有正结果继续显示，并说明未完成状态。
5. HGamer 被禁用且普通源无结果：显示“已启用来源中未找到补丁”，不声称 HGamer 已查无结果。

普通源命中以可信游戏身份或已保存的明确人工关联为准；仅相似标题的待确认候选不能自动抑制 HGamer。补丁下载/安装暂不支持不等于未命中，仍显示该普通来源及实际限制。HGamer 提供的上游链接作为该补查结果的证据保留，不通过隐式遍历普通网站绕过来源更新边界；普通源后续更新确认命中时隐藏 HGamer。

### 3.3 游戏增量匹配与重新匹配

首次本地清单发现的游戏全部作为新增；之后比较可信 AppID 与安装实例。新增游戏只匹配自身，索引命中后按需获取详情；已有未变化游戏直接读取持久化匹配结果。相同 AppID 多实例复用来源关联，每个实例保留自己的 DLC/路径/安装状态。名称/语言/订阅等影响匹配的输入变化时，只重算受影响游戏。

所有游戏详情均保留“重新匹配”，包括已命中、无补丁、失败的游戏。重新匹配复用普通源索引，不更新或遍历普通源全站；命中项重新获取相关详情并更新缓存，确认无普通源匹配后主动重新查询 HGamer。首次缺普通源缓存时提示先更新来源，不悄悄把扫描变成全站更新。

移除游戏只移除当前实例及其展示，不删除来源缓存、历史事务或安装收据。扫描清单不递归遍历游戏文件；安装状态核验与来源匹配分开，重匹配不得触发全库文件哈希。

来源成功更新后，用新索引重算该来源对当前库游戏的匹配，对命中项补充/更新相关详情，保留其他来源结果；确认后重新决定 HGamer 显示。已有 HGamer 完整结果可复用，只有尚无结果或用户重新匹配时联网补查。普通源禁用/退订同样重算受影响关联。

## 4. 目标架构与数据

```text
手动更新指定源 / 到期调度
  → Rust 按来源收集游戏/补丁索引
  → 发布该源成功快照
  → 对当前游戏清单重新匹配该源

扫描 Steam 清单
  → 比较新增/变化实例
  → 普通来源本地索引匹配
  → 命中条目按需获取详情并缓存（复用相同 URL）
  → 详情确认后仍无普通源匹配时 HGamer 按游戏补查
  → 保存匹配结果并更新受影响行
```

Rust 是来源缓存、匹配规则和 fallback 判定的唯一业务实现。宿主只负责运行期间的唤醒、任务调用和界面事件转发；不在 Python/TypeScript 复制来源匹配策略。不新建常驻 Rust 服务或通用调度框架。

### 4.1 按源快照

复用现有来源存储，统一成功快照与尝试状态的语义。每源索引快照包括 source_id、内容修订、覆盖完整性、更新时间，以及列表页可直接取得的名称、别名、详情/分类 URL 和实际存在的 AppID 等字段；不为补齐列表缺失字段遍历所有详情。详情缓存按来源和规范 URL 共享，保留 AppID/身份依据、版本、语言、本体/DLC 关系、下载项、格式和人工选择所需信息。缓存归来源所有，游戏记录只关联条目，避免不同游戏重复保存/请求同一详情。

- patch.moe：列表数据按源一次获取与解析。
- Kagura：来源更新只遍历列表/目录分页，保存可取得的游戏或补丁条目及分类/详情链接，不获取全站详情。游戏先在本地索引筛选候选，再由游戏匹配任务获取相关详情和必要的该游戏分类分页、DLC 链接。不得从游戏任务回到全站入口重建索引；无命中时进入 HGamer，索引不完整时明确提示。现有适配器已解析列表标题和链接，但列表是否提供 AppID、是否完整包含本体/DLC，需 P0 以真实页面核实，不能假设站点提供完整结构化 API。
- HGamer：保留按游戏的搜索结果缓存，不建立全站镜像。正结果和已完成空结果均可复用。

单次来源更新中按规范 URL 去重，复用已抓取页面；同批游戏的详情请求也按来源和规范 URL 合并。普通扫描复用已缓存详情；手动重匹配刷新命中详情，来源更新后刷新当前库命中项详情，不更新未安装游戏的详情。复用现有分页/继续机制；对其硬限制逐项核查依据，不能以任意页数或耗时截断并声称更新完成。后续更新可利用网站可靠的变更标记/条件请求；无可靠依据时重新读取，不能臆测详情永不变化。

只有完整成功结果替换正式快照；部分失败/取消保存工作进度与错误，不能据此删除旧补丁。首次未完整更新时不得把局部空集合当成无补丁依据。完整成功的新快照可反映已撤下条目，不能永远累加旧记录。

### 4.2 游戏匹配记录

持久化游戏身份、相关匹配输入、所用普通源修订、普通源结果、HGamer 结果/查询状态。来源数据修订与订阅设置修订分开：只有实际影响输入变化时重匹配，不因查看页面或更新时间变化重算。

结果至少明确：待匹配、普通源命中、HGamer 命中、完整无结果、未完成/失败。它们是可解释的业务结果，不另建复杂通用状态机。候选、人工选择与安装动作继续由现有共享投影生成；索引命中不直接等于确认有补丁，详情失败显示未完成并保留既有成功结果；已确认普通源命中才隐藏 HGamer。增加按实例/批次投影入口，避免调用整库 scan 取得单行。

### 4.3 调度与结果归属

来源索引更新、游戏匹配中的详情获取使用独立任务身份，不再共用一个可互相关闭的扫描会话。用户重新匹配一个游戏不能取消其他来源的更新。相同源的重复更新合并；网络执行和短暂快照提交分离，不持有存储写锁等待联网。

结果提交绑定实际来源修订、订阅状态和游戏实例，避免已停用源或已移除游戏被旧异步响应重新加入。复用已有取消及任务事件能力，不新增自动无限重试。安装任务继续使用现有内容绑定；来源更新不能改写已经开始的安装输入或跳过原有重解析检查。

### 4.4 接口边界（名称在 P1 固化）

- 读取/刷新本地游戏清单：返回新增、变化、移除及已有结果，不联网更新普通源索引；新增游戏的匹配任务可获取命中项详情。
- 更新指定来源：source_id，返回任务身份与来源进度。
- 设置来源更新间隔：source_id + 间隔或关闭。
- 匹配指定游戏集合：支持增量批次及单游戏主动重匹配。
- 读取结果/任务状态：返回来源状态与受影响游戏行；优先复用现有事件传输，不要求新增 WebSocket。

共享 Rust 协议为源头，同步 CLI、生成 schema/TS/Python、Decky 桥接及 Windows Tauri。破坏性变更按仓库协议规则升级，不长期保留旧新两套业务流程。详情获取是匹配任务中的明确阶段，界面区分索引匹配与详情获取，不能把整条任务宣称为纯离线。

## 5. 缓存迁移与删除范围

可兼容的现有来源目录、详情、正结果、空结果和身份依据迁入新表示；旧的按游戏缓存不能冒充完整全源快照，必须保留覆盖范围。保留订阅、人工选择、下载缓存、收据和事务。不可兼容的来源数据明确提示需要更新，不清空整个状态目录。

转换应在正式覆盖前完成验证，通过原子写入发布。迁移失败保留原数据并报告，不回落到静默空结果；只保留本次版本升级所需迁移入口，不长期维护双写。

双端切换后删除：逐游戏触发普通源全站遍历、全库 force 向每游戏广播、来源事件调用全库 scan 的回填、共用扫描会话造成的相互取消、旧来源刷新按钮/RPC/状态与仅服务旧流程的测试。保留有业务意义的缓存、取消、DLC、身份和安装契约测试，改接新入口。

阶段可在功能分支内渐进实现，但对用户交付是一次完整切换；不发布半套来源/匹配接口。计划阶段不提交代码，不部署设备。

## 7. 验收矩阵

1. 普通来源初始化一次后，1/10/多游戏共享同一快照；新增游戏不新增普通源索引请求，只请求命中项缺失详情；已有详情直接复用。使用固定响应服务器断言请求轨迹，不能只测函数返回。
2. 两款游戏引用同一个来源详情时，同批该 URL 只请求一次；游戏数增加不放大来源索引更新遍历次数。
3. 游戏库新增一款，只匹配新项；重启后仍保留已有匹配；相同 AppID 多实例不重复 HGamer 查询，实例状态独立。
4. 普通源命中、仅 HGamer 命中、全部完整未命中、源未初始化、部分更新、网络失败、HGamer 禁用分别得到正确显示；普通源后来命中会隐藏旧 HGamer。
5. 手动重匹配已命中/无补丁游戏都可执行；不更新普通源索引，可刷新命中详情，确认未命中可重新查 HGamer；其他来源任务不被取消。
6. 指定源索引更新仅访问该源列表/目录；随后关联游戏的详情补充作为明确后续阶段，普通源确无匹配时可补查 HGamer；自动关闭/到期/修改间隔/重启/休眠恢复/更新失败/同源重复点击行为正确，无补跑风暴或立即失败重试循环。
7. 更新失败/取消保留最后成功缓存；完整更新反映撤下条目；缓存年龄不阻止匹配、人工选择或安装。迁移覆盖旧本体+DLC、镜像、已确认身份和空结果。
8. 更新期间停用源、删除游戏或改订阅，旧结果不会回写；来源更新与安装并行时无状态锁冲突，安装输入保持绑定。
9. 匹配更新不触发整库 scan/全库哈希；记录冷启动、暖缓存、新游戏、单游戏重匹配、来源更新的请求数/扫描数/耗时，不预设未经测量的秒数门槛。
10. Windows 与 Decky 的真实设置、进度、取消、离线展示、重启及手柄入口验证；普通源 ZIP/EXE、本体/DLC、人工候选与镜像选择走既有安装链的回归。仅构建或 RPC 通过不等于实机 UI 或游戏内生效通过。

## 8. 精简设计审阅与待验证项

计划自审采用仓库 overengineering-review 技能。需要保留的机制均有当前触发条件：来源分页耗时需要进度和取消；失败更新不能抹掉已找到结果；定时和手动可能同时触发需同源合并；停用/移除发生于网络请求期间需阻止旧结果回写。

不引入通用爬虫平台、额外数据库、系统级后台服务、无限重试、默认全站并发框架或缓存年龄安装禁令。先改变工作单位和数据流，再依据 P0/P2 实测决定是否需要并发。

待验证：Kagura 列表索引覆盖与首次更新成本、站点是否提供可靠变更信号、命中项详情及游戏分类能否保留完整身份和 DLC 关系、旧数据迁移的实际样本、安装与来源写入的现有锁边界。P0/P2 必须提供证据并修订设计，不以这些未知项为由预加硬限制或悄悄恢复逐游戏普通源全站遍历。P6 已核验 Kagura 列表结构、条件请求（304）与 EN 双入口；真实全量更新的页数/耗时/流量与身份/DLC 全量覆盖仍未测。

## 9. 2026-10-19 方案修订：索引与详情分层

用户明确要求来源先只保存游戏清单，匹配命中后由该游戏任务获取详情。采纳此要求，取消原稿的全源详情预取与整条匹配纯离线目标。职责边界调整为：来源更新拥有共享索引，游戏匹配拥有候选筛选和按需详情获取，详情结果仍写入按源共享缓存。联网范围限定到命中游戏相关页面；首次更新成本不再包含全站详情。

## 10. 2026-10-19 P5/P6 实现收口与偏差

### 10.1 实际实现落点（与 §4/§6 对应）

- **按源更新**：`sources::update::update_source`（`crates/core/src/sources/update.rs`）无游戏参数；完整成功才写 `index/<source>.json`，部分/取消/失败写 `index-progress/<source>.json`；patch.moe/table 复用列表收集，Kagura 只读列表/目录分页（`IndexOutcome`/`collect_index`），不抓详情。
- **按需详情**：`sources::matching` 在本地索引筛选命中项后才发现详情；`resolve_page` 产出 query 无关的 `PageFact` 并按来源+规范 URL 写入 `details/`，跨游戏/跨轮次复用；详情失败保留既有正结果并报未完成。
- **匹配与六态**：`GameMatchRecord` 持久化到 `matches/<appid>.json`；`input_key` 只包含名称/本地化名/提示/语言/订阅快照；六态由 `match::derive_game_status` 推导；HGamer 的 `disabled/not_queried/not_needed` 语义按 §3.2 落实现。
- **协议 v5 与宿主**：`PROTOCOL_VERSION=5`、20 方法、4 类事件；Decky 与 Windows 均改为“按源/按匹配键”的任务注册表（同键去重、可取消），scan 只做一次只读整库投影，不再触发来源刷新或逐游戏发现；自动更新由宿主运行期间的 60s 到期检查驱动（`next_due_at` 由核心派生）。
- **迁移**：schema 1 → 2 一次性迁移 settings/cache/discovery-index/discovery/status；迁移诊断经 `registry.diagnostics()` 进入投影诊断；失败保留旧文件并报 `source_migration_failed`。
- **矩阵 8 提交绑定**：P6 新增最小绑定（见 [p6-acceptance.md](p6-acceptance.md) §1）：更新在发布索引前重读持久化 settings，源已停用则只保存 progress 并返回 `source_not_enabled`；匹配在写 `matches/` 前比较 settings 修订与重算的 `input_key`，变化则丢弃本次尝试并保留上次记录。

### 10.2 与冻结契约的实现偏差（保留原契约，差异记录于 p1-contract §13）

1. `failed` 在实时匹配中不可达：普通源详情失败 + HGamer 失败显示 `incomplete`（带诊断），`failed` 只由迁移记录产生；需要产品决定修订契约或后续单列修复。
2. `SourceStatus` 落盘不含 `revision/complete`；两者由 `SourceIndex` 得出并经 `SourceSummary`/`update_source` 结果暴露。
3. `DetailRecord` 存 `PageFact` 而非候选列表；候选在匹配时按游戏生成（§9 分层决策）。
4. Kagura 海外多入口：原实现只读 `pages.first()`；修复后 `collect_index` 无 progress 时从 `rule.url` + `rule.pages` 全部入口起爬（canonical 去重），每个入口各自分页；fixture `kagura_en_crawls_every_configured_entry_root` 通过。真实全量更新与两入口合并后的最终条目数仍未跑。
5. 矩阵 8 绑定新增 `source_not_enabled` 错误码（UI 已有文案，非协议字段）。
6. HGamer 真实站点：原 DOM 契约（h1 父节点摘要）与当前站点（`<p>「term」找到 N 筆結果</p>` 在 h1 兄弟 section）不符；修复后 `result_summary` 先扫描含查询词且可解析计数的 `<p>`，再回退整页文本，不解析 RSC。`hgamer_live` 真实网络测试通过（3/5 逻辑请求、complete、identities=1、空 diagnostics）。
