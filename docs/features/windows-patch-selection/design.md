# Windows 补丁选择状态修复

施工记录：[progress.md](progress.md)。

## 问题与目标

同一来源候选由发现条目变为可安装条目时，展示 key 从 candidate_id 变为 candidate:source_id:candidate_id。界面据此错误判断原补丁消失，重置选择并提示用户。

## 方案与范围

为 DisplayEntry 提供统一的 selectionKey，发现候选使用与可安装分组一致的来源 ID 与候选 ID。Windows 游戏选择、补丁选择器和页面状态使用 selectionKey；展示 key 和共享 TypeScript 展示夹具契约保持原样。无候选 ID 的可安装条目继续使用现有 key。

不增加重试、超时或状态恢复分支。真实候选移除时仍按既有流程提示并选择第一项；来源或候选不同的条目不得被视为同一补丁。

## 实施与验收

1. 统一选择身份并连接所有选择入口。
2. 回归验证同一候选双向切换时保留选择、不误报；真实移除仍提醒。
3. 执行 Flutter 针对性测试与静态分析，记录结果。真实用户数据与运行中的安装版验证另行记录，不以自动化代替实机结果。

## 2026-10-26 补充：候选项统一安装交互

用户要求移除标题中的“手动选择 / 文件名”拼接后缀，推荐仅影响默认选择；选择其他合法候选或下载项不再触发额外勾选确认。

- 共享 Rust 投影始终使用来源 patch_title，下载项和镜像继续在各自选择器展示，不将 URL 编码文件名混入补丁名称。
- Windows 和 Decky 删除候选专用确认状态、复选框、按钮门禁和专属安装按钮文案，使用相同安装入口。可安装状态与摘要只依据真实 actions，不因 manual_selection_required 改成等待确认。
- 保留来源语言、DLC、版本等客观信息，保留来源/游戏/下载绑定、真实 blocker、运行任务互斥和本地文件输入要求。manual_selection_required 仍作为底层精确下载选择的协议值，不据此新增交互步骤。
- 沿用当前排序与镜像去重，不更改推荐策略或安装协议。回归覆盖非推荐候选可直接启动正确的 selection_id，以及真实 blocker 与本地文件要求仍生效。

本补充复用本功能目录及 feature/windows-patch-selection 分支。双端自动化与后端投影验证后记录结果；真实设备部署与游戏安装待验证。
