# Feature：EXE 补丁静态提取与安装

状态：P1–P4 工程实现与自动化已推进；2026-10-05 在真实 Deck 上用当前源码复跑 Linux Rust、后端与隔离合成事务闭环，实机复核 P4 界面修复，并对 VenusBlood FRONTIER（AppID 1189440）、夏日官方本体补丁 CN v1.03（2,502 文件）与夏日官方 DLC 补丁 CN v2.02.1（5,874 文件）完成审核 profile 与真实安装/恢复闭环。夏日英文本体、中文/英文本体与 DLC 的语言/版本组合及实体手柄仍待其它实例；生产审核表含这三条经审核条目。日期：2026-10-05（Asia/Shanghai）。目标客户端：Steam Deck / Decky。

施工记录：[progress.md](progress.md)。调研证据：[research.md](research.md)。P0 工具与设备条件：[p0-audit.md](p0-audit.md)。完成门槛核对：[acceptance.md](acceptance.md)。

## 1. 目标与调研结论

让用户在 Decky 中安装经过审核的 Kagura Games EXE 补丁，继续使用已有的准备、变更预览、确认、备份、安装和恢复流程，不要求用户进入桌面模式操作 Windows 安装器。

本轮对官方《夏日狂想曲》中文本体 v1.03、英文本体 v3 做了静态实验：两者均识别为 **Setup Factory 9.5**，游戏载荷分别为 2,502 / 2,892 个文件，目标为 `%AppFolder%\www\...`。安装器另含运行时、Lua DLL、安装元数据及界面资源；其中安装事件还检查 `Game.exe` 与 `Script.vdf`。证据和实验局限见[调研记录](research.md)。

因此首期路线是 **识别 Setup Factory → 受限静态提取 → 审核目标映射和适用条件 → 生成规范化 ZIP 与配方 → 复用 Rust 安装事务**。不能把 EXE 改名成 ZIP，不能把解包成功视为 SteamOS 兼容性证明，也不能将本体两份样本外推至所有 Kagura 游戏、DLC 或更新版本。

## 2. 范围和产品决策

### 首期范围

- 接入既有 [Kagura 双站发现功能](../kagura-hgamer-fallback/design.md)，仅处理官方详情页提供、受限域名可直接取得的完整单文件 EXE。
- 首批提取适配器支持经过样本核验的 Setup Factory 9.5 + LZMA2；SF7/8、其他 SF9 小版本列为扩展，不能仅因上游工具宣称支持就默认开放。
- 首批验收使用中文本体 v1.03 与英文本体 v3；只有完成身份、语言、游戏版本、DLC 条件和实机验证的组合才开放正式自动安装。国内本体官方要求未安装/未购买对应 DLC、排除 GOG，必须保留这些约束。2026-10-05 增加首个不同引擎的真实组合：VenusBlood FRONTIER International（AppID 1189440，KiriKiri，仅新增游戏根目录文件），其官方中文补丁 v5 已按同一门槛审核并在设备完成真实安装/恢复；它不替代也不放松夏日样本的约束。同日晚些时候增加夏日官方 DLC 补丁 CN v2.02.1（variant=dlc，requires_dlc=[1390150]），在已装 DLC 的真实实例上完成 5,874 个文件的安装与全量恢复；随后在临时移除 DLC 的本体实例上完成本体 CN v1.03（2,502 文件）的安装与全量恢复。本体补丁要求无 DLC 的 `Script.vdf` CRC 3876755782，DLC 补丁要求 CRC 2002373744，二者不混用；英文本体 v3 待英文本体实例。
- 游戏目录来自可信 Steam 实例扫描。将已审核的 `%AppFolder%` 映射到该实例根，支持内置盘和外置 Steam 库，不猜测 Windows 盘符路径。
- 官网及候选继续实时采集。安装审核配置是受版本管理的能力规则与验证记录，不替代实时来源成为固定游戏发现清单；未知游戏仍能发现和查看来源。
- 首批 EXE 安装必须保留原文件备份，使真实恢复验收可完成。现有默认关闭 `keep_backups` 的设置不能在此流程中悄悄清除备份：准备界面应明确提示并让用户启用/确认；未满足则不生成可执行计划。通用 ZIP 的既有设置策略不在本期调整范围。

### 不支持的情况

执行 EXE、Wine/Proton 安装、静默安装参数、Lua/安装脚本解释执行、注册表写入、服务/驱动、运行时下载、二进制差分更新、多卷、加密包、未核验安装器版本和 HGamer 的任意文件直装均不属于首期。

Inno Setup、NSIS、7z SFX 保留适配器扩展位置，按独立样本决定是否实施，不为本期预先打包所有工具。未知格式或需要安装器动作的补丁继续提供来源引导，给出具体原因。

### 用户流程

1. 选中游戏，显示官方来源、语言、补丁版本及本体/DLC 条件。完成审核的组合提供“准备安装”；其余保留“查看官方安装说明”。
2. 准备任务显示下载、检查安装包、提取补丁、核对游戏、生成安装计划几个阶段，支持取消。
3. 下载前或准备前展示官方适用范围、使用条款及安装说明；需要同意的条款在确认前取得用户同意，不因跳过安装器界面而跳过条件。
4. 预览显示补丁来源和版本、替换/新增文件数量、空间需求、备份要求和冲突。技术细节放在诊断中，普通用户不必选择解压器或了解规范化 ZIP。
5. 用户确认关闭游戏、暂停更新并确认安装；由 Rust 核心执行事务。将 `committed`、`rolled_back`、`needs_recovery` 分别显示，不能只看 RPC 调用是否成功。
6. 安装成功后可安全清理下载与转换缓存，保留本次备份。用户可查看实际事务、卸载或恢复；当前文件被游戏/Steam 改动时保留冲突，不盲目恢复旧文件。

## 4. 信任模型与能力升级

### 4.1 发现记录不直接授予安装权

新增服务从后端缓存/重新抓取结果读取候选及镜像，前端仅提交可信实例和选择标识，不能提交任意 URL、路径、提取参数或配方。准备前重新检查来源启用、逐游戏订阅、候选身份与条件，过期或变更的记录重新验证。

后端管理的 `publisher_exe` 安装能力与已审核安装 profile 关联，生成独立 `release_id`；旧 `candidate-*` 仍不能用于 preview/plan/fetch/prepare/apply。关联候选由官方来源、来源记录、AppID、语言、variant、原始补丁版本及载荷摘要决定，禁止使用标题或 EXE URL 后缀单独匹配。具体契约已在 P1 固化，但正式 profile 尚未开放。

推荐能力状态：来源引导 → 可检查安装包 → 已通过审核的可安装 release。检查任务成功可以生成诊断报告，但未经审核不得自动升级。来源停用、订阅取消、身份条件变化、载荷变更均使关联失效；apply 前重新核验这些条件。

### 4.2 安装 profile

当前契约由后端 `exe_profiles.py`、`exe_installation.py` 与 UI 类型固化：release 为 `exe-<profile规范JSON摘要前24位>-<appid>`；registry 独立于实时来源。准备 RPC 的第四参数只接受 `terms_accepted`、`conditions_accepted`、`keep_backups` 布尔确认；前端不能提交 profile、URL、配方或 worker 路径。计划策略持久化在 `jobs/<核心UUID>/exe-policy.json`，记录 EXE、ZIP、来源、profile、游戏条件、确认、租约和强制备份，恢复不依赖在线 profile。生产 registry 尚无正式条目。

受审核的 profile 至少声明：官方来源/记录、AppID、语言、补丁版本、本体/DLC 条件、支持的平台和已验证 build 范围、EXE SHA-256、格式与版本、允许的压缩方式、安装元数据摘要、目标变量映射、载荷文件清单/摘要、必需的原游戏文件条件及审核版本。

首期将已审核载荷摘要锁定。官网同 URL 更新或任一镜像字节不同都进入“补丁已变化，待重新核验”，不会沿用旧 profile。SHA-256 只绑定字节，不是发行商签名；新下载的摘要须经审核记录确认，不能把“刚计算出的摘要”当作来源真实性和平台兼容性证明。

安装器中 `Game.exe`、`Script.vdf` 校验必须转写为声明式前置条件，并保留来源证据。中文样本存在 `Script.vdf` CRC 条件，但 CRC 仅复现发行商的条件，不能代替 SHA-256 基线验证。确认当前 Steam 游戏是否仍满足条件，若不满足，首期阻止并说明版本不匹配；不得为了能安装删掉检查或自动把当前 build 标为已验证。

完整审核必须覆盖文件条件、事件、删除/转换/运行/下载动作及替换策略。字符串搜索只能提供线索，不能证明全部脚本语义。未知变量、未知事件序列、条件分支无法可靠映射时维持引导状态。

## 5. 技术方案

### 5.1 受限下载与缓存

沿用 HTTPS、CA 校验、每跳域名检查、流式大小限制、超时、取消、临时文件及原子发布；官方下载域名与规则来自受审来源配置，HGamer 不能扩大下载白名单。跳转到登录、网盘页面或 HTML 错误页时退出直装流程，不将页面保存为有效 EXE。

EXE 缓存使用独立类型和元数据，不混入旧 ZIP 缓存。校验 PE 结构、实际大小、SHA-256、完整 overlay 和安装器版本；扩展名/Content-Type 仅辅助。镜像只能在同一 profile 下通过相同摘要验证后切换，不拼接不同镜像字节。首期不引入文件断点续传。

### 5.2 Setup Factory 受限提取器

格式参考基线为 [CybercentreCanada/sfextract](https://github.com/CybercentreCanada/sfextract)，MIT，面向 Linux，声明支持 SF7/8/9。本轮研究固定源码 commit `21f5c5595a70e9284fff83476c0e307d5b92f573`。不能原样接入线上：上游读取整个 overlay、按包内路径写文件、忽略部分解码错误，且缺少解压资源上限；它的 `ParseScript` 不校验所有普通载荷的 CRC/实际长度。P0 已选择仓库维护的专用 SF9.5 parser，只用 Python 标准库，保留格式参考来源的 MIT 许可；当前仅实现只读审计，不是生产提取接口。

P0 已选择专用 parser 并保留参考源码版本与许可；P2 已实现固定 sandbox 生产 worker，独立审查与合成测试通过。审计、清单与提取分开：**写前**先解析和验证完整目录、条件与目标路径，不能先写到临时目录再检查逃逸。当前直接把经核验的清单成员流式写入确定性 ZIP，不创建以原始包路径命名的中间文件；包内 Windows 路径只解析为声明式目标。

- 严格解码，不接受丢字节后形成的新路径；同时检查 Windows 与 POSIX 路径、盘符、UNC、ADS、设备名、`..`、NUL、绝对路径、大小写/Unicode 冲突、文件与目录冲突。
- `%AppFolder%` 仅在审核规则允许的目标位置移除；其他 `%...%` 变量不展开为真实系统路径。不可做全局替换或通用“剥离首层目录”。
- 校验所有记录偏移、压缩区间、整数/计数、重复文件、分卷和尾部完整性。解码流必须结束，实际长度等于声明长度，CRC 校验加 SHA-256；CRC 不提供来源信任。
- 安装引擎、Lua DLL、`irsetup.dat`、界面资源作为诊断材料隔离，禁止进入规范化游戏载荷。游戏本身的 JS/DLL/EXE 不能一概按后缀删除，只允许 profile 声明的游戏文件。
- 独立受限 worker，固定参数启动、不使用 shell，不加载包内 DLL、不执行提取文件，禁止网络与对游戏/state 的写入。Linux sandbox/资源限制及取消时杀死完整子进程组为 P2 必须验证的能力；隔离不成立时不启用自动提取。

首期资源预算（2026-10-05 按真实 VenusBlood FRONTIER 与夏日 DLC 补丁在 Deck 实测调整）：EXE ≤2 GiB，单文件展开 ≤1 GiB，总展开 ≤2 GiB，manifest ≤16 MiB，游戏文件及规范化 ZIP 条目 ≤8,192，LZMA 字典 ≤128 MiB，worker 地址空间 ≤3 GiB，静态提取 ≤180 秒。条目上限从 4,096 上调到 8,192，以容纳官方夏日 DLC 补丁的 5,874 个成员；预算不得超过核心既有上限（归档 8 GiB、单文件 4 GiB、总展开 16 GiB），也不得在失败后自动无限重试或提高限额。必须在解压前和流式解压时限流，不依赖提取后统计或磁盘剩余空间兜底。

### 5.3 规范化 ZIP 与 Rust 事务复用

首期采用转换桥接，避免新建第二套游戏落盘器：

1. 经过 profile 校验的游戏成员使用安全相对路径写入规范化 ZIP，路径分隔符统一为 `/`。优先 `ZIP_STORED`，避免二次压缩开销；原 EXE 的解压限额仍独立执行，不能通过转换掩盖解压炸弹。
2. 每个源成员、目标成员、长度和 SHA-256 一一对应，未审核成员不能被顺带加入。对照当前可信游戏实例读取原文件基线并生成完整声明式新增/替换配方。
3. 使用现有发行商路径的本地签名目录机制，将规范化 ZIP 大小/摘要、配方与 AppID/已验证 build 交给 CoreBridge。规范化 artifact 的摘要和原 EXE 摘要分开记录；本地签名不能冒充发行商签名。
4. profile/安装元数据中持久记录官方页面、镜像最终 URL、EXE 摘要、转换 ZIP 摘要、提取器/profile 版本、脚本审核结论、游戏实例/build 和条件。Rust 的 release 标识要与该证据稳定关联，重启后仍能预览、apply 和恢复。
5. Rust 再检查 ZIP 路径/大小/摘要、实例、基线、空间及配方，生成 plan；TTL 从准备完成后开始。apply 前重新验证关联审核信息，不能只信前端携带的旧结果。

未来需要省去转换缓存时可另评估 Rust 直接消费安全 staging 的接口；这会增加核心信任边界，首期不采用。规范化 ZIP 是内部桥接实现，用户看到的来源仍为官方 EXE。

### 5.4 任务、空间和清理

复用安装 TaskManager 的互斥、租约、心跳和取消。下载、提取、转换、签名与 plan 均属于准备任务；取消/超时不得改写游戏载荷/存档或留下可 apply 的半成品。沿用 Rust 核心的目录协作锁：首次 plan 可以创建空 `.steam-patch-manager.lock`，须在目录审计中单独记录，不把这个既有核心行为隐藏为绝对零文件创建。

空间预估分别覆盖 state 中 EXE、隔离提取目录、规范化 ZIP、Rust staging、备份，以及目标库同目录临时文件；state 和目标库位于不同磁盘时分别检查。总展开字节不是磁盘需求总和。worker 输出不能被前端作为路径输入重新导入。

每个任务使用受控 job 目录，标注原 EXE、提取材料、转换 ZIP、plan staging 和备份的生命周期。有效计划及正在运行任务持有租约；取消仅清理自己已确认归属的文件。提交后按现有缓存策略清理可重建材料，首批 EXE 保留备份。失败、部分写入、未知目录和恢复冲突沿用核心恢复规则。

备份保留策略必须绑定计划并持久化，不能仅检查准备时的全局 `keep_backups`：当前 `_cleanup_after_install` 按提交时的全局设置删除 `.backup`，因此本功能必须为 EXE 计划接入独立、可恢复的保留策略，并覆盖用户准备后切换设置、进程重启及手动清理。source/profile 停用应阻止新的安装，却不能阻止读取已安装事务及使用本地已校验备份安全卸载/恢复；恢复不依赖官网在线或重新下载 EXE。

## 6. 依赖与交付

- Decky 冻结 Python 的依赖不完整；继续使用固定 `/usr/bin/python3 -I` worker。P0 专用 parser 已通过 PE resource table 自读 manifest，不需要 `pefile`；生产实现经 P2 审核后随插件离线分发固定版本代码，不运行用户设备上的 pip，不修改 SteamOS 根文件系统。
- 上游 metadata 声明 Python ≥3.8，但当前源码使用 `match/case`，实际至少需要 3.10；必须明确项目运行时最低版本，并核验系统 Python 的 `lzma`、所需压缩后端、内存限制和 sandbox 能力。
- 本轮实验通过自读 PE offset/manifest 复用 SF8/9 parser，不等于完整 `sfextract + pefile` 依赖组合已验证。正式依赖与打包产物的 `-I` 导入、离线提取和错误传播均须 Linux CI 和 Steam Deck 验证。
- 保留 MIT 及所有依赖版权/许可，检查转用的 `blast.py` 等文件许可；固定依赖摘要，生成依赖清单并纳入 Linux 打包检查。首期未用的 7-Zip/innoextract 不加入包。
- 不把官方 EXE、游戏载荷或整份安装器资源加入 Git/插件包。自动化使用自制/获授权的最小安装器样本，官方大样本仅作为外部验收输入和摘要记录。

## 7. 实施拆分与顺序

| 阶段 | 工作与主要落点 | 完成门槛 |
| --- | --- | --- |
| P0 可行性补足与审核 profile | 完整解析安装事件/文件条件；核对 `Script.vdf`、语言、本体/DLC、当前 build；验证完整依赖组合及 Deck 资源；决定提取器维护方式 | 两个样本有可审计的清单和语义结论；不满足的样本保持引导；确认预算与 sandbox 可用 |
| P1 能力与契约 | 新增 EXE profile/报告数据模型、release 关联、backend/UI 模式；保留 candidate 安装拒绝；补关联生命周期 | 未审核、伪造、取消订阅、过期、载荷变更和任意 URL/路径均不能升级安装能力 |
| P2 安全提取基础设施 | 共享下载器、格式探测、写前 manifest 验证、受限 worker、流式解码/哈希、规范化 ZIP、独立缓存 | 路径/资源/截断/CRC/大小不匹配/取消负面测试通过，游戏目录零写入 |
| P3 接入事务安装 | EXE prepare 服务、profile 条件复核、本地签名配方、CoreBridge、证据与备份策略持久化、ID 分发/state 发现、空间及缓存枚举 | prepare→preview→apply→uninstall/recover 在合成库闭环通过；Rust 仍是唯一落盘器 |
| P4 Decky 交互与打包 | 来源/能力状态、准备阶段、协议确认、备份要求、失败回退、取消与重入、依赖许可/CI | 打包产物离线提取通过；小屏幕中文和手柄可操作；旧 ZIP/来源引导回归通过 |
| P5 实机受控验收与开放 | Steam Deck 真实目标版本及语言；完整下载、安装、生效、退出、重启和恢复；不满足条件的拒绝 | 对具体已验证组合开放 profile；自动化和实机证据更新 progress；其他样本维持待验证 |

工程依赖：P1 契约→P2/P3→P4；没有正式开放的 profile 时，使用自制样本和合成 Steam 库推进工程与失败守卫。P0 的完整语义、身份与条件审核是具体官方 profile 开放的门槛，P5 是正式安装开放的实机门槛；两者未完成不应阻止其他工程实现，也不得用合成验证代替官方审核/验收。P0 和 P5 中不适用的样本继续保持引导。每个实现阶段必须更新本功能施工记录。提交按仓库规则拆分文档与代码，同一提交只包含本功能的一项完整变化及必要测试；不包含现有 Kagura 发现功能的未提交修改。

## 8. 验收标准

### 自动化

- SF9.5 合成正样本正确区分运行时和游戏载荷、解析目标变量、还原字节；中文文件名严格解码；实际长度、CRC 和 SHA-256 一致。
- 未支持的 SF10、NSIS/Inno/7z SFX、假 MZ、HTML、未知压缩、分卷、加密、脚本分支和非 `%AppFolder%` 目标有明确拒绝原因，不回退执行 EXE。
- 路径逃逸、盘符/UNC/ADS、链接、大小写/Unicode 重复、文件目录冲突、异常偏移/计数、压缩炸弹、坏 CRC、截断和尾部异常均在可控时间/内存内失败，隔离目录外零写入。
- 候选、镜像、订阅、游戏实例、语言/DLC/build、profile/摘要变化及任意前端伪造输入不能绕过准备/apply 守卫。含许可证/条件未确认时不能 apply。
- 原 EXE→提取清单→规范化 ZIP→配方→plan 的摘要链可验证；取消、租约到期、QAM 关闭重开、worker 崩溃、磁盘不足均不改写游戏载荷/存档，不保留可执行半计划；核心协作锁单独记录。
- 合成 Steam 库覆盖新增/替换、基线冲突、权限保留、崩溃恢复、备份损坏、Steam build 改变和用户修改后的恢复拒绝；EXE 计划准备后修改全局备份设置、重启和清理仍保留本次所需备份；来源离线/停用时仍能安全恢复。保留旧 ZIP、缓存清理与发现 RPC 回归。
- Linux 插件实际打包产物在系统 Python `-I` 中离线运行，通过依赖、许可和资源限制检查。范围涉及 Python/Rust/TypeScript 时运行相应必要测试与构建。P0 已执行只读 Python 工具检查，不等于插件打包或安装功能通过，实际状态以施工记录为准。

### Steam Deck

- 分别记录中文/英文对应已安装语言、build、DLC 状态、`Game.exe`/`Script.vdf` 条件和 profile 摘要。没有对应语言/条件的已安装样本，标为待验证，不将另一语言测试算作通过。
- 准备前后对游戏目录做摘要审计，证明游戏载荷/存档的内容及路径未改变；单独报告首次核心 plan 创建的空协作锁。原 EXE 未执行。内置盘、外置库、离线/满盘及取消有实际证据。
- 安装后核对所有声明文件及版本；进入游戏确认补丁生效，再验证退出与存档基本行为。不能仅凭 `committed` 或启动成功宣称生效。
- 使用保留备份完成卸载/恢复，恢复到原文件摘要，新增文件移除、存档与无关文件保持；用户后续修改应报告冲突而保留内容。
- QAM 中文显示、长版本/路径、进度/取消、确认/恢复和实体手柄完成验收；安装后游戏模式仍可运行。

## 9. 待决策项与停止条件

P0 已确定专用 parser 维护方式并验证该设备系统 Python/bubblewrap 的基础隔离、取消和资源预算。当前语言、build、已安装 DLC 由 Steam manifest 取得，关键文件摘要/CRC 只读核验；当前 DLC 实例不符合本期本体样本条件，不能标为已验证 build。详细证据见 [p0-audit.md](p0-audit.md)。P0 尚需确定：完整安装脚本和未知文件字段的可审核表示、适用本体实例的 `Script.vdf`/SHA-256 基线、未安装 DLC 权益证据。profile 已采用随版本分发、严格摘要锁定且独立于来源的 registry，新条目更新需重新审核及对应验收。P2/P3 已完成合成验证，不能把只读探针或合成库视作具体官方 profile 的真实游戏验收。

若目标样本只能执行安装器才能完成、需要未审核条件/差分操作，或无法实现写前路径校验和受限解压，则该样本停止进入自动安装阶段，保留具体诊断与官方引导。可以完成其他经验证 profile 的流程；不得为了覆盖数量放宽这些门槛。
