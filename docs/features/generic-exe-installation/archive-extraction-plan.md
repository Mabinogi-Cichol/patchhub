# EXE / ZIP 安装精简：单一纯解压流程

日期：2026-11-07（Asia/Shanghai，同日最终职责修订）。状态：**方案已修订，待实现；本轮只改文档，未改代码、构建或部署。**

关联：[功能设计](design.md) · [施工记录](progress.md) · [一站式安装](../simplified-install-flow/design.md)。

## 1. 当前决策与职责

用户根据完整样本的新事实确认：此前纯解压 fallback 所具备的文件提取能力已经满足需求，不再需要 Lua 执行环节。将该能力直接作为唯一主流程，删除“Lua 主链 + fallback”的双路径设计。

工具负责下载 EXE / ZIP、定位用户选定目录、还原包内文件结构并解压覆盖。它不重现发行商安装器的执行结果，不需要证明脚本选择与纯提取等价才允许解压。不同包的原安装器可能存在额外行为，这是产品职责的区别，不以假想的组件冲突为由重新增加解释器、预审或分流。

- EXE 与 ZIP 均走：下载 → 读取成员 → 映射相对路径 → 流式解压覆盖 → 返回实际结果。
- 不执行原生 EXE/DLL 或安装器 Lua；删除现有 Lua AST、符号求值、完整对象图覆盖及行为授权对提取的依赖，不换成真实 Lua 运行时。
- 不按组件默认值、Steam/GOG、DLC、文件条件、build、语言或游戏 CRC 筛选载荷、拒绝提取。包内全部文件载荷按容器顺序输出，同路径普通文件按该顺序覆盖。
- 保留目标目录定位与路径映射：使用已选 Steam 实例目录，确有需求的明确注册表位置可由工具直接定位；无法定位时由用户选目录，不运行包内定位脚本。尚未具备的入口列入实施，不写成已支持。
- 不再判断“需不需要脚本选择”，不设直接解压/独立解包自动分流，不增加组件选择框架、宽松模式、逐游戏例外或未知 API 兜底。
- 仅实际下载、文件读取/解压及落盘错误失败；用户取消单独报告。记录、报告、缓存旁车或清理失败附带提示，不能阻断提取或将已写入成功改判失败。
- 完成提示准确为“文件已解压到目标目录”，不据此宣称原安装器完全等价或游戏内已生效。

## 3. 必需的提取能力

### 3.1 目录和成员读取

目标根由用户已选实例或手动目录确定；`%AppFolder%` 映射该根，`www/` 等结构保持。作者机器的 `C:\Dropbox...` 源路径不是输出路径。目录已确定后不再执行原定位函数，也不为保留 `isSteam` 副作用运行脚本。

SF 独立读取成员目录/文件名、顺序、载荷偏移、压缩大小/算法和实际校验信息。定位记录边界时仍须消费真实结构；对源路径、文案、条件、组件名等无消费者字段按 framing 跳过，不解码、不生成完整对象图，不读取脚本后判断是否允许提取。安装引擎、向导图片等容器运行资源按格式位置与游戏文件载荷分离，不按 EXE/DLL 等扩展名过滤正常游戏文件。

不能直接把 `analyze_behavior` 换成旧 `analyze`：后者仍调用 inventory 并输出审计报告。以独立成员读取/提取契约替代旧报告；同包 host/worker 一并更新，不维持新旧授权协议兼容链。成员仅携带实际提取需要的字段，格式内部的压缩区间留在读取器内，不新增通用插件框架或 EXE 转 ZIP 中间包。

ZIP 按包内相对结构提取；已有明确 source→destination 映射有消费者时复用。删除基于现场游戏内容猜测 XP3/YPF 布局并拒绝额外文件的规则，不建立“识别失败再 fallback”。非必要 extra 标签、未知附带文案和未消费对象不影响实际可读成员。

### 3.2 文件名和写入

- 文件名必须正确还原。ZIP 按声明编码/有效 Unicode 信息处理；SF 区分 ANSI 与 UTF-16 字符串，按实际格式和字节确定编码策略，覆盖 CP936/GBK 中文及既有 UTF-8/UTF-16。当前样本不证明所有 SF ANSI 字段都是 GBK。不得使用 replacement / ignore 制造错误文件名。
- 成员路径只解释为选定根下的相对路径；不沿用“目标变量不在白名单”之类业务准入。包内能恢复逻辑相对路径就提取，确实无法定位成员才报告真实路径读取失败。
- 同路径普通文件顺序覆盖，不查旧收据、原版摘要、游戏文件是否被修改或组件资格。大小写与 Unicode 遵循目标文件系统实际行为，不用统一小写/规范化碰撞规则拒绝本机合法路径。
- 实际路径边界防止 `..`、绝对路径或链接逃逸至用户未选目录。目标类型冲突、文件系统无法表示的名称、权限/空间/校验错误如实失败；不能跳过失败成员后宣称全部成功。
- 保持单遍流式解压、进度与取消。同目录真实并发写入串行；不新增备份、回滚、TTL、租约或必须先恢复旧状态才能重试的流程。
- 删除无必要的空间预估、预留量及人工包大小/文件数/报告长度/分析预算；实际 I/O、格式字段宽度和算术溢出仍如实处理。目录查询或辅助记录失败不构成解压许可。

### 3.3 结果与旧状态

实际文件全部正确输出即提取成功；压缩流或写入中途失败/取消如实说明可能部分覆盖，重试重新提取，不切换第二条路径。没有可独立提取文件、缺少密码/分卷或读取器尚不支持该压缩/容器，说明实际无法提取，不宣称支持任意 EXE。

请求 ID 只防同一操作重复执行，内容摘要只标识输入与历史，不绑定游戏条件或审核报告。日志、历史、缓存旁车和清理保存失败只附带提示，不能停止剩余成员或把完成结果改为失败；不能吞掉提示。旧安装记录继续只读展示，重装使用新流程，不依赖旧行为报告/收据豁免。不为旧恢复/卸载凭空生成备份。

Windows / Decky 都走共享 Rust 主链；移除分析安装器、审核、游戏适用条件、组件选择未知及 fallback 的进度和按钮 blocker。来源说明仍可展示，完成提示只承诺解压结果，不新增确认或手工组件选择步骤。

## 6. 过度设计自审

按项目 `overengineering-review` 复核：纯解压已是明确需求，原安装器 Lua 执行、宿主 API、跨事件状态、组件判定与 fallback 分流均没有必要保留。本次删除这些方案，不再建设一个执行器来决定何时可以调用已有提取器。

完整样本只证实其自身载荷与脚本关系。此前将 Steam/GOG 状态变化直接推导为不同载荷是证据不足的推断，已修正；不再把它当作增加运行时的依据。对其他包也不先证明“无需选择”才提取，工具承诺的是静态提取，不是原安装器效果等价。

保留实际格式解析、正确路径、输入数据校验、目录写入和取消所需处理，删除超出此职责的限制。复用既有 worker 与解压器；当前 worker 为普通子进程，不能冒称已有 OS 沙箱，本方案也不以引入脚本执行为由扩张权限框架。

本节是方案自审，不代表独立审查、实现测试或游戏内验收。本次只改文档，待实现。
