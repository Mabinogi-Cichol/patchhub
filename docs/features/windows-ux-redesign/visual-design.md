# Windows Modern 视觉重设计方案

状态：2026-10-24 参考图对齐修订已实现，悬浮底栏、右侧补丁状态及整行技术详情已验证，用户已授权合并并发布 v0.3.0，正式发行包核验通过；具体证据与未验证边界见 [progress.md](progress.md)。既有交互及 Flutter 技术方案见 [design.md](design.md)。

## 1. 设计方向与范围

以用户本轮参考图为视觉依据：**深色游戏库、艺术作品横幅、清晰的信息卡、稳定的底部操作栏**。目标是让界面更接近经过设计的桌面游戏工具，而不是默认 Material 表单。

保留现有「概览 / 补丁管理 / 操作记录 / 游戏订阅」和全局来源、安装进度及结果流程。参考图表达视觉方向，不作为字段真实性或安装能力的依据。首轮仅设计，随后用户明确要求开始施工；实现限于 Windows 客户端与必要的原生图片位置读取，不执行部署或真实游戏安装。

与既有方案的关系：

- [原设计](design.md)继续约束业务交互、安装动作、取消和恢复语义；本方案细化并替代其视觉呈现约定。
- [Windows 视觉完善](../windows-visual-polish/design.md)的品牌图标、下载速度与关窗修复保留；其中黑白灰按钮和灰阶选中背景改为本方案的克制蓝色强调。此为本次参考图驱动且已获施工授权的修订，不追改历史施工事实。
- 保留跟随系统、浅色、深色三种外观选项。本轮以深色稿定义主视觉，浅色采用同一结构与对应色板，不改变当前默认跟随系统行为。

## 2. 对参考图的取舍

| 部位 | 采用方式 | 调整原因 |
| --- | --- | --- |
| 左侧游戏库 | 封面缩略图、两行名称、状态、整行选中态 | 提升识别速度，保留快速切换游戏 |
| 详情横幅 | Steam Hero 艺术作品，文字侧遮罩，底部淡出 | 建立视觉重心，确保标题可读 |
| 四栏目 | 横排图标与文字，蓝色低饱和选中块 | 保留已确认的信息架构 |
| 补丁信息 | 竖版封面＋条件与下载选择；宽窗增加摘要栏 | 适配现有默认窗口，避免照搬大图后拥挤 |
| 底部操作 | 提示、次按钮、唯一主按钮 | 明确下一步，避免滚动寻找安装入口 |
| 玻璃与发光 | 使用实色表面、细边框和局部渐变 | 保持层次，减少满屏描边、高光和模糊 |
| 重复游戏标题 | 横幅显示游戏名；卡片显示真实补丁名 | 游戏名与补丁名不一定相同，不重复堆叠相同信息 |
| 游戏信息表 | 使用现有真实字段 | 不将来源名冒充开发商，不推断游戏类型 |

## 3. 页面结构与尺寸

尺寸均为 Flutter 逻辑像素，分界点用于布局换行，不限制业务数据。保持默认窗口 1180×760、最小 850×560。参考图较宽，三列信息卡在默认及宽窗口出现；文字放大或窄窗口时将状态摘要移到主体下方，始终保留。

```text
┌───────────────────────────────────────────────────────────────┐
│ 品牌图标  Steam 黄油补丁助手              全局来源  外观  窗口控制 │
├───────────────┬───────────────────────────────────────────────┤
│ 搜索名称/AppID │                          Steam Hero 艺术作品    │
│ 有补丁     12 │ 游戏完整名称    [找到补丁来源]                    │
│ 已安装补丁  8 │ 所选补丁的来源 · 语言 · 格式                     │
│ 全部游戏   36 │ 概览   [补丁管理]   操作记录   游戏订阅            │
│ 需处理      1 ├───────────────────────────────────────────────┤
│               │ 补丁信息                                      │
│ ▣ 游戏 A      │ ┌─────┐ 补丁名称           宽窗：当前补丁摘要    │
│   找到补丁来源 │ │竖封面│ 来源网页 ↗          检测状态 / 适用性    │
│ ▣ 游戏 B      │ │     │ 适用条件            AppID / build      │
│   已安装补丁   │ └─────┘ 下载项 / 镜像                           │
│ …             │ 必要警告 / 手动确认 / 本地 ZIP                  │
│               │ ▸ 文件与技术详情                              │
│ 重新扫描游戏库 ├───────────────────────────────────────────────┤
│               │ 安装前关闭游戏并暂停更新   打开游戏目录  安装补丁 │
└───────────────┴───────────────────────────────────────────────┘
```

- **标题区**：应用工具区约 48px 高；沿用既有品牌 PNG。实施时检查现有原生标题栏，只保留一套应用名称和窗口控制；如合并工具区与标题栏，复用 window_manager 并验证拖动、双击最大化、系统菜单、关闭生命周期，不另画不接系统行为的装饰按钮。
- **侧栏**：1180px 窗口下约 272px，1440px 及以上可用 296px；最小窗口为 228px。内边距 16px，搜索框高 40px。筛选为四个紧凑导航行，保留现有「需处理」，计数来自当前搜索范围内各筛选的真实结果；筛选不是互斥分组，计数不必相加等于全部。
- **游戏列表**：行高约 72px，52×52px 缩略图，圆角 8px；名称最多两行，状态单独一行，完整名称在详情显示。多实例继续显示库位置，允许行高增长。选中行采用浅蓝底＋左侧 3px 标记，悬停只提高表面亮度。列表单独滚动，底部扫描入口常驻。
- **详情横幅**：实现采用宽内容区 158px、紧凑区 112px，将空间留给补丁内容。图像铺右侧，左侧为阅读区；上方标题、下方四栏目，横幅底部融入内容背景。名称允许换行，长标题与元信息可在横幅阅读区滚动完整查看，栏目独立保留。
- **主体**：左右留白默认 24px，小窗 16px；卡片间距 16px。补丁信息用一张主卡，技术详情为卡内折叠行，避免每个字段各套一层卡片。
- **底部操作栏**：在补丁管理页独立于内容滚动，以悬浮卡片呈现；左右随主体留白 16/24px，底部留白 20px，16px 圆角、整圈细边框与轻阴影，可随文字换行增高，不覆盖正文。概览、记录、订阅及来源页不显示无关安装按钮。

### 响应式布局

| 可用窗口宽度 | 信息卡 | 横幅与操作栏 |
| --- | --- | --- |
| ≥1360px | 竖封面约 144×216px＋主体＋约 240px 摘要栏 | 横幅可加高，提示与按钮同排 |
| 1050–1359px | 竖封面＋主体＋补丁状态/游戏信息右栏；可用内容宽度不足或文字放大时摘要移到主体下方 | 默认布局，操作栏允许提示单独一行 |
| 850–1049px | 隐去重复竖封面，信息单列；保留补丁状态摘要并移到主体下方，详情可垂直滚动 | 横幅约 112px 起，栏目可横向滚动；提示和按钮上下排列 |

高度较低或 150% 文本缩放时优先收紧横幅装饰空间，不压缩正文到不可读；底栏按内容测量，技术信息和条件可完整滚动查看。尺寸为初始设计值，最终以真实 Flutter 排版验收调整，不硬锁卡片高度。

## 4. 视觉规范

| 角色 | 深色 | 浅色 |
| --- | --- | --- |
| 应用底色 | `#0C1118` | `#F3F5F8` |
| 侧栏 / 内容表面 | `#111923` | `#FFFFFF` |
| 抬升表面 / 输入框 | `#182230` | `#EAF0F6` |
| 分隔 / 边框 | `#293647` | `#D5DEE9` |
| 主文字 | `#F3F6FA` | `#172333` |
| 次文字 | `#A9B7C9` | `#526176` |
| 主按钮 | `#346BE0`，白字 | `#245DD8`，白字 |
| 链接 / 焦点 | `#78A9FF` | `#245DD8` |
| 成功 / 警告 / 错误 | 绿 / 琥珀 / 红，搭配图标与文字 | 使用同语义的深色值 |

- 基础字体沿用 Windows 可用系统字体与中文回退；游戏标题 28–32px、补丁标题 22–24px、区块标题 18px、正文 14–15px、辅助文字 12–13px。正文行高约 1.5；名称、路径和错误可选择复制。
- 采用 4/8px 间距节奏；主卡圆角 16px、按钮和输入框 10px、徽标胶囊形。主要按钮高约 44px，普通图标操作有至少 36px 的点击区域。
- 主按钮以蓝色实底为基准，可增加极轻的同色渐变；不使用参考图中强烈的蓝紫辉光。选中栏目与主按钮形成主次，不同时成为两个高亮焦点。
- 图标使用 Flutter 现有 Material 图标，统一线性风格及 18–20px 尺寸；不混用表情符号。沿用项目品牌，不生成新 Logo。
- 悬停、按下、栏目切换可用约 120–160ms 的轻量颜色过渡；加载使用现有进度，不增加视差、全屏模糊或背景动画。
- 最终实现检查普通文字对比度至少 4.5:1，状态不单靠颜色，键盘焦点可见；参考色板不是对比度实测通过的证据。

## 5. 补丁管理内容与状态

信息依次回答「选的是哪个补丁、适用条件是什么、当前检测如何、从哪里获取、能否安装」。

1. **补丁身份**：真实补丁名、具体来源、补丁语言、格式和来源网页。多个补丁才显示选择器；游戏封面不能暗示存在单独的补丁官方封面。
2. **条件与检测**：适用条件、当前检测状态、适用性分行展示。`状态未知` 使用中性样式；「安装时检查条件」与已确认兼容区别显示。未确认 DLC 条件必须直接可读。
3. **下载选择**：单项为只读文件摘要，多项才出现镜像下拉；长文件名可换行，完整 URL 在详情。手动核对、本地 ZIP 主路线和阻断原因紧邻相关控件，不因折叠美化而隐藏。
4. **宽窗摘要栏**：展示 AppID / build 等已有游戏字段；检测与适用性统一放在主内容中，不重复堆叠，不添加第二个安装入口。参考图的「游戏类型」「开发商」目前不在 GameInstall 契约内，不为视觉补齐而扩展抓取或显示猜测。
5. **技术详情**：沿用文件变更预览、标识、匹配依据和完整地址。折叠只影响展示，不触发业务请求。
6. **底栏**：左侧提示，中间次操作「打开游戏目录」，右侧唯一主操作。目录操作已在 DesktopServices 实现，使用所选实例的 install_path 打开资源管理器；目录不存在或系统打开失败时显示错误反馈，不影响已有补丁状态。

| 实际情况 | 呈现及主操作 |
| --- | --- |
| 找到补丁来源，但未确认可安装 | 蓝色来源提示；不能仅凭匹配结果显示绿色「可安装」 |
| 核心允许安装 | 主按钮「安装补丁」；摘要可显示「可安装」，与检测是否已安装分别表达 |
| 已安装 | 检测区域绿色文字＋图标；主操作严格跟随核心覆盖安装契约 |
| 条件待人工确认 | 琥珀提示＋既有确认控件，确认前保持既有禁用条件 |
| 要求本地 ZIP | 直接显示文件选择，底栏给出需要选择文件的说明 |
| 不可安装 / 来源线索 | 可读原因和来源入口；不伪造可用安装按钮 |
| 下载 / 安装中 | 复用前台模态进度，显示已有真实速度、进度和取消；完成后结果内容替换进度 |
| 无图片 / 图片读取失败 | 保留布局，用中性封面占位与文字；不阻塞游戏选择、匹配和安装 |

所有主操作可用性、取消、部分写入、恢复范围与结果仍以现有契约为准。信息图像化不能将未知状态写成成功，也不增加安装确认步骤。

## 6. Steam 艺术作品使用方案

### 产品决定

优先使用用户本机 Steam 已设置的自定义艺术作品，其次使用本机 Steam 已有游戏库图片；二者均无可用图时显示中性占位。首轮无需登录、API Key、SteamGridDB 账号或全量联网下载。

使用分工：Hero 用于详情横幅，竖版 Capsule 用于补丁卡封面。左侧优先用户自定义 Header / Capsule，再用默认 Capsule / Header；真实截图核对后优先默认竖封面，避免将宽图过度裁切导致模糊。保留图像比例，不拉伸；缩略图裁切、竖封面等比展示、横幅使用遮罩。无 Hero 时使用中性横幅，避免将竖图拉伸成背景。游戏名仍由文字呈现，第一轮无需解析或摆放艺术作品中的 Logo。

依据：Steam 官方说明支持用户自定义游戏库 Header 与 Logo；Steamworks 文档区分 Library Capsule、Hero 与 Header。这些资料支持资源类型与视觉用途，不承诺本地缓存文件名或跨版本目录结构：

- [Steam 游戏库官方说明](https://store.steampowered.com/libraryupdate?l=english)
- [Steamworks 图形资源概览](https://partner.steamgames.com/doc/store/assets?l=english)

### 核验与实际接入

- 已核验本机 `appcache/librarycache/<AppID>/` 的直接文件和哈希子目录，支持中文 `library_600x900_schinese` / `library_hero_schinese` / Header 及无语言后缀资源，排除 Hero blur 变体。自定义图读取 `userdata/<账号>/config/grid` 中的 `<AppID>p`、`<AppID>_hero` 与 `<AppID>`；本机没有可用自定义图样本，该部分以隔离夹具验证，不记为真实用户自定义图验收。
- 账号优先沿用 Steam 当前账号；未运行时核对最近使用账号的现有配置。不能明确归属时仅读取默认库图，不任意混用另一账号的自定义资源；第一轮不增加账号管理页面。
- 图片按 AppID 复用，游戏操作仍按 instance_id 区分；多库安装不能因共用图片而合并操作对象。Steam 安装根目录与游戏库根目录必须区分，不能从 library_path 猜出 userdata 位置。
- Flutter 原模型没有图片路径，启动配置也未提供 Steam 安装根。实际通过现有 Windows runner 的轻量 MethodChannel 仅读取 HKCU 的 SteamPath / ActiveUser，停止运行时从 loginusers.vdf 的唯一 MostRecent 记录解析账号；不改 Rust 或安装任务协议。图片信息由 Windows 展示层独立持有，失败不伪造成库扫描失败。
- 仅对已构建列表项（包括 Flutter 的邻近预构建项）和当前游戏异步解析、解码，复用 Flutter 自带图像缓存及按显示尺寸解码能力。显式扫描后更新图片缓存键的代次，使同路径被替换的图片也能重新读取；切换游戏等待新图时不保留旧游戏图片。此次不新增持久缓存、定时预下载、文件监听服务、手动上传或艺术作品编辑器。
- 本地图片缺失或无法解码时使用占位，保留可检查的图片诊断；这是一项展示资源错误，不把它升级为阻止安装的业务错误。不增加图片大小/数量硬限制、任意超时或自动重试循环。
- 游戏图按本机现有资源读取，不把用户艺术作品及游戏美术打进发行包。

## 7. 其他页面统一

- **概览**：同一 Hero 与栏目区；补丁卡展示简洁名称、来源、条件摘要和「查看并安装」。无匹配时保留重新匹配与订阅入口。
- **操作记录**：平面记录列表，结果文字与语义图标同排，时间为次文字；异常恢复提示放在关联记录旁，不增加大幅装饰或全局常驻恢复按钮。
- **游戏订阅 / 全局来源**：统一表面、标题和间距，保留来源可折叠卡片及运行/失败摘要；全局来源保持明确的返回游戏入口，不套用某个游戏的 Hero。
- **进度与结果**：统一卡片和按钮色，维持现有模态焦点及真实终态；结果以清晰文字为重，不增加成功庆祝动画。
- **空状态和扫描失败**：用简短标题、具体原因与现有可用操作呈现；扫描时保留旧列表，图片加载不制造全屏等待。

## 8. 实施拆分与验收

用户已授权施工。在现有功能分支保留并兼容先前未提交的下载速度、图标及关窗修复；本轮不自行提交、合并或发布，不把既有修改归入本次新增范围。

| 阶段 | 工作落点 | 验收结果要求 |
| --- | --- | --- |
| V1 视觉基础与框架 | app.dart、library_page.dart；复用现有主题切换及窗口宿主 | 深浅色、标题区、封面列表、筛选、四栏目在默认和最小窗口可读 |
| V2 艺术作品 | Windows 宿主与展示模型的最小图片解析；真实 Steam 样本 | 当前账号自定义优先、默认图、缺图、坏图、多库与切换无错配；不阻塞扫描及安装 |
| V3 补丁内容与底栏 | patch_management_page.dart、desktop_services.dart | 多补丁/镜像、手动确认、本地 ZIP、阻断、覆盖安装均保持原动作；目录打开错误可解释 |
