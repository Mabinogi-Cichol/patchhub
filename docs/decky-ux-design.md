# Decky 游戏补丁管理 UX 方案

- 更新日期：2026-10-04
- 状态：用户已于 2026-10-03 授权施工；实现、验证和部署进度见文末。2026-10-04 续作已完成实机路由与顶部布局修复并部署验证。
- 参考：用户提供的 Decky Clash 设置页截图，采用 Steam 原生左侧导航、右侧内容区、顶部状态栏和底部手柄提示。
- 本次修订：下载和安装使用原生模态进度面板及全屏黑色遮罩，展示真实进度、下载速度和文件大小；关闭进度面板即取消任务，安装取消需安全恢复已修改文件。

## 1. 页面结构

```text
Decky 快捷侧栏
├─ 搜索、筛选、游戏列表
│  └─ 点击具体游戏 → 全屏游戏管理
│     ├─ 概览（默认）
│     ├─ 补丁管理
│     ├─ 操作记录
│     └─ 管理订阅源（全局）
├─ 管理订阅源 → 直接进入全屏订阅源页
└─ 重新扫描
```

侧栏承担选游戏的任务；全屏页承担查看来源、准备安装、确认变更、卸载和异常处理的任务。

## 2. 一级：Decky 快捷侧栏

```text
Steam 补丁管理
┌──────────────────────────┐
│ 搜索游戏名称或编号…        │
│ 筛选：有补丁            ▾ │
├──────────────────────────┤
│ [图标] 游戏 A             │
│        可安装 · 2 个补丁   │
│ [图标] 很长的游戏名称…     │
│        已安装补丁          │
│ [图标] 游戏 C             │
│        需要处理            │
├──────────────────────────┤
│ 管理订阅源              › │
│ 重新扫描                  │
└──────────────────────────┘
```

### 游戏行和长名称

- 每行固定高度：左侧图标，右侧一行名称和一行简短状态。名称不换行，不推动其他游戏行。
- 名称未溢出时静止；溢出且未聚焦时显示省略号。
- 手柄聚焦、鼠标悬停或触屏选中该行后，停留约 0.8 秒开始水平滚动，显示完整名称；末尾停顿后回到起点循环。
- 离开焦点后停止滚动并恢复起始位置。一次仅滚动当前交互行，避免整个列表同时运动。
- 滚动区域裁剪在文字栏内，不覆盖图标或状态。视觉滚动不改变可访问名称，也不产生重复朗读。
- 触屏点击仍直接进入详情，不需要等待文字滚完。详情页提供完整游戏名称。
- 全屏左侧导航中的当前游戏名称同样保持单行；右侧页面标题可完整展示长名称。

### 列表交互

- 筛选项：全部、有补丁、已安装补丁、需要处理。搜索匹配游戏名称或编号。
- 搜索和筛选只处理已有扫描结果，不触发扫描；切换筛选保留搜索内容。
- 点击游戏进入该游戏的全屏概览。
- 游戏列表占主要空间；底部提供订阅源和重新扫描操作。
- 首次加载显示扫描状态；再次扫描时保留旧列表，标明正在更新并禁用重复扫描。
- 没有筛选结果时提供清除筛选操作；确实没有已安装游戏时提示检查游戏库或 SD 卡。

## 3. 二级：全屏框架

```text
                       Steam 顶部状态栏
┌─────────────────┬────────────────────────────────────┐
│ Steam 补丁管理   │ 当前游戏名称                       │
│                 │                                    │
│ 当前游戏名称    │ 当前栏目的标题与内容                │
│ ▌概览           │                                    │
│  补丁管理       │                                    │
│  操作记录       │                                    │
│                 │                                    │
│ ─────────────── │                                    │
│  管理订阅源     │                                    │
└─────────────────┴────────────────────────────────────┘
                        A 选择    B 返回
```

- 使用 Steam / Decky 原生侧栏导航和控件，外观、焦点高亮及手柄操作与参考图一致。
- 以 Steam Deck 的 1280×800 屏幕为基准，左侧约占四分之一，右侧承担主要内容；不覆盖系统顶部和底部区域。
- 左侧栏目保持可见，右侧独立滚动；切换栏目时记住各自的滚动位置。
- 从游戏进入时默认选中概览；切换栏目始终保留当前游戏上下文。
- 从一级侧栏直接进入订阅源时，只展示全局订阅源导航，不显示没有对应游戏的栏目。

## 4. 概览：状态和匹配源

```text
游戏 A
概览
┌──────────────────────────────────────────────────────┐
│ 补丁状态                          可安装 · 2 个补丁   │
│ 匹配来源                          源甲、源乙         │
└──────────────────────────────────────────────────────┘

匹配到的补丁
┌──────────────────────────────────────────────────────┐
│ 补丁一                                               │
│ 匹配源：源甲 · 当前查询                               │
│ [查看补丁]                           [打开来源网页 ↗]│
├──────────────────────────────────────────────────────┤
│ 补丁二                                               │
│ 匹配源：源乙 · 缓存结果 · 更新时间                    │
│ [查看补丁]                           [打开来源网页 ↗]│
└──────────────────────────────────────────────────────┘

游戏信息
游戏编号 / 游戏版本 / 安装位置
```

- 概览直接回答“找到什么补丁、来自哪个匹配源、数据是否为缓存”。不能只展示链接或笼统的“已匹配”。
- 每个补丁显示对应的匹配源名称；匹配源指实际提供该条结果的订阅源，不把下载站名称当成匹配源。
- 多个源时逐项对应，不只给出一个无法辨认归属的来源总数。
- 区分匹配源与来源网页：前者说明结果从哪里匹配，后者供用户查看补丁原始说明。
- “查看补丁”跳到补丁管理，并选中对应补丁；“打开来源网页”使用外部浏览器。
- 缓存结果展示缓存时间；查询失败但仍使用缓存时明确提示。
- 没有匹配结果时显示“暂无匹配补丁”，提供管理订阅源入口；不暗示此游戏一定没有补丁或不需要补丁。
- 若现有数据无法确定某条补丁的匹配源，显示“匹配源未知”，不根据下载域名猜测。实施时需核实来源字段能否随扫描结果传到界面。

## 5. 补丁管理：具体布局

仍使用同一套左侧原生导航，选中“补丁管理”；右侧采用从上到下的操作顺序，不再增加一层侧栏。

### 5.1 默认页：选择补丁与查看详情

```text
游戏 A / 补丁管理

选择补丁                 [补丁一                    ▾]
匹配源                   源甲 · 当前查询

补丁详情
┌──────────────────────────────────────────────────────┐
│ 当前状态                                  未安装     │
│ 兼容性                                    检查结果   │
│ 安装方式                                  官方 ZIP   │
│ 补丁说明、限制或阻止安装的具体原因                    │
│ [打开来源网页 ↗]                                     │
└──────────────────────────────────────────────────────┘

安装准备
┌──────────────────────────────────────────────────────┐
│ 获取方式说明                                         │
│ [自动下载并准备安装]                                 │
│ 手动指定本地 ZIP（高级，仅支持时展示）              ▸ │
└──────────────────────────────────────────────────────┘
```

- 只有一个补丁时显示名称，不显示无意义的下拉框；多个补丁时使用原生下拉选择。
- 从概览指定补丁进入时直接选中该补丁。切换补丁时清除旧预览、安装计划及确认状态。
- 状态、匹配源和主要操作优先出现在首屏；较长说明放在下方，右侧可以滚动。
- 有安装阻碍时在主操作附近显示原因，并禁用安装准备操作。
- 不支持自动下载时，主操作改为“查找本地 ZIP 并准备安装”，同时保留来源网页入口。
- 点击准备后进入独立全屏进度页，显示查找本地文件、下载、校验等当前阶段，防止重复点击。具体布局和退出行为见 5.4。

### 5.2 准备完成：检查计划与确认安装

准备成功后，从全屏进度页返回补丁管理，在右侧用“安装计划”替换准备操作区域，并将焦点移到计划摘要，避免结果出现在视口外。成功后的自动跳转不属于用户退出取消。

```text
安装计划
┌──────────────────────────────────────────────────────┐
│ 补丁一 · 源甲                                        │
│ 文件来源：本地 ZIP / 本次下载                         │
│ 将修改 N 个文件 · 覆盖文件会先备份                    │
│ 计划剩余有效时间                                     │
│ [查看文件变更（N）]                                  │
│ [继续确认安装]                     [取消本次准备]    │
└──────────────────────────────────────────────────────┘
```

- 文件变更默认折叠，展开后在右侧展示操作类型和路径，避免大量文件淹没主要操作。
- “继续确认安装”打开原生确认对话框，列明游戏、补丁及变更数量，并要求用户确认已关闭游戏及暂停更新。
- 对话框操作为“取消”和“已关闭游戏及更新，安装”。完成这一明确确认后才写入游戏文件。
- 计划过期时禁用确认安装，提供重新准备；有阻碍时列出原因，不出现可执行的安装确认。
- 确认安装后进入独立全屏安装进度页；只有安装事务提交成功才显示完成。完成后更新概览、补丁状态和操作记录，用户点击“返回补丁管理”离开结果页。

### 5.3 已安装及异常状态

- 本工具安装的补丁：显示“已安装”和“卸载补丁”。卸载通过原生确认对话框说明将恢复备份文件。
- 外部安装的补丁：显示“通过其他方式安装”，说明没有本工具备份，不能提供自动卸载。
- 未完成事务：概览与补丁管理显示简短异常提示及“查看操作记录”入口；具体修复操作集中在操作记录中。
- 正常状态不显示“修复未完成的操作”按钮。

### 5.4 下载与安装：原生进度面板与全屏黑色遮罩

本文所称“全屏进度页”统一指覆盖当前管理页的原生模态进度面板：全屏黑色半透明 mask，中央显示任务内容与原生进度条，不新增独立路由页面。原管理页留在遮罩下面，不能操作，其导航和滚动位置保留。面板始终显示当前游戏、补丁名称、阶段及关闭后会取消的说明。

- 视觉目标：沿用 Steam 原生模态层的黑色遮罩、字体、间距、焦点和手柄提示；中央内容区无需铺满屏幕，不另加管理侧栏或自制页面背景。
- 下载、校验、安装、取消和恢复在同一面板内更新阶段，避免反复关闭和打开导致焦点闪跳。
- 下载准备成功后关闭面板，底层补丁管理显示安装计划；确认安装后再次打开进度面板。
- B、取消按钮和其他实际关闭入口统一请求取消；点击遮罩空白处不关闭，避免误触。取消和恢复结束后才正常关闭面板。
- 已核对当前仓库的 `@decky/ui`：导出了 `showModal`、`ModalRoot`、`ProgressBar` 和 `ProgressBarWithInfo`，可作为复用原生模态层与进度条的基础。尚未确认有单个现成组件同时提供黑色全屏遮罩、速度、文件大小与任务取消；这些数据和行为仍需插件接入。
- 黑色遮罩的具体透明度和面板尺寸以实机原生效果核验，不把源码导出存在当作实机视觉验收通过。

复用依据：[Decky 原生模态组件源码](https://github.com/SteamDeckHomebrew/decky-frontend-lib/blob/main/src/components/Modal.ts)、[进度组件源码](https://github.com/SteamDeckHomebrew/decky-frontend-lib/blob/main/src/components/ProgressBar.ts)。

#### 下载布局

以下框线表示黑色全屏遮罩中央的面板内容范围，不表示新的全屏路由；数值仅为布局示例，实际显示由任务实时上报。

```text
                       Steam 顶部状态栏
┌──────────────────────────────────────────────────────┐
│ 下载补丁                                             │
│ 游戏 A · 补丁一                                      │
│ 匹配源：源甲                                         │
│                                                      │
│ patch.zip                                            │
│ [████████████░░░░░░░░░░░░░░░░]                  40%  │
│ 已下载 400 MiB / 总大小 1,000 MiB                     │
│ 下载速度 12.5 MiB/s            预计剩余 48 秒          │
│ 已用时间 32 秒                                       │
│                                                      │
│ 退出此界面将中断任务，不会在后台继续下载。             │
│ [取消下载并返回]                                     │
└──────────────────────────────────────────────────────┘
                         B 取消并返回
```

- 显示真实接收字节数、文件总大小、当前下载速度、进度条、百分比及耗时。统一使用 KiB、MiB、GiB 等单位。
- 速度根据近期实际接收量平滑计算，停滞时显示 0 B/s；连接中显示“正在连接”，不能沿用之前的速度。
- 仅在总大小已知且速度可用时估算剩余时间；数值尚不稳定时显示“估算中”。
- 服务器未提供总大小时，显示“总大小未知”、已下载量和速度，进度条使用不定进度样式，不伪造百分比。
- 下载到 100% 仅代表文件接收完成，随后切换为“正在校验”，不会直接显示安装完成。
- 复用本地 ZIP 时跳过下载，直接进入全屏校验阶段，展示文件大小；不显示虚假的下载速度。
- 校验阶段有真实已处理量时显示对应进度；暂时无法计量的连接、扫描或收尾阶段使用不定进度条并明确阶段名称。

#### 安装布局

```text
                       Steam 顶部状态栏
┌──────────────────────────────────────────────────────┐
│ 安装补丁                                             │
│ 游戏 A · 补丁一                                      │
│                                                      │
│ 当前阶段：写入文件（备份已完成）                      │
│ [███████████████░░░░░░░░░░░░░░]      当前阶段 50%     │
│ 已处理 600 MiB / 本阶段总量 1.17 GiB                  │
│ 文件 18 / 36 · 当前文件：data/example.pak             │
│ 安装包大小 1,000 MiB · 已用时间 25 秒                 │
│                                                      │
│ 退出将中断安装，并恢复本次已修改的文件。               │
│ [取消安装并返回]                                     │
└──────────────────────────────────────────────────────┘
                         B 取消并返回
```

- 按校验、备份、写入、提交等实际阶段展示进度，明确标注“当前阶段”，避免阶段重置被误解为总体进度倒退。
- 展示安装包大小、当前阶段已处理 / 总字节数、文件数与当前文件。压缩包大小与解压后写入量分别标注，不能混作同一总量。
- 大文件的复制和解压应提供字节级进度，不能只在整个文件处理完成后跳动。
- 安装阶段不把磁盘写入速度标成下载速度；如提供吞吐量，标注为“处理速度”。
- 尚未取得当前阶段总量时显示不定进度条；只有后端确认成功提交，才能展示“安装完成”。

#### 退出与中断规则

- 点击取消按钮、按 B 返回、导航离开进度页或关闭该界面，都视为取消当前下载 / 准备 / 安装任务；没有“后台继续”选项。取消无需再弹一次确认，页面和按钮提前明确后果。
- 仅打开 Steam 系统覆盖菜单而未离开进度页不算退出；实际路由离开、关闭插件界面或前端断开后，不允许任务无限期在后台运行。
- 下载取消：停止网络请求和后续校验、安装准备，清理本次未完成的临时下载文件；已有完整缓存及用户原有 ZIP 不删除。
- 校验或准备取消：停止读取和生成计划，作废本次尚未执行的计划，不修改游戏文件。
- 安装取消：立即请求停止新增写入，在安全边界停止当前步骤，然后根据事务日志恢复本次已修改文件。不能直接强杀进程后把半安装状态当作已取消。
- 正常返回操作先显示“正在取消”或“正在恢复原文件”，安全清理完成后自动返回补丁管理。清理期间不接受重复取消或新的安装。
- 如果用户已通过系统导航离开，下载和安装工作仍应停止；仅允许完成必要的清理和恢复，不继续安装。下次进入时显示实际取消或恢复结果。
- 前端崩溃、断连等情况下也应有后端取消保障，不能只依赖页面卸载回调；无法即时感知的断连按可检测的超时处理。重新连接后不得自动续装。
- 恢复失败时显示“已中断，仍需恢复”，记录错误并提供恢复入口；不能显示“已安全取消”。
- 若退出与最终提交恰好同时发生，以事务实际结果为准：已提交则明确提示“安装已完成，未取消”，可按正常流程卸载；不可把已提交结果误报为取消成功。
- 成功或失败结果页没有运行中的任务，离开该页不会再次触发取消或卸载。

#### 实施所需能力

以上是目标交互，尚未实现。施工时需同时核实并补齐下载、校验和安装的进度上报及取消能力；仅添加前端进度动画不满足验收。任务状态必须能区分执行中、取消中、恢复中、已取消、成功和失败，并在前端重连后恢复实际状态。

## 6. 操作记录

- 仅展示当前游戏的记录，按时间倒序显示安装、卸载、恢复结果及错误原因。
- 未完成事务置顶，提供“已关闭游戏并暂停更新，修复未完成的操作”。
- 若恢复接口会处理其他游戏的事务，必须在确认前列出受影响游戏和操作范围，不能让用户误以为只影响当前游戏。
